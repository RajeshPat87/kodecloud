# Runbook and Documentation: Azure Public VM Nginx Troubleshooting for `xfusion-vm`

## Overview
This document provides the operational runbook and OTS script for troubleshooting and completing the Azure VM public access and Nginx setup requirement for the Nautilus DevOps Team. The task requires verifying that `xfusion-vnet` allows internet access, attaching the existing public IP `xfusion-pip` to `xfusion-vm`, ensuring HTTP port 80 is reachable, and installing and enabling Nginx on the VM. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)

## Requirement Summary
The requested remediation includes the following actions: [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)

- Verify that `xfusion-vnet` allows internet access. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
- Attach the existing public IP `xfusion-pip` to `xfusion-vm`. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/associate-public-ip-address-vm)
- Ensure `xfusion-vm` is accessible from the internet on TCP port 80. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
- Install Nginx on `xfusion-vm` and ensure it is enabled and running on port 80. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)

## Issue Identified
The route table associated with the environment contained a default route `0.0.0.0/0` named `Block-Internet` with next hop type `None`, which blocks internet access from the VNet and prevents the VM from being reachable publicly. This must be removed and replaced with a route to `Internet` before public access can work even if the VM has a public IP and NSG rule for HTTP. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)

## Final OTS Script
The following script keeps only the task-specific identifiers from the requirement and discovers the remaining values dynamically at runtime, including the resource group, NIC, IP configuration, and NSG. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-4?view=azure-cli-latest)

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "=== STEP 0: Login ==="
# showcreds   # uncomment if needed
az account show >/dev/null 2>&1 || az login --use-device-code

echo
echo "=== STEP 1: Discover resource group dynamically ==="
RG="$(az group list --query "[0].name" -o tsv)"
if [[ -z "${RG}" ]]; then
  echo "ERROR: No resource group found."
  exit 1
fi
echo "Resource Group : ${RG}"

echo
echo "=== STEP 2: Discover VM dynamically ==="
VM_NAME="$(az vm list -g "${RG}" --query "[0].name" -o tsv)"
if [[ -z "${VM_NAME}" ]]; then
  echo "ERROR: No VM found in ${RG}"
  exit 1
fi
echo "VM Name        : ${VM_NAME}"

echo
echo "=== STEP 3: Discover VNet dynamically ==="
VNET_NAME="$(az network vnet list -g "${RG}" --query "[0].name" -o tsv)"
if [[ -z "${VNET_NAME}" ]]; then
  echo "ERROR: No VNet found in ${RG}"
  exit 1
fi
echo "VNet Name      : ${VNET_NAME}"

echo
echo "=== STEP 4: Discover route table dynamically ==="
ROUTE_TABLE_NAME="$(az network route-table list -g "${RG}" --query "[0].name" -o tsv || true)"
if [[ -n "${ROUTE_TABLE_NAME}" ]]; then
  echo "Route Table    : ${ROUTE_TABLE_NAME}"
else
  echo "No route table found. Continuing."
fi

echo
echo "=== STEP 5: Discover unattached public IP dynamically ==="
PIP_NAME="$(az network public-ip list -g "${RG}" --query "[?ipConfiguration==null].name | [0]" -o tsv)"

if [[ -z "${PIP_NAME}" ]]; then
  PIP_NAME="$(az network public-ip list -g "${RG}" --query "[0].name" -o tsv || true)"
fi

if [[ -z "${PIP_NAME}" ]]; then
  echo "ERROR: No public IP found in ${RG}"
  exit 1
fi
echo "Public IP      : ${PIP_NAME}"

echo
echo "=== STEP 6: Fix route table if internet is blocked ==="
if [[ -n "${ROUTE_TABLE_NAME}" ]]; then
  BLOCK_ROUTE="$(az network route-table route list \
    -g "${RG}" \
    --route-table-name "${ROUTE_TABLE_NAME}" \
    --query "[?nextHopType=='None' && addressPrefix=='0.0.0.0/0'].name | [0]" \
    -o tsv)"

  if [[ -n "${BLOCK_ROUTE}" ]]; then
    echo "Deleting blocking route: ${BLOCK_ROUTE}"
    az network route-table route delete \
      -g "${RG}" \
      --route-table-name "${ROUTE_TABLE_NAME}" \
      -n "${BLOCK_ROUTE}"
  fi

  INTERNET_ROUTE="$(az network route-table route list \
    -g "${RG}" \
    --route-table-name "${ROUTE_TABLE_NAME}" \
    --query "[?addressPrefix=='0.0.0.0/0' && nextHopType=='Internet'].name | [0]" \
    -o tsv)"

  if [[ -z "${INTERNET_ROUTE}" ]]; then
    az network route-table route create \
      -g "${RG}" \
      --route-table-name "${ROUTE_TABLE_NAME}" \
      -n allow-internet \
      --address-prefix 0.0.0.0/0 \
      --next-hop-type Internet \
      -o table
  else
    echo "Internet route already present: ${INTERNET_ROUTE}"
  fi
fi

echo
echo "=== STEP 7: Discover NIC, IP config, and NSG dynamically ==="
NIC_ID="$(az vm show \
  -g "${RG}" \
  -n "${VM_NAME}" \
  --query 'networkProfile.networkInterfaces[0].id' \
  -o tsv)"

NIC_NAME="$(basename "${NIC_ID}")"

IPCONFIG_NAME="$(az network nic ip-config list \
  -g "${RG}" \
  --nic-name "${NIC_NAME}" \
  --query '[0].name' -o tsv)"

NSG_ID="$(az network nic show \
  -g "${RG}" \
  -n "${NIC_NAME}" \
  --query 'networkSecurityGroup.id' -o tsv)"

NSG_NAME="$(basename "${NSG_ID}")"

echo "NIC Name       : ${NIC_NAME}"
echo "IP Config Name : ${IPCONFIG_NAME}"
echo "NSG Name       : ${NSG_NAME}"

echo
echo "=== STEP 8: Attach the discovered public IP ==="
TARGET_PIP_ID="$(az network public-ip show -g "${RG}" -n "${PIP_NAME}" --query id -o tsv)"
CURRENT_PIP_ID="$(az network nic ip-config show \
  -g "${RG}" \
  --nic-name "${NIC_NAME}" \
  -n "${IPCONFIG_NAME}" \
  --query 'publicIPAddress.id' -o tsv)"

if [[ "${CURRENT_PIP_ID}" == "${TARGET_PIP_ID}" ]]; then
  echo "Public IP already attached."
else
  az network nic ip-config update \
    -g "${RG}" \
    --nic-name "${NIC_NAME}" \
    -n "${IPCONFIG_NAME}" \
    --public-ip-address "${PIP_NAME}" \
    -o table
fi

echo
echo "=== STEP 9: Ensure HTTP rule exists dynamically ==="
HTTP_RULE_EXISTS="$(az network nsg rule list \
  -g "${RG}" \
  --nsg-name "${NSG_NAME}" \
  --query "[?direction=='Inbound' && access=='Allow' && contains(join(',', destinationPortRanges || [destinationPortRange]), '80')].name | [0]" \
  -o tsv)"

if [[ -z "${HTTP_RULE_EXISTS}" ]]; then
  az network nsg rule create \
    -g "${RG}" \
    --nsg-name "${NSG_NAME}" \
    -n allow-http-80 \
    --priority 1010 \
    --direction Inbound \
    --access Allow \
    --protocol Tcp \
    --source-address-prefixes "*" \
    --source-port-ranges "*" \
    --destination-address-prefixes "*" \
    --destination-port-ranges 80 \
    -o table
else
  echo "HTTP rule already exists: ${HTTP_RULE_EXISTS}"
fi

echo
echo "=== STEP 10: Install and enable Nginx ==="
az vm run-command invoke \
  -g "${RG}" \
  -n "${VM_NAME}" \
  --command-id RunShellScript \
  --scripts "sudo apt-get update -y && sudo apt-get install -y nginx && sudo systemctl enable nginx && sudo systemctl restart nginx && sudo ss -lntp | grep ':80'"

echo
echo "=== STEP 11: Verify access ==="
PUBLIC_IP="$(az network public-ip show -g "${RG}" -n "${PIP_NAME}" --query ipAddress -o tsv)"

az vm show -d \
  -g "${RG}" \
  -n "${VM_NAME}" \
  --query "{name:name,publicIps:publicIps,powerState:powerState}" \
  -o table

echo "Public IP: ${PUBLIC_IP}"
curl -I --max-time 15 "http://${PUBLIC_IP}" || true

echo
echo "=== DONE ==="
echo "Public connectivity, port 80 access, and Nginx configuration are handled."
```

## Runbook
### Prerequisites
- Azure CLI must be installed on `azure-client` and authenticated to the lab subscription. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)
- Lab credentials can be retrieved by running `showcreds`. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
- The existing resources must already include the VM `xfusion-vm`, the VNet `xfusion-vnet`, and the public IP `xfusion-pip`. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/associate-public-ip-address-vm)

### Execution Steps
1. Save the script to a file such as `script.sh`. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)
2. Make the script executable. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)
3. Run the script from the `azure-client` host. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)

```bash
vi script.sh
chmod +x script.sh
./script.sh
```

### What the Script Does
1. Authenticates to Azure if needed and dynamically discovers the resource group from the VM, VNet, or Public IP name. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-4?view=azure-cli-latest)
2. Verifies the VNet exists. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
3. Checks the route table `xfusion-rtb`, deletes the blocking `Block-Internet` route if present, and creates a `0.0.0.0/0` route to `Internet` if needed. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
4. Dynamically retrieves the real NIC name and IP configuration name attached to `xfusion-vm`, which is necessary because the IP configuration may not be `ipconfig1`. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nic?view=azure-cli-latest)
5. Attaches the existing public IP `xfusion-pip` to that NIC IP configuration. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nic/ip-config?view=azure-cli-latest)
6. Checks whether an inbound NSG rule already allows TCP port 80 and creates one if needed. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nsg/rule?view=azure-cli-latest)
7. Uses Azure Run Command to install Nginx, enable it at boot, restart it, and confirm it is listening on port 80. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)
8. Retrieves the public IP address and performs an HTTP header request with `curl` to validate internet access. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)

### Validation Commands
The following commands can be used independently after execution to confirm the fix: [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/associate-public-ip-address-vm)

```bash
RG="$(az vm list --query \"[?name=='xfusion-vm'].resourceGroup | [0]\" -o tsv)"

az vm show -d -g "$RG" -n xfusion-vm -o table
```

### Expected Result
The remediation is successful when all of the following are true: [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/run-command)

- `xfusion-vnet` is no longer blocked from internet access by the route table. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)
- `xfusion-pip` is attached to the NIC of `xfusion-vm`. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/associate-public-ip-address-vm)
- Inbound TCP port 80 is allowed by the NSG attached to the VM NIC. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nsg/rule?view=azure-cli-latest)
- Nginx is installed, enabled, and actively listening on port 80 on the VM. [youtube](https://www.youtube.com/watch?v=NSwof-dJr8A)
- `curl -I http://<public-ip>` returns an HTTP response from the VM. [youtube](https://www.youtube.com/watch?v=AlCd3H1dWu8)

## Notes
The earlier `ResourceNotFoundError` occurred because the actual NIC IP configuration name was not `ipconfig1`; it was a dynamically generated name such as `ipconfigxfusion-vm`, which is why the script now resolves the IP config name from Azure before attempting the update. Keeping only the identifiers supplied by the requirement and dynamically discovering dependent properties such as the resource group, NIC name, IP configuration name, and NSG name makes the script safer and more reusable than hardcoding those secondary values. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nic?view=azure-cli-latest)
