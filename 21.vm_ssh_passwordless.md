## Runbook: Create `datacenter-vm` via Azure CLI with Standard_LRS 30 GB Disk

### Purpose

Provision a Linux VM on Azure from the `azure-client` host using Azure CLI, reusing the existing lab resource group, enforcing a standard VM/disk profile, and configuring password-less SSH from `azure-client`. [youtube](https://www.youtube.com/watch?v=O_WcIkUIJJM)

### Standard profile (no deviation)

- Resource group: **existing lab RG**, auto-discovered (here: `kml_rg_main-c477b51992644970`).[user query]
- VM name: `datacenter-vm`.[user query]
- Region: `westus` (VM location; RG metadata remains `eastus`).[user query]
- Size: `Standard_B1s`.[user query]
- OS image: `Ubuntu2204`.[user query] [youtube](https://www.youtube.com/watch?v=O_WcIkUIJJM)
- Admin username: `azureuser`.[user query]
- Disk:
  - Type: `Standard_LRS` (non-Premium).[user query] [stackoverflow](https://stackoverflow.com/questions/53584539/how-to-specify-azure-linux-os-disk-type-with-azure-cli-create-vm)
  - OS disk size: `30 GB`.[user query] [youtube](https://www.youtube.com/watch?v=O_WcIkUIJJM)
- Authentication: SSH key from `/root/.ssh/id_rsa` on `azure-client`.[user query] [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/ssh-keys-azure-cli)

### Step 1 – Prepare the script

On `azure-client`:

```bash
rm -f script.sh
vi script.sh    # paste the script below, save with :wq
chmod 755 script.sh
```

Use this script content:

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "=== STEP 0: Azure login / lab credentials ==="
# In labs, run showcreds first if required.
# showcreds
az account show >/dev/null 2>&1 || az login --use-device-code

echo "=== STEP 1: Discover subscription and existing resource group ==="
SUBSCRIPTION_ID="$(az account show --query id -o tsv)"
SUBSCRIPTION_NAME="$(az account show --query name -o tsv)"
echo "Using subscription: ${SUBSCRIPTION_NAME} (${SUBSCRIPTION_ID})"

echo "Available resource groups:"
az group list --query "[].{name:name,location:location}" -o table

RESOURCE_GROUP="$(az group list --query '[0].name' -o tsv)"
if [[ -z "${RESOURCE_GROUP}" ]]; then
  echo "ERROR: No existing resource group found."
  exit 1
fi

RG_LOCATION="$(az group show --name "${RESOURCE_GROUP}" --query location -o tsv)"
echo "Using existing RG only: ${RESOURCE_GROUP} (RG metadata location: ${RG_LOCATION})"

echo
echo "=== STEP 2: Ensure SSH key exists on azure-client ==="
SSH_DIR="${HOME}/.ssh"
SSH_PRIV_KEY="${SSH_DIR}/id_rsa"
SSH_PUB_KEY="${SSH_PRIV_KEY}.pub"

mkdir -p "${SSH_DIR}"
chmod 700 "${SSH_DIR}"

if [[ -f "${SSH_PRIV_KEY}" && -f "${SSH_PUB_KEY}" ]]; then
  echo "Existing SSH keypair found: ${SSH_PRIV_KEY}"
else
  echo "Generating SSH keypair..."
  ssh-keygen -t rsa -b 4096 -f "${SSH_PRIV_KEY}" -N ""
fi

echo
echo "=== STEP 3: Standard VM / disk policy ==="
VM_NAME="datacenter-vm"
VM_LOCATION="westus"
VM_SIZE="Standard_B1s"
ADMIN_USER="azureuser"
IMAGE="Ubuntu2204"
STORAGE_SKU="Standard_LRS"
OS_DISK_SIZE_GB="30"

echo "VM Name       : ${VM_NAME}"
echo "VM Location   : ${VM_LOCATION}"
echo "VM Size       : ${VM_SIZE}"
echo "Admin User    : ${ADMIN_USER}"
echo "Image         : ${IMAGE}"
echo "Storage SKU   : ${STORAGE_SKU}"
echo "OS Disk Size  : ${OS_DISK_SIZE_GB} GB"

echo
echo "=== STEP 4: Create VM using existing RG only ==="
az vm create \
  --resource-group "${RESOURCE_GROUP}" \
  --name "${VM_NAME}" \
  --location "${VM_LOCATION}" \
  --image "${IMAGE}" \
  --size "${VM_SIZE}" \
  --admin-username "${ADMIN_USER}" \
  --ssh-key-values "@${SSH_PUB_KEY}" \
  --public-ip-sku Standard \
  --storage-sku "${STORAGE_SKU}" \
  --os-disk-size-gb "${OS_DISK_SIZE_GB}" \
  -o table

echo
echo "=== STEP 5: Fetch public IP ==="
VM_PUBLIC_IP="$(az vm show -d \
  --resource-group "${RESOURCE_GROUP}" \
  --name "${VM_NAME}" \
  --query publicIps -o tsv)"

if [[ -z "${VM_PUBLIC_IP}" ]]; then
  echo "ERROR: Failed to get public IP for ${VM_NAME}"
  exit 1
fi

echo "VM Public IP: ${VM_PUBLIC_IP}"

echo
echo "=== STEP 6: Verify password-less SSH ==="
ssh -o StrictHostKeyChecking=accept-new \
    -o ConnectTimeout=20 \
    "${ADMIN_USER}@${VM_PUBLIC_IP}" \
    'echo "SSH login successful on $(hostname)"; exit'

echo
echo "=== SUCCESS ==="
echo "VM created with lab standard policy:"
echo "  Existing RG only"
echo "  VM size      : ${VM_SIZE}"
echo "  Disk type    : ${STORAGE_SKU}"
echo "  OS disk size : ${OS_DISK_SIZE_GB} GB"
echo "Connect with:"
echo "  ssh ${ADMIN_USER}@${VM_PUBLIC_IP}"

set +u
exit 0
```

This pattern directly matches Microsoft’s CLI usage for SSH-key-based VM creation and public IP retrieval, extended with explicit `--storage-sku` and `--os-disk-size-gb` to satisfy lab policies. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

## Operational notes

- **Reusability**: This runbook is designed so you can reuse it across labs by only changing `VM_NAME` or `VM_LOCATION` if needed, while keeping the VM/disk policy fixed (Standard_B1s, Standard_LRS, 30 GB). [kodekloud](https://kodekloud.com/community/t/unable-to-create-azure-vm-using-cli-in-kodekloud-lab-100-days-of-cloud-azure-day3-task/490679)
- **Safety**: It never creates or deletes resource groups; it always uses the existing lab RG, which is important in restricted lab subscriptions.[user query] [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/group?view=azure-cli-latest)
- **Compliance**: By setting `--storage-sku Standard_LRS` and `--os-disk-size-gb 30`, you comply with lab policies that forbid Premium disks and large OS disks. [stackoverflow](https://stackoverflow.com/questions/53584539/how-to-specify-azure-linux-os-disk-type-with-azure-cli-create-vm)
