# Runbook — Kubernetes Workloads: Pod, Deployment, ReplicaSet, Job, CronJob

**Cluster access:** `kubectl` on jump host, pre-configured
**Namespace:** `default` unless stated

---

## 1. Core concept — Kubernetes workload hierarchy

```
CronJob        → creates Jobs on a schedule
Job            → creates Pods that run to completion
Deployment     → manages ReplicaSets (rolling updates, rollbacks)
ReplicaSet     → ensures N pod replicas are always running
Pod            → the smallest deployable unit (one or more containers)
```

**Declarative over imperative** — always use `kubectl apply -f -` with a manifest.
Never use `kubectl set image`, `kubectl run` (for production), or other imperative
commands. The manifest is the source of truth; Git is where it lives.

**Key kubectl commands:**

| Action | Command |
|---|---|
| Apply manifest | `kubectl apply -f <file>` or `cat <<EOF \| kubectl apply -f -` |
| Get resources | `kubectl get <resource>` |
| Describe resource | `kubectl describe <resource> <name>` |
| Get logs | `kubectl logs <pod-name>` |
| Execute in pod | `kubectl exec -it <pod> -- bash` |
| Delete resource | `kubectl delete <resource> <name>` |
| Watch rollout | `kubectl rollout status deployment/<name>` |
| Rollback | `kubectl rollout undo deployment/<name>` |

> `kubectl get logs` is NOT valid — logs is a top-level command, not a resource type.
> `kubectl logs <pod>` is correct.

## 2. Pod

### 2.1 Simple pod

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: pod-nginx
  labels:
    app: nginx_app
spec:
  containers:
    - name: nginx-container
      image: nginx:latest
EOF
```

### 2.2 Pod with resource requests and limits

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: httpd-pod
spec:
  containers:
    - name: httpd-container
      image: httpd:latest
      resources:
        requests:
          memory: "15Mi"
          cpu: "100m"
        limits:
          memory: "20Mi"
          cpu: "100m"
EOF
```

### 2.3 Pod in a namespace

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Namespace
metadata:
  name: dev
---
apiVersion: v1
kind: Pod
metadata:
  name: dev-nginx-pod
  namespace: dev
spec:
  containers:
    - name: dev-nginx-pod
      image: nginx:latest
EOF
```

### 2.4 Verify pod

```bash
kubectl get pod <name>
kubectl get pod <name> -n <namespace>       # if in a non-default namespace
kubectl describe pod <name> | grep -E "Name:|Image:|Labels:|Namespace:|Requests:|Limits:"
kubectl logs <pod-name>                      # view container logs
```

## 3. Deployment

### 3.1 Create deployment

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  template:
    metadata:
      labels:
        app: nginx-app
    spec:
      containers:
        - name: nginx
          image: nginx:latest
EOF
```

### 3.2 Rolling update (update image)

**Always check the existing selector first — it is immutable:**
```bash
kubectl get deployment <name> -o jsonpath='{.spec.selector.matchLabels}'
```

Then apply with the exact same selector, only changing the image:
```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx-app        # MUST match existing immutable selector
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 1
  template:
    metadata:
      labels:
        app: nginx-app
    spec:
      containers:
        - name: nginx
          image: nginx:1.19  # the only change
EOF

kubectl rollout status deployment/nginx-deployment
```

### 3.3 Rollback

```bash
kubectl rollout history deployment/nginx-deployment    # view revisions
kubectl rollout undo deployment/nginx-deployment       # rollback to previous
kubectl rollout status deployment/nginx-deployment     # confirm
kubectl describe deployment nginx-deployment | grep Image   # verify image
```

### 3.4 Verify deployment

```bash
kubectl get deployment <name>
kubectl get pods -l app=<selector-label>
kubectl describe deployment <name> | grep -E "Image:|Replicas:|Labels:"
kubectl get replicaset    # shows current + old replicasets
```

## 4. ReplicaSet

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: httpd-replicaset
  labels:
    app: httpd_app
    type: front-end
spec:
  replicas: 4
  selector:
    matchLabels:
      app: httpd_app
      type: front-end
  template:
    metadata:
      labels:
        app: httpd_app
        type: front-end
    spec:
      containers:
        - name: httpd-container
          image: httpd:latest
EOF
```

> Labels must appear in three places: `metadata.labels` (the RS itself),
> `selector.matchLabels` (how RS finds its pods), and `template.metadata.labels`
> (what gets stamped on each pod). All three must be consistent.

### Verify

```bash
kubectl get replicaset httpd-replicaset
kubectl get pods -l app=httpd_app
kubectl describe replicaset httpd-replicaset | grep -E "Replicas:|Image:|Labels:"
```

## 5. Job

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: countdown-datacenter
spec:
  template:
    metadata:
      name: countdown-datacenter
    spec:
      containers:
        - name: container-countdown-datacenter
          image: ubuntu:latest
          command:
            - sleep
            - "5"
      restartPolicy: Never
EOF
```

> `restartPolicy` for Jobs must be `Never` or `OnFailure` — never `Always`.
> Quote numeric command args (`"5"`) to keep them as strings.

### Verify

```bash
kubectl get job countdown-datacenter           # COMPLETIONS: 1/1 = done
kubectl get pods -l job-name=countdown-datacenter
kubectl logs <pod-name>                        # empty for sleep; shows output for echo
```

## 6. CronJob

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: batch/v1
kind: CronJob
metadata:
  name: nautilus
spec:
  schedule: "*/6 * * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: cron-nautilus
              image: httpd:latest
              command:
                - /bin/sh
                - -c
                - echo Welcome to xfusioncorp!
          restartPolicy: OnFailure
EOF
```

### Trigger manually (don't wait for schedule)

```bash
kubectl create job nautilus-manual --from=cronjob/nautilus
kubectl get jobs
kubectl get pods
kubectl logs <pod-name>    # Welcome to xfusioncorp!
```

### Verify

```bash
kubectl get cronjob nautilus
kubectl describe cronjob nautilus | grep -E "Schedule:|Image:|restartPolicy:"
```

## 7. Common selector / label gotchas

| Gotcha | Detail | Fix |
|---|---|---|
| `spec.selector: field is immutable` | you changed the selector on an existing deployment | check existing selector with `-o jsonpath`, match it exactly |
| Labels in only one place | ReplicaSet/Deployment needs labels in metadata, selector, AND template | add to all three |
| Wrong namespace | resource created in default, queried without `-n` | always add `-n <namespace>` for non-default |
| `kubectl get logs` | logs is not a resource type | use `kubectl logs <pod>` |

## 8. Troubleshooting quick reference

```bash
# pod not starting
kubectl describe pod <name>     # check Events section at the bottom

# image pull error
kubectl describe pod <name> | grep -A5 "Events:"

# check all resources across namespaces
kubectl get all -A

# check logs of a completed/crashed pod
kubectl logs <pod-name> --previous

# get the pod name from a job
kubectl get pods -l job-name=<job-name>

# get the pod name from a cronjob run
kubectl get pods -l job-name=<cronjob-name>-<hash>

# force delete a stuck pod
kubectl delete pod <name> --grace-period=0 --force
```

## 9. Manifest field reference

| Field | Where it lives | Notes |
|---|---|---|
| `restartPolicy` | `spec.template.spec` (pod level) | `Always` (Deployment), `Never`/`OnFailure` (Job/CronJob) |
| `resources.requests/limits` | `spec.containers[].resources` | container level, not pod level |
| `selector.matchLabels` | `spec.selector` | immutable on Deployment/RS after creation |
| `schedule` | `spec.schedule` (CronJob) | standard cron syntax |
| `replicas` | `spec.replicas` | Deployment and ReplicaSet |
| `image` | `spec.containers[].image` | always specify the tag explicitly |
| `namespace` | `metadata.namespace` | omit = default namespace |
