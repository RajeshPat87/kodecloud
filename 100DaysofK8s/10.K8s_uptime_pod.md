Three objects: namespace, configmap, and pod (with volume + env from configmap). All in the `datacenter` namespace.

## Create and apply

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Namespace
metadata:
  name: datacenter
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: time-config
  namespace: datacenter
data:
  TIME_FREQ: "10"
---
apiVersion: v1
kind: Pod
metadata:
  name: time-check
  namespace: datacenter
spec:
  containers:
    - name: time-check
      image: busybox:latest
      command:
        - /bin/sh
        - -c
        - "while true; do date; sleep $TIME_FREQ; done >> /opt/dba/time/time-check.log"
      env:
        - name: TIME_FREQ
          valueFrom:
            configMapKeyRef:
              name: time-config
              key: TIME_FREQ
      volumeMounts:
        - name: log-volume
          mountPath: /opt/dba/time
  volumes:
    - name: log-volume
      emptyDir: {}
EOF
```

## Verify

```bash
# all three objects created in datacenter namespace
kubectl get namespace datacenter
kubectl get configmap time-config -n datacenter
kubectl get pod time-check -n datacenter

# confirm env var from configmap
kubectl describe pod time-check -n datacenter | grep -A3 "Environment:"

# confirm volume mount
kubectl describe pod time-check -n datacenter | grep -A3 "Mounts:"

# confirm log is being written (wait a few seconds)
kubectl exec -n datacenter time-check -- cat /opt/dba/time/time-check.log
```

Expected log output (grows every 10 seconds):
```
Wed Aug 12 10:00:00 UTC 2026
Wed Aug 12 10:00:10 UTC 2026
Wed Aug 12 10:00:20 UTC 2026
```

## Why each piece

**ConfigMap `time-config`** — stores `TIME_FREQ=10` as a key-value; the pod reads it via `configMapKeyRef` so the value isn't hardcoded in the pod spec.

**`env.valueFrom.configMapKeyRef`** — injects `TIME_FREQ=10` as an environment variable into the container. The command `sleep $TIME_FREQ` uses it.

**Command** — `/bin/sh -c "while true; do date; sleep $TIME_FREQ; done >> /opt/dba/time/time-check.log"` writes the loop output to the log file. The `>>` redirects stdout to the file.

**`log-volume` with `emptyDir`** — creates an ephemeral volume that lives as long as the pod, mounted at `/opt/dba/time`. `emptyDir` is the right choice for a pod-local log scratch space.

## Requirement trace

| Requirement | Evidence |
|---|---|
| Pod `time-check` in `datacenter` namespace | `metadata.name/namespace` |
| Container `time-check` with `busybox:latest` | `name: time-check`, `image: busybox:latest` |
| ConfigMap `time-config` with `TIME_FREQ=10` | `data.TIME_FREQ: "10"` in same namespace |
| Command writes to `/opt/dba/time/time-check.log` | `>> /opt/dba/time/time-check.log` in command |
| Env `TIME_FREQ` from configmap key | `configMapKeyRef name: time-config key: TIME_FREQ` |
| Volume `log-volume` mounted at `/opt/dba/time` | `volumeMounts.mountPath: /opt/dba/time` |
