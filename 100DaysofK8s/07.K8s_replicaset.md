Clean cluster — just the kubernetes service. Apply the ReplicaSet directly.

## Create and apply

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: httpd-replicaset
  labels:
    app: httpd_app
    type: front-end
spec:
  replicas: 4
  selector:
    matchLabels:
      app: httpd_app
      type: front-end
  template:
    metadata:
      labels:
        app: httpd_app
        type: front-end
    spec:
      containers:
        - name: httpd-container
          image: httpd:latest
EOF
```

## Verify

```bash
kubectl get replicaset httpd-replicaset
kubectl get pods -l app=httpd_app
kubectl describe replicaset httpd-replicaset | grep -E "Name:|Image:|Replicas:|Labels:"
```

Expected:
```
NAME               DESIRED   CURRENT   READY   AGE
httpd-replicaset   4         4         4       ...

NAME                             READY   STATUS    RESTARTS   AGE
```

## Requirement trace

| Requirement | Evidence |
|---|---|
| ReplicaSet name `httpd-replicaset` | `metadata.name: httpd-replicaset` |
| Image `httpd:latest` | `image: httpd:latest` |
| Label `app: httpd_app` | in `metadata.labels`, `selector`, and `template.labels` |
| Label `type: front-end` | in `metadata.labels`, `selector`, and `template.labels` |
| Container name `httpd-container` | `name: httpd-container` |
| Replicas `4` | `replicas: 4` |

Both labels are in three places — `metadata.labels` (the RS itself), `selector.matchLabels` (how RS finds its pods), and `template.metadata.labels` (what gets stamped on each pod). All three must be consistent or Kubernetes rejects the manifest.
