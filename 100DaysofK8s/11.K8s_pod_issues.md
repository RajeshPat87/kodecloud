The error is clear from the events: **`httpd:latests`** — a typo in the image tag (`latests` instead of `latest`). The sidecar pulled fine; only the httpd container has the wrong tag.

## Fix — patch the image tag

```bash
# confirm the typo first
kubectl get pod webserver -o jsonpath='{.spec.containers[*].image}'

# get the full current manifest
kubectl get pod webserver -o yaml > webserver.yaml

# fix the typo
sed -i 's|httpd:latests|httpd:latest|g' webserver.yaml

# verify the fix
grep "image:" webserver.yaml

# pods are immutable — delete and recreate
kubectl delete pod webserver
kubectl apply -f webserver.yaml
```

## Verify

```bash
kubectl get pod webserver
kubectl describe pod webserver | grep -E "Image:|State:|Ready:"
kubectl events --for pod/webserver
```

Expected:
```
NAME        READY   STATUS    RESTARTS   AGE
webserver   2/2     Running   0          ...

Image: httpd:latest       (httpd-container)
Image: ubuntu:latest      (sidecar-container)
State: Running
```

`2/2` means both containers (`httpd-container` + `sidecar-container`) are running.

## Root cause summary

| Container | Image used | Status |
|---|---|---|
| `httpd-container` | `httpd:latests` ❌ (typo) | `ImagePullBackOff` |
| `sidecar-container` | `ubuntu:latest` ✓ | Running |

The fix: `httpd:latests` → `httpd:latest`. One character (`s`) caused the entire pod to be non-functional because Kubernetes couldn't pull the image from the registry — `docker.io/library/httpd:latests` doesn't exist.

## Why delete + recreate

Pod specs are **immutable** after creation — you can't `kubectl apply` a changed image on a running pod directly (only Deployments support in-place rolling updates). For a bare pod, the only way to update a container image is to delete the pod and recreate it from the corrected manifest.
