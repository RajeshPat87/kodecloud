Namespace first, then the pod inside it. Two objects, one apply.

## Create and apply

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Namespace
metadata:
  name: dev
---
apiVersion: v1
kind: Pod
metadata:
  name: dev-nginx-pod
  namespace: dev
spec:
  containers:
    - name: dev-nginx-pod
      image: nginx:latest
EOF
```

## Verify

```bash
kubectl get namespace dev
kubectl get pod dev-nginx-pod -n dev
kubectl describe pod dev-nginx-pod -n dev | grep -E "Name:|Image:|Namespace:"
```

Expected:
```
NAME          READY   STATUS    RESTARTS   AGE
dev-nginx-pod   1/1     Running   0          ...
```

`describe` shows:
```
Namespace:    dev
Name:         dev-nginx-pod
Image:        nginx:latest
```

## Requirement trace

| Requirement | Evidence |
|---|---|
| Namespace `dev` | `kind: Namespace name: dev` |
| Pod name `dev-nginx-pod` | `metadata.name: dev-nginx-pod` |
| Pod in `dev` namespace | `namespace: dev` |
| Image `nginx:latest` | `image: nginx:latest` |

Two objects applied in one command — namespace and pod both created. Note the `-n dev` flag is needed on all subsequent `kubectl` commands targeting this pod since it's not in the default namespace.
