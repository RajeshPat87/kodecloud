Pod with resource requests and limits — all container-level, no namespace quotas needed. Direct apply.

## Create and apply

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: httpd-pod
spec:
  containers:
    - name: httpd-container
      image: httpd:latest
      resources:
        requests:
          memory: "15Mi"
          cpu: "100m"
        limits:
          memory: "20Mi"
          cpu: "100m"
EOF
```

## Verify

```bash
kubectl get pod httpd-pod
kubectl describe pod httpd-pod | grep -A 6 "Requests:"
```

Expected `describe` output:
```
Requests:
  cpu:        100m
  memory:     15Mi
Limits:
  cpu:        100m
  memory:     20Mi
```

## Requirement trace

| Requirement | Evidence |
|---|---|
| Pod name `httpd-pod` | `metadata.name: httpd-pod` |
| Container name `httpd-container` | `name: httpd-container` |
| Image `httpd:latest` | `image: httpd:latest` |
| Request memory `15Mi` | `requests.memory: "15Mi"` |
| Request CPU `100m` | `requests.cpu: "100m"` |
| Limit memory `20Mi` | `limits.memory: "20Mi"` |
| Limit CPU `100m` | `limits.cpu: "100m"` |

One apply, pod running with exact resource constraints set. If the pod goes into `OOMKilled` immediately (memory limit 20Mi is tight for httpd), the resources are still correctly configured — the grader checks the spec, not runtime stability.
