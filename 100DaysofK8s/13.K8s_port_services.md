ReplicaSet is running with 3 pods. Just need to create the NodePort service targeting the existing pod labels.

## Step 1 — Confirm pod labels

```bash
kubectl get pods --show-labels
```

Should show `app=httpd_app,type=front-end` on each pod.

## Step 2 — Create the service

```bash
cat <<'EOF' | kubectl apply -f -
apiVersion: v1
kind: Service
metadata:
  name: httpd-service
spec:
  type: NodePort
  selector:
    app: httpd_app
    type: front-end
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
EOF
```

## Verify

```bash
kubectl get service httpd-service
kubectl describe service httpd-service | grep -E "Selector:|NodePort:|Port:|Endpoints:"
```

Expected:
```
NAME             TYPE       CLUSTER-IP     EXTERNAL-IP   PORT(S)        AGE
httpd-service    NodePort   10.43.x.x      <none>        80:30080/TCP   ...

Selector:    app=httpd_app,type=front-end
Port:        80/TCP
NodePort:    30080/TCP
Endpoints:   <pod-IPs>:80
```

`Endpoints` showing pod IPs confirms the service selector matched the ReplicaSet pods.

## Requirement trace

| Requirement | Evidence |
|---|---|
| Service name `httpd-service` | `metadata.name: httpd-service` |
| Type `NodePort` | `spec.type: NodePort` |
| NodePort `30080` | `nodePort: 30080` |
| Port `80` exposed | `port: 80`, `targetPort: 80` |
| Selector matches RS pods (`app: httpd_app`, `type: front-end`) | `selector` block; `Endpoints` populated |
| ReplicaSet not modified | only a Service created; RS untouched |

The service selector `app: httpd_app` + `type: front-end` must match both labels on the pods — both are required since the pods carry both labels. A single-label selector would still match but using both is explicit and correct.

Labels confirmed — `app=httpd_app,type=front-end` on all three pods. Apply the service directly:

```bash
cat <<'EOF' | kubectl apply -f -

  name: httpd-service
```
