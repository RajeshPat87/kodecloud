# Runbook and Documentation: Azure Public VNet and VM Deployment

## Overview
This document records the successful deployment of a public Azure virtual network and Linux virtual machine for the Nautilus DevOps task. The deployment used the existing resource group `kml_rg_main-751742b88e2342ab` in `eastus`, created the VNet `datacenter-pub-vnet`, subnet `datacenter-pub-subnet`, and VM `datacenter-pub-vm`, and verified public SSH access successfully. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

## Objective
Provision a public-facing Azure network and VM for application hosting with the following requirements: [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

- VNet name: `datacenter-pub-vnet`. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)
- Subnet name: `datacenter-pub-subnet`. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)
- VM name: `datacenter-pub-vm`. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)
- Region: `eastus`. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-2?view=azure-cli-latest)
- SSH port 22 open and reachable from the internet. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)
- VM size kept in the standard tier, using `Standard_B1s` in this execution. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)
- OS disk forced to `Standard_LRS` to avoid Premium defaults. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

## Environment Details
The lab subscription already contained a single resource group named `kml_rg_main-751742b88e2342ab` in `eastus`, and no resources were present in it before deployment based on `az resource list --resource-group kml_rg_main-751742b88e2342ab -o json` returning an empty array. The VM deployment generated SSH key files at `/root/.ssh/id_rsa` and `/root/.ssh/id_rsa.pub` because no existing key pair was available at runtime. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-4?view=azure-cli-latest)

## Final Script Used
The following idempotent Bash script was used so repeated runs would skip resources that already existed and avoid duplicate SSH rule conflicts.

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "=== STEP 0: Azure login / lab credentials ==="
# Uncomment if your lab requires it
# showcreds
az account show >/dev/null 2>&1 || az login --use-device-code

echo
 echo "=== STEP 1: Variables ==="
RG="kml_rg_main-751742b88e2342ab"
LOCATION="eastus"
VNET_NAME="datacenter-pub-vnet"
SUBNET_NAME="datacenter-pub-subnet"
VNET_CIDR="10.20.0.0/16"
SUBNET_CIDR="10.20.1.0/24"
VM_NAME="datacenter-pub-vm"
VM_SIZE="Standard_B1s"
ADMIN_USER="azureuser"
IMAGE="Ubuntu2204"
OS_DISK_SIZE_GB="30"
STORAGE_SKU="Standard_LRS"
SSH_RULE_NAME="Allow-SSH-22-Custom"
SSH_RULE_PRIORITY="1010"

echo "Resource Group : ${RG}"
echo "Location       : ${LOCATION}"
echo "VNet           : ${VNET_NAME}"
echo "Subnet         : ${SUBNET_NAME}"
echo "VM Name        : ${VM_NAME}"
echo "VM Size        : ${VM_SIZE}"
echo "Image          : ${IMAGE}"
echo "Storage SKU    : ${STORAGE_SKU}"
echo "OS Disk Size   : ${OS_DISK_SIZE_GB} GB"

echo
 echo "=== STEP 2: Ensure resource group exists ==="
az group show --name "${RG}" >/dev/null 2>&1 || {
  echo "ERROR: Resource group ${RG} not found."
  exit 1
}

echo
 echo "=== STEP 3: Ensure VNet exists ==="
if az network vnet show --resource-group "${RG}" --name "${VNET_NAME}" >/dev/null 2>&1; then
  echo "VNet ${VNET_NAME} already exists. Skipping create."
else
  az network vnet create \
    --resource-group "${RG}" \
    --name "${VNET_NAME}" \
    --location "${LOCATION}" \
    --address-prefixes "${VNET_CIDR}" \
    --subnet-name "${SUBNET_NAME}" \
    --subnet-prefixes "${SUBNET_CIDR}" \
    -o table
fi

echo
 echo "=== STEP 4: Ensure subnet exists ==="
if az network vnet subnet show \
  --resource-group "${RG}" \
  --vnet-name "${VNET_NAME}" \
  --name "${SUBNET_NAME}" >/dev/null 2>&1; then
  echo "Subnet ${SUBNET_NAME} already exists. Skipping create."
else
  az network vnet subnet create \
    --resource-group "${RG}" \
    --vnet-name "${VNET_NAME}" \
    --name "${SUBNET_NAME}" \
    --address-prefixes "${SUBNET_CIDR}" \
    -o table
fi

echo
 echo "=== STEP 5: Ensure VM exists ==="
if az vm show --resource-group "${RG}" --name "${VM_NAME}" >/dev/null 2>&1; then
  echo "VM ${VM_NAME} already exists. Skipping create."
else
  az vm create \
    --resource-group "${RG}" \
    --name "${VM_NAME}" \
    --location "${LOCATION}" \
    --image "${IMAGE}" \
    --size "${VM_SIZE}" \
    --admin-username "${ADMIN_USER}" \
    --generate-ssh-keys \
    --vnet-name "${VNET_NAME}" \
    --subnet "${SUBNET_NAME}" \
    --public-ip-sku Standard \
    --storage-sku "${STORAGE_SKU}" \
    --os-disk-size-gb "${OS_DISK_SIZE_GB}" \
    -o table
fi

echo
 echo "=== STEP 6: Ensure SSH port 22 is allowed ==="
NIC_ID="$(az vm show \
  --resource-group "${RG}" \
  --name "${VM_NAME}" \
  --query 'networkProfile.networkInterfaces[0].id' \
  -o tsv)"

NIC_NAME="$(basename "${NIC_ID}")"

NSG_ID="$(az network nic show \
  --resource-group "${RG}" \
  --name "${NIC_NAME}" \
  --query 'networkSecurityGroup.id' \
  -o tsv)"

if [[ -z "${NSG_ID}" ]]; then
  echo "ERROR: No NSG associated with NIC ${NIC_NAME}"
  exit 1
fi

NSG_NAME="$(basename "${NSG_ID}")"

SSH_RULE_EXISTS="$(az network nsg rule list \
  --resource-group "${RG}" \
  --nsg-name "${NSG_NAME}" \
  --query "[?direction=='Inbound' && access=='Allow' && contains(join(',', destinationPortRanges || [destinationPortRange]), '22')].name | [0]" \
  -o tsv)"

if [[ -n "${SSH_RULE_EXISTS}" ]]; then
  echo "SSH allow rule already exists in NSG ${NSG_NAME}: ${SSH_RULE_EXISTS}. Skipping create."
else
  az network nsg rule create \
    --resource-group "${RG}" \
    --nsg-name "${NSG_NAME}" \
    --name "${SSH_RULE_NAME}" \
    --priority "${SSH_RULE_PRIORITY}" \
    --access Allow \
    --protocol Tcp \
    --direction Inbound \
    --source-address-prefixes "*" \
    --source-port-ranges "*" \
    --destination-address-prefixes "*" \
    --destination-port-ranges 22 \
    -o table
fi

echo
 echo "=== STEP 7: Fetch public IP ==="
VM_PUBLIC_IP="$(az vm show -d \
  --resource-group "${RG}" \
  --name "${VM_NAME}" \
  --query publicIps -o tsv)"

if [[ -z "${VM_PUBLIC_IP}" ]]; then
  echo "ERROR: Failed to retrieve public IP for ${VM_NAME}"
  exit 1
fi

echo "VM Public IP: ${VM_PUBLIC_IP}"

echo
 echo "=== STEP 8: Verify configuration ==="
az vm show -d \
  --resource-group "${RG}" \
  --name "${VM_NAME}" \
  --query "{name:name,location:location,powerState:powerState,publicIps:publicIps}" \
  -o table

echo
 echo "=== SUCCESS ==="
echo "VNet ${VNET_NAME} and subnet ${SUBNET_NAME} are present in ${LOCATION}."
echo "VM ${VM_NAME} is present with Standard public IP and Standard_LRS OS disk."
echo "SSH (22) is allowed from the internet."
echo "Connect with:"
echo "  ssh ${ADMIN_USER}@${VM_PUBLIC_IP}"

set +u
exit 0
```

## Execution Procedure
### 1. Validate initial environment
Before deployment, the resource group existed and contained no resources, which was confirmed by `az group list` and `az resource list --resource-group kml_rg_main-751742b88e2342ab -o json` returning an empty list. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-4?view=azure-cli-latest)

### 2. Save and run the script
The script was saved as `script.sh`, permissions were set with `chmod +x script.sh`, and the script was executed from the `azure-client` host. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

```bash
vi script.sh
chmod +x script.sh
./script.sh
```

### 3. Handle first-run SSH rule conflict
The first script version created the VM successfully but failed on `az vm open-port` because Azure had already created a rule named `default-allow-ssh`, and Azure NSG rules cannot share the same priority and direction. The final script fixed this by checking for an existing inbound allow rule on port 22 before creating a new one. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nsg/rule?view=azure-cli-latest)

### 4. Re-run with idempotent logic
On the second execution, the script correctly detected that the VNet, subnet, VM, and SSH rule already existed and skipped those creation steps, then fetched public IP `104.41.141.134` and displayed the final verification table. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/azure-cli-vm-tutorial-4?view=azure-cli-latest)

## Notes and Lessons Learned
The command `az resource list --resorce-group ...` failed because `--resorce-group` is a typo; the correct argument is `--resource-group`. The script explicitly used `--storage-sku Standard_LRS` so the VM OS disk stayed in the standard tier and did not risk defaulting to Premium storage on a supported VM family. The final SSH-rule logic was safer than calling `az vm open-port` unconditionally because it inspected the effective NSG rule set before making changes. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/network/nsg/rule?view=azure-cli-latest)
