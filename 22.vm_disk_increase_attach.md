## Runbook: Expand OS Disk and Add Data Disk for `devops-vm`

### 1. Purpose

Increase storage capacity for the existing Azure Linux VM `devops-vm` by:

- Expanding its OS disk from **32 GiB** to **64 GiB**.  
- Creating and attaching a new **64 GiB Standard_LRS** managed data disk named `devops-disk`.  
- Formatting and mounting the new data disk at **`/mnt/devops-disk`** inside the VM, with a persistent mount using `/etc/fstab`.[user query] [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-format-mount-data-disks-linux)

This is required to support increased workloads on the Nautilus DevOps environment without recreating the VM.

### 2. Scope and Preconditions

- Environment: Azure lab subscription accessed from `azure-client` host.  
- The VM **already exists**:
  - Name: `devops-vm`
  - Location: `eastus`
- Resource group is **not hardcoded**; it is discovered dynamically from the VM definition, which is safer than assuming a static RG name.[user query] [learn.microsoft](https://learn.microsoft.com/en-us/azure/governance/resource-graph/concepts/explore-resources)
- Azure CLI is installed and authenticated (use `showcreds` as per lab, then `az login --use-device-code` if needed).[user query] [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm?view=azure-cli-latest)

### 3. High-level Steps

1. Discover the resource group, location, OS disk name, and admin user for `devops-vm`.  
2. Deallocate `devops-vm` to allow OS disk resize.  
3. Resize the OS disk to 64 GiB.  
4. Start the VM again.  
5. Create a new 64 GiB Standard_LRS managed data disk (`devops-disk`).  
6. Attach the new data disk to `devops-vm`.  
7. Inside the VM (via `az vm run-command invoke`), find the new block device, format it with `ext4`, create `/mnt/devops-disk`, add an `/etc/fstab` entry by UUID, and mount it.  
8. Verify disk sizes, attachment, and mount point. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/add-disk)

```bash
vi script.sh        # paste the script below, save with :wq
./script.sh
```

### 4.2 Script content

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "=== STEP 0: Azure login / lab credentials ==="
# Run showcreds if required in your lab
# showcreds
az account show >/dev/null 2>&1 || az login --use-device-code

echo "=== STEP 1: Discover RG and VM ==="
VM_NAME="devops-vm"
DATA_DISK_NAME="devops-disk"
TARGET_OS_DISK_SIZE_GB="64"
DATA_DISK_SIZE_GB="64"
MOUNT_POINT="/mnt/devops-disk"
DATA_DISK_SKU="Standard_LRS"

# Discover RG from VM
RESOURCE_GROUP="$(az vm list --query "[?name=='${VM_NAME}'].resourceGroup | [0]" -o tsv)"
if [[ -z "${RESOURCE_GROUP}" ]]; then
  echo "ERROR: Could not find VM ${VM_NAME}."
  exit 1
fi

VM_LOCATION="$(az vm show -g "${RESOURCE_GROUP}" -n "${VM_NAME}" --query location -o tsv)"
OS_DISK_NAME="$(az vm show -g "${RESOURCE_GROUP}" -n "${VM_NAME}" --query 'storageProfile.osDisk.name' -o tsv)"
ADMIN_USER="$(az vm show -g "${RESOURCE_GROUP}" -n "${VM_NAME}" --query 'osProfile.adminUsername' -o tsv)"

if [[ -z "${OS_DISK_NAME}" ]]; then
  echo "ERROR: Could not determine OS disk name for ${VM_NAME}."
  exit 1
fi

echo "Using RG          : ${RESOURCE_GROUP}"
echo "VM Name           : ${VM_NAME}"
echo "VM Location       : ${VM_LOCATION}"
echo "Admin User        : ${ADMIN_USER}"
echo "OS Disk Name      : ${OS_DISK_NAME}"
echo "New Data Disk     : ${DATA_DISK_NAME}"
echo "Mount Point       : ${MOUNT_POINT}"

echo
echo "=== STEP 2: Deallocate VM before OS disk resize ==="
az vm deallocate -g "${RESOURCE_GROUP}" -n "${VM_NAME}" -o table

echo
echo "=== STEP 3: Set OS disk size to ${TARGET_OS_DISK_SIZE_GB} GiB ==="
az disk update \
  --resource-group "${RESOURCE_GROUP}" \
  --name "${OS_DISK_NAME}" \
  --size-gb "${TARGET_OS_DISK_SIZE_GB}" \
  -o table

echo
echo "=== STEP 4: Start VM after OS disk resize ==="
az vm start -g "${RESOURCE_GROUP}" -n "${VM_NAME}" -o table

echo
echo "=== STEP 5: Create Standard_LRS ${DATA_DISK_SIZE_GB} GiB data disk if needed ==="
if az disk show -g "${RESOURCE_GROUP}" -n "${DATA_DISK_NAME}" >/dev/null 2>&1; then
  echo "Disk ${DATA_DISK_NAME} already exists; reusing it."
else
  az disk create \
    --resource-group "${RESOURCE_GROUP}" \
    --name "${DATA_DISK_NAME}" \
    --location "${VM_LOCATION}" \
    --size-gb "${DATA_DISK_SIZE_GB}" \
    --sku "${DATA_DISK_SKU}" \
    -o table
fi

echo
echo "=== STEP 6: Attach data disk to VM if not already attached ==="
ATTACHED_DISK_NAMES="$(az vm show -g "${RESOURCE_GROUP}" -n "${VM_NAME}" --query 'storageProfile.dataDisks[].name' -o tsv || true)"

if echo "${ATTACHED_DISK_NAMES}" | grep -qw "${DATA_DISK_NAME}"; then
  echo "Disk ${DATA_DISK_NAME} is already attached to ${VM_NAME}."
else
  az vm disk attach \
    --resource-group "${RESOURCE_GROUP}" \
    --vm-name "${VM_NAME}" \
    --name "${DATA_DISK_NAME}" \
    -o table
fi

echo
echo "=== STEP 7: Format and mount disk inside VM at ${MOUNT_POINT} ==="
az vm run-command invoke \
  --resource-group "${RESOURCE_GROUP}" \
  --name "${VM_NAME}" \
  --command-id RunShellScript \
  --scripts "
set -e

MOUNT_POINT='${MOUNT_POINT}'

# Find the new, unmounted disk
DEVICE=\$(lsblk -dpno NAME,TYPE | awk '\$2==\"disk\" {print \$1}' | while read d; do
  if ! lsblk -no MOUNTPOINT \"\$d\" | grep -q '/'; then
    echo \"\$d\"
  fi
done | head -n 1)

if [ -z \"\$DEVICE\" ]; then
  DEVICE=\$(readlink -f /dev/disk/azure/scsi1/lun0 2>/dev/null || true)
fi

if [ -z \"\$DEVICE\" ]; then
  echo 'Unable to determine attached data disk device.'
  exit 1
fi

# Create filesystem if not already present
if ! blkid \"\$DEVICE\" >/dev/null 2>&1; then
  mkfs.ext4 -F \"\$DEVICE\"
fi

mkdir -p \"\$MOUNT_POINT\"

UUID=\$(blkid -s UUID -o value \"\$DEVICE\")
grep -q \"\$UUID\" /etc/fstab || echo \"UUID=\$UUID \$MOUNT_POINT ext4 defaults,nofail 0 2\" >> /etc/fstab

mountpoint -q \"\$MOUNT_POINT\" || mount \"\$MOUNT_POINT\"

df -h \"\$MOUNT_POINT\"
" \
  -o json

echo
echo "=== STEP 8: Verify final state ==="
az disk show -g "${RESOURCE_GROUP}" -n "${OS_DISK_NAME}" --query "{name:name,sizeGb:diskSizeGb,sku:sku.name}" -o table
az disk show -g "${RESOURCE_GROUP}" -n "${DATA_DISK_NAME}" --query "{name:name,sizeGb:diskSizeGb,sku:sku.name}" -o table
az vm show -g "${RESOURCE_GROUP}" -n "${VM_NAME}" --query "storageProfile.dataDisks[].{name:name,lun:lun}" -o table

echo
echo "=== SUCCESS ==="
echo "OS disk set to ${TARGET_OS_DISK_SIZE_GB} GiB."
echo "Data disk ${DATA_DISK_NAME} created, attached, and mounted at ${MOUNT_POINT}."
set +u
exit 0
```

This structure follows Azure’s guidance for expanding disks on Linux VMs (deallocate → `az disk update` → start VM) and for adding/formatting data disks with CLI. [learn.microsoft](https://learn.microsoft.com/en-us/cli/azure/vm/run-command?view=azure-cli-latest)

## 6. Troubleshooting Notes

- **If OS disk update fails** with `OperationNotAllowed` and an empty disk property, ensure:
  - VM is **deallocated** before `az disk update` (Step 2).  
  - You reference the correct `OS_DISK_NAME` obtained from `az vm show`. [learn.microsoft](https://learn.microsoft.com/en-us/troubleshoot/azure/virtual-machines/windows/troubleshoot-disk-resize)
- **If mount fails**:
  - Re-run `az vm run-command invoke` portion alone; check that the device (e.g., `/dev/sdc`) is the only unmounted data disk.  
  - Ensure `/etc/fstab` uses the UUID, not the raw `/dev/sdX` path, to survive reboots. [learn.microsoft](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-format-mount-data-disks-linux)
