# Runbook — Ansible Inventory for App Server 1 (`stapp01`)

**File:** `/home/thor/playbook/inventory` (ini) · **Host:** jump host · **Target:** `stapp01`
**Validation:** `ansible-playbook -i inventory playbook.yml` (no extra args)
**Status:** Verified — `ping: pong`

## 1. Purpose

Create an ini-type Ansible inventory on the jump host so the DevOps team can run the
playbooks under `/home/thor/playbook/` against App Server 1 in Stratos DC. Ansible runs
**from** the jump host and connects **to** `stapp01` over SSH; the inventory supplies the
hostname and the connection variables so the validation command works with no extra flags.

## 2. Environment / reference values

| Item | Value |
|---|---|
| Control node (where file lives) | jump host, user `thor` |
| Playbook dir | `/home/thor/playbook/` |
| Inventory path | `/home/thor/playbook/inventory` |
| Target server name (wiki) | `stapp01` (App Server 1, Stratos DC) |
| SSH user / password | `tony` / `Ir0nM@n` |
| Connection | `ssh` (password auth via `sshpass`) |

> The inventory hostname MUST be the wiki server name `stapp01` (requirement c), not an
> arbitrary alias.

## 3. Prerequisites

- `/home/thor/playbook/` exists on the jump host (given — playbooks already placed there).
- `ansible` and `sshpass` installed on the jump host (`sshpass` is required for
  `ansible_ssh_pass` password auth; usually preinstalled).
- SSH reachability jump host → `stapp01` as `tony`.

## 4. One-time script (OTS) — run on the jump host as thor

> Run this on **`thor@jump-host`**, NOT on stapp01. The file belongs on the control node;
> nothing is placed on the target. (`/home/thor` does not exist on stapp01.)

```bash
#!/usr/bin/env bash
# jump host — create Ansible inventory for App Server 1 (stapp01)
set -e

mkdir -p /home/thor/playbook

# ini inventory: hostname = wiki server name, plus connection vars
cat > /home/thor/playbook/inventory <<'EOF'
stapp01 ansible_host=stapp01 ansible_user=tony ansible_ssh_pass=Ir0nM@n ansible_connection=ssh
EOF

# optional: ansible.cfg so validation never hits a host-key prompt,
# and a bare `ansible-playbook playbook.yml` still finds the inventory
cat > /home/thor/playbook/ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

echo "== inventory =="; cat /home/thor/playbook/inventory
```

## 5. Inventory line explained

`stapp01 ansible_host=stapp01 ansible_user=tony ansible_ssh_pass=Ir0nM@n ansible_connection=ssh`

| Token | Why it's needed |
|---|---|
| `stapp01` | inventory hostname = wiki server name (requirement c) |
| `ansible_host=stapp01` | actual host Ansible connects to (resolvable name or IP) |
| `ansible_user=tony` | SSH login user for App Server 1 |
| `ansible_ssh_pass=Ir0nM@n` | password auth → no key setup, no `--ask-pass` needed at validation |
| `ansible_connection=ssh` | explicit SSH transport |

Together these let `ansible-playbook -i inventory playbook.yml` connect with **no extra
arguments** (the Note requirement).

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `No such file or directory` writing the file | ran on stapp01, not jump host | `exit` to `thor@jump-host`; `/home/thor` only exists there |
| `sshpass program not found` | `sshpass` missing | `sudo yum install -y sshpass` on the jump host |
| `Host key verification failed` / hangs on first connect | unknown host key | `export ANSIBLE_HOST_KEY_CHECKING=False`, or the `ansible.cfg` in section 4 |
| `Permission denied` on ping | wrong user/password | confirm `tony` / `Ir0nM@n` for stapp01 from the wiki/infra table |
| inventory file owned by root | created via `sudo` | `sudo chown thor:thor /home/thor/playbook/inventory` |
| playbook needs a group name | playbook targets `hosts: <group>` | add a group header, e.g. `[app_servers]` above the `stapp01` line, if the playbook expects it |

## 9. Notes

- **Nothing is installed or placed on stapp01** — the inventory lives entirely on the jump
  host; Ansible reaches the target over SSH at runtime.
- The `ots.sh` helper script location is irrelevant to grading; only
  `/home/thor/playbook/inventory` matters.
- If a playbook uses `hosts: all` (common in these tasks), the single ungrouped `stapp01`
  entry is matched automatically — no group needed. Add `[app_servers]` only if a playbook
  explicitly targets that group.
