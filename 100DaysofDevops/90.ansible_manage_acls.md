## OTS — run on jump host as thor

```bash
#!/usr/bin/env bash
# jump host — per-server empty files owned by root + specific ACLs
set -e

cd /home/thor/ansible

[ -f ansible.cfg ] || cat > ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

cat > playbook.yml <<'EOF'
---
- name: blog.txt + ACL on app server 1
  hosts: stapp01
  become: true
  tasks:
    - name: Create /opt/itadmin/blog.txt owned by root
      ansible.builtin.file:
        path: /opt/itadmin/blog.txt
        state: touch
        owner: root
        group: root
    - name: Give group tony read on blog.txt
      ansible.posix.acl:
        path: /opt/itadmin/blog.txt
        entity: tony
        etype: group
        permissions: r
        state: present

- name: story.txt + ACL on app server 2
  hosts: stapp02
  become: true
  tasks:
    - name: Create /opt/itadmin/story.txt owned by root
      ansible.builtin.file:
        path: /opt/itadmin/story.txt
        state: touch
        owner: root
        group: root
    - name: Give user steve read+write on story.txt
      ansible.posix.acl:
        path: /opt/itadmin/story.txt
        entity: steve
        etype: user
        permissions: rw
        state: present

- name: media.txt + ACL on app server 3
  hosts: stapp03
  become: true
  tasks:
    - name: Create /opt/itadmin/media.txt owned by root
      ansible.builtin.file:
        path: /opt/itadmin/media.txt
        state: touch
        owner: root
        group: root
    - name: Give group banner read+write on media.txt
      ansible.posix.acl:
        path: /opt/itadmin/media.txt
        entity: banner
        etype: group
        permissions: rw
        state: present
EOF

echo "== playbook.yml =="; cat playbook.yml
```

## Why each piece

**Three separate plays, one per host** — because every parameter differs (file name, entity, etype, perms). Targeting `hosts: stapp01/02/03` individually is cleaner and less error-prone than one play with three `when:`-gated task sets. Requirement mapping is 1:1 and obvious.

**`file: state: touch` with `owner: root group: root`** — creates the empty file (requirement: empty file) owned by root only (the team's requirement that root owns them). `become: true` is required since `/opt/itadmin` is root territory.

**`ansible.posix.acl` module** — this is the correct module for ACLs (the task says "using acl"). Per entry:
- `entity` = the user/group name (tony / steve / banner)
- `etype` = `group` or `user` exactly as specified per task
- `permissions` = `r` (task 1) or `rw` (tasks 2, 3)
- `state: present` adds the ACL entry without removing existing perms

**Hostnames must match your inventory** — I used `stapp01/02/03`. If your inventory groups them (e.g. `[app_servers]`), the individual hostnames still work as `hosts:` targets. If the inventory uses different aliases, match those.

## Watch-outs

- **`ansible.posix.acl` collection** — the module lives in the `ansible.posix` collection. On KodeKloud jump hosts it's preinstalled. If the run errors "couldn't resolve module ansible.posix.acl", install it: `ansible-galaxy collection install ansible.posix` (or just use the short name `acl:` if the collection is already in the default path — the FQCN is safest).
- **`/opt/itadmin` must exist** — `file: state: touch` creates the *file* but not missing parent dirs. If `/opt/itadmin` doesn't exist, add a `file: path: /opt/itadmin state: directory` task before each touch. In these labs the dir usually exists, but add it if the run errors "No such file or directory".
- **etype exactness** — task 1 is `group` tony, task 2 is `user` steve, task 3 is `group` banner. Mixing these up is the easy mistake; the playbook above matches each exactly.
- **`become: true`** — required; files are root-owned in a root dir.
- **Hostnames match inventory** — if `hosts: stapp01` matches nothing, the play skips silently ("no hosts matched"); confirm your inventory host names.
- File exact: playbook `/home/thor/ansible/playbook.yml`.
