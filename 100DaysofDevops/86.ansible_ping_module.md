# Runbook — Password-less SSH: Jump Host → App Servers (Ansible)

**Controller:** jump host, user `thor` · **Managed node (required):** App Server 1 (`stapp01`)
**Inventory:** `/home/thor/ansible/inventory` · **Validation:** `ansible -i inventory stapp01 -m ping` → `pong`
**Status:** Verified — key installed, inventory uses `ansible_user`, ping returns pong

## 1. Purpose

Establish key-based (password-less) SSH from the Ansible controller (`thor` on the jump
host) to the managed nodes, so playbooks run without prompting for passwords. The ticket
requires App Server 1 specifically; all three app servers are set up for completeness.
Success = `ansible -m ping` to `stapp01` returns `pong` with no password prompt.

## 2. Environment / reference values

| Server | Host | SSH user | Password (one-time, for key copy only) |
|---|---|---|---|
| App Server 1 | `stapp01` | `tony` | `Ir0nM@n` |
| App Server 2 | `stapp02` | `steve` | `Am3ric@` |
| App Server 3 | `stapp03` | `banner` | `BigGr33n` |

| Item | Value |
|---|---|
| Controller | jump host, user `thor` |
| Inventory path | `/home/thor/ansible/inventory` |
| thor's key pair | `~/.ssh/id_rsa` / `~/.ssh/id_rsa.pub` |

> The password is used **once** per host by `ssh-copy-id`. After that, auth is key-based.
> The inventory must NOT carry `ansible_ssh_pass` — the ticket grades password-less (key)
> auth, so login relies on the copied key + `ansible_user`.

## 3. Prerequisites

- `thor` shell on the jump host.
- Inventory file exists at `/home/thor/ansible/inventory` (given).
- SSH reachability jump host → app servers.

## 4. Core concept — why user + key both matter

Two independent things must line up:
- **The key must be installed for the login user on the target.** `ssh-copy-id tony@stapp01`
  appends thor's public key to `/home/tony/.ssh/authorized_keys` on stapp01. The key is
  now trusted **only for tony**.
- **The inventory must tell Ansible to connect as that same user.** `ansible_user=tony`
  makes Ansible log in as tony, which is who the key is installed for.

If the inventory omits `ansible_user`, Ansible connects as the **controller user (thor)**,
finds no matching key for thor on the target, and falls back to a password it doesn't have
→ `UNREACHABLE! Invalid/incorrect password`. That's the classic failure for this task.

## 5. One-time script (OTS) — run on jump host as thor

```bash
#!/usr/bin/env bash
# jump host — password-less SSH from thor to app servers
set -e

# 1. generate thor's key pair non-interactively if absent
[ -f ~/.ssh/id_rsa ] || ssh-keygen -t rsa -b 2048 -N "" -f ~/.ssh/id_rsa

# 2. inventory with ansible_user per host, NO password (key auth)
cat > /home/thor/ansible/inventory <<'EOF'
stapp01 ansible_host=stapp01 ansible_user=tony
stapp02 ansible_host=stapp02 ansible_user=steve
stapp03 ansible_host=stapp03 ansible_user=banner
EOF

# 3. (optional) cfg to avoid host-key prompts + set default inventory
cat > /home/thor/ansible/ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

# 4. copy the public key to each host (prompts ONCE per host for that user's password)
ssh-copy-id -o StrictHostKeyChecking=no tony@stapp01     # Ir0nM@n
ssh-copy-id -o StrictHostKeyChecking=no steve@stapp02    # Am3ric@
ssh-copy-id -o StrictHostKeyChecking=no banner@stapp03   # BigGr33n
```

> Only stapp01 is strictly required by the ticket. The other two are harmless and match
> "managed nodes." A "All keys were skipped because they already exist" message means the
> key was already installed on that host — that's fine.

## 6. Verification

```bash
cd /home/thor/ansible

# inventory has ansible_user (not a password)
cat inventory

# password-less SSH: no prompt, prints the hostname
ssh tony@stapp01 hostname

# THE graded check
ansible -i inventory stapp01 -m ping
```

Pass output:
```
stapp01 | SUCCESS => {
    "ansible_facts": { "discovered_interpreter_python": "/usr/bin/python3" },
    "changed": false,
    "ping": "pong"
}
```
No password prompt anywhere = password-less confirmed.


## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `UNREACHABLE! Invalid/incorrect password` | inventory missing `ansible_user` → connects as thor | add `ansible_user=<user>` per host (section 5) |
| `Unable to parse /home/thor/inventory` | ran from `~`, not the ansible dir | `cd /home/thor/ansible` first, or use full path `-i /home/thor/ansible/inventory` |
| `ssh-copy-id: no identities found` | key pair not generated | `ssh-keygen -t rsa -N "" -f ~/.ssh/id_rsa`, retry |
| Still prompts for password on `ssh <user>@host` | key not installed for that user | re-run `ssh-copy-id <user>@host`; confirm "Number of key(s) added: 1" |
| `Host key verification failed` in ping | unknown host fingerprint | `ansible.cfg` with `host_key_checking = False` (section 5) |
| `sshpass ... Host Key checking is enabled` | only appears with password auth + unknown key | not relevant once key auth is used; if seen, add the cfg above |
| Key auth works but ping fails | wrong user in inventory vs. where key was copied | inventory `ansible_user` must equal the `ssh-copy-id` target user |

## 9. Notes

- **Nothing is placed on the app servers except the public key** in each user's
  `authorized_keys`. The inventory and key pair live on the jump host.
- **Keep `ansible_ssh_pass` out of the inventory** — a `pong` obtained via a password does
  not satisfy a "password-less SSH" ticket; the grader expects key-based auth.
- The key is installed **per user per host** — tony on stapp01, steve on stapp02, banner on
  stapp03 — because that's who each inventory line logs in as.
