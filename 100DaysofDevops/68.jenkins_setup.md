## Installation and Configuration Steps

### Step 1: Install Java (initially Java 11; later upgrade to Java 21)

Initially, you may have Java 11 installed:

```bash
apt-get update
apt-get install -y openjdk-11-jre-headless gnupg
java -version
```

Jenkins logs will show:

```text
Running with Java 11 ... which is older than the minimum required version (Java 21).
Supported Java versions are: [21, 25]
```

This indicates Jenkins requires **Java 21+** for the installed version. [jenkins](https://www.jenkins.io/doc/book/platform-information/support-policy-java/)

**Correct approach for this lab: install Java 21 via apt and set it as default:**

```bash
apt-get update
apt-get install -y openjdk-21-jdk
# or if you prefer runtime-only:
apt-get install -y openjdk-21-jre-headless
```

Set Java 21 as the default JVM if multiple versions are present:

```bash
update-alternatives --config java
# Select the openjdk-21 entry
java -version   # confirm it shows version "21.x"
```

This satisfies Jenkins’ minimum Java requirement and uses apt only, per lab instructions. [rosehosting](https://www.rosehosting.com/blog/how-to-install-java-21-on-ubuntu-24-04/)

***

### Step 2: Install Jenkins via apt

Add the Jenkins repository and install the package:

```bash
# Add Jenkins GPG key
curl -fsSL https://pkg.jenkins.io/debian-stable/jenkins.io.key | apt-key add -

# Add Jenkins repository
echo "deb https://pkg.jenkins.io/debian-stable binary/" > /etc/apt/sources.list.d/jenkins.list

# Update and install Jenkins
apt-get update
apt-get install -y jenkins
```

This installs Jenkins under `/usr/share/jenkins` and sets up the `jenkins` service unit.

***

### Step 3: Start Jenkins using `service` and handle startup errors

Start Jenkins:

```bash
service jenkins start
```

If Jenkins starts successfully:

```bash
service jenkins status
# Expect: jenkins is running / active (running)
```

In this lab, you initially saw:

```text
* Starting Jenkins Automation Server jenkins  Setting up max open files limit to 8192 [fail]
* jenkins is not running
```

The log showed:

```bash
tail -n 50 /var/log/jenkins/jenkins.log
Running with Java 11 ... which is older than the minimum required version (Java 21).
Supported Java versions are: [21, 25]
```

Solution:

- Install Java 21 via apt.
- Configure `update-alternatives` to use Java 21.
- Retry:

  ```bash
  service jenkins start
  service jenkins status
  ```

Once Java 21 is the default, Jenkins should start cleanly.​ [jenkins](https://www.jenkins.io/doc/book/platform-information/upgrade-java-to-21/)

If Jenkins still fails, re-check the log for other causes (port conflicts, permissions), but in this lab the Java version was the key fix.

## Notes and Lessons

- **Java compatibility matters**: Modern Jenkins LTS releases require **Java 21+**; running with Java 11 causes startup failures, as seen in the log. [jenkins](https://www.jenkins.io/doc/book/platform-information/support-policy-java/)
- **apt-only constraint**: All installs (Java, Jenkins) were done via `apt`, respecting lab constraints.
- **Service troubleshooting**: Always follow the recommended sequence:
  - `service jenkins status`
  - Check `/var/log/jenkins/jenkins.log`
  - Fix root cause (Java, ports, permissions), then retry.

This documentation captures the full lifecycle: installation, troubleshooting, and admin user creation, tailored to the xFusion Jenkins lab.
