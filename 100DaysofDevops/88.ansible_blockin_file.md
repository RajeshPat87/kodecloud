## OTS — run on jump host as thor

```bash
#!/usr/bin/env bash
# jump host — httpd install + sample page via blockinfile on all app servers
set -e

cd /home/thor/ansible

# (only if the existing inventory doesn't already reach the servers / lacks host-key cfg)
# ensure host-key checking won't block sshpass, and default inventory is set
[ -f ansible.cfg ] || cat > ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

# create the playbook
cat > playbook.yml <<'EOF'
---
- name: Install httpd and deploy sample page on all app servers
  hosts: all
  become: true
  tasks:
    - name: Install httpd
      ansible.builtin.yum:
        name: httpd
        state: present

    - name: Start and enable httpd
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true

    - name: Add sample content to index.html
      ansible.builtin.blockinfile:
        path: /var/www/html/index.html
        create: true
        block: |
          Welcome to XfusionCorp!
          This is Nautilus sample file, created using Ansible!
          Please do not modify this file manually!

    - name: Set owner, group and permissions on index.html
      ansible.builtin.file:
        path: /var/www/html/index.html
        owner: apache
        group: apache
        mode: '0655'
EOF

echo "== playbook.yml =="; cat playbook.yml
```

## Why each piece

**`hosts: all`** — uses whatever the existing inventory defines; works whether the hosts are grouped or not, so you don't need to know the group name.

**`become: true`** — install, service management, and writing under `/var/www/html` all need root.

**Task 1 `yum` + Task 2 `service`** — install httpd, then `state: started` + `enabled: true` satisfies "service up and running" (requirement 1). Both idempotent.

**Task 3 `blockinfile`** — adds the three lines. Two critical details:
- **`create: true`** — the file may not exist yet after a fresh httpd install, so this creates it if absent (otherwise blockinfile errors on a missing path).
- **No `marker` set** — per Note ii, I leave the default markers (`# BEGIN ANSIBLE MANAGED BLOCK` / `# END ...`). Do **not** add `marker: ""` or a custom marker — that's exactly what the note forbids and what fails validation.
- `block: |` preserves the three lines exactly as given.

**Task 4 `file`** — sets `owner: apache`, `group: apache` (requirement 3) and `mode: '0655'` (requirement 4). Quoted mode so YAML reads it as octal. Kept as a separate `file` task rather than piling owner/mode onto blockinfile, because blockinfile's own `owner`/`mode` params apply only when it creates the file — a dedicated `file` task guarantees the final state regardless.

## Watch-outs

- **Note ii — leave `marker` alone.** Don't add `marker: ""` (empty) or a custom string. The default markers must remain. This is the #1 way this specific task fails.
- **`create: true` on blockinfile** — without it, if `/var/www/html/index.html` doesn't exist post-install, the task errors "path does not exist."
- **`mode: '0655'` quoted** — unquoted, YAML may mangle the octal. `0655` is unusual (execute bit for others but not owner) — enter it exactly as the task states, don't "correct" it to 0644.
- **owner `apache` must exist** — installing httpd creates the `apache` user/group, so Task 1 running before Task 4 ensures it exists. Keep task order as written.
- **`become: true` required** for all four tasks.
- **Existing inventory** — don't recreate it; the task says it's already there. Only add `ansible.cfg` if pings fail on host keys.
- File exact: playbook `/home/thor/ansible/playbook.yml`.
