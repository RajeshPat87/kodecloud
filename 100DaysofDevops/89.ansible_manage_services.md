## OTS — run on jump host as thor

```bash
#!/usr/bin/env bash
# jump host — install + start/enable vsftpd on all app servers
set -e

cd /home/thor/ansible

# ensure host-key checking won't block auth + default inventory (only if no cfg yet)
[ -f ansible.cfg ] || cat > ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

# create the playbook
cat > playbook.yml <<'EOF'
---
- name: Install and enable vsftpd on all app servers
  hosts: all
  become: true
  tasks:
    - name: Install vsftpd
      ansible.builtin.yum:
        name: vsftpd
        state: present

    - name: Start and enable vsftpd
      ansible.builtin.service:
        name: vsftpd
        state: started
        enabled: true
EOF

echo "== playbook.yml =="; cat playbook.yml
```

## Why each piece

**`hosts: all`** — uses whatever the existing inventory defines, so you don't need the group name.

**`become: true`** — installing packages and managing services are root operations.

**Task 1 `yum`** — installs `vsftpd` (`state: present`, idempotent).

**Task 2 `service`** — `state: started` (requirement b: running) + `enabled: true` (requirement b: enabled on boot). Both idempotent — reruns report "ok", so validation passes on repeat.

**Requirement d (thor can run it)** — satisfied by creating the playbook under `/home/thor/ansible` as thor and running as thor; nothing extra needed.

- **`become: true` required** — without it, install and service management fail with permission errors.
- **`service` module handles both start + enable** in one task — `state: started` and `enabled: true` together satisfy requirement b fully.
- **Existing inventory** — don't recreate it; the task says it's already there. Only add `ansible.cfg` if pings fail on host keys or sshpass.
