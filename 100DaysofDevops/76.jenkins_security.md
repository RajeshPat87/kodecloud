## 2. Install Matrix Authorization Strategy plugin (if needed)

If the lab doesn’t already have it, you must install **Matrix Authorization Strategy**. [facebook](https://www.facebook.com/groups/ComputerClasslk/posts/27657980943800674/)

1. In Jenkins UI, go to **Manage Jenkins → Manage Plugins**.
2. Go to the **Available** (or **Updates**) tab.
3. Search for:
   - `Matrix Authorization Strategy` (plugin ID: `matrix-auth`).
4. Check the box for the plugin.
5. Click **Install without restart**.
6. After installation completes:
   - Select **Restart Jenkins when installation is complete and no jobs are running**.
   - Wait for Jenkins to restart.
   - If the UI appears stuck, refresh the page until the login screen shows again.
7. Log back in as `admin / Adm!n321`.

***

## 3. Enable Project-based Matrix Authorization globally

You must configure global security to use **Project-based Matrix Authorization Strategy**. [facebook](https://www.facebook.com/groups/ComputerClasslk/posts/27657980943800674/)

1. Go to **Manage Jenkins → Configure Global Security**.
2. Under **Authorization**, select:
   - **Project-based Matrix Authorization Strategy**.
3. In the global matrix:
   - Ensure `admin` has full permissions (Overall/Administer and all relevant boxes).
   - Add users `sam` and `rohan` if they are not already present.
   - For **each** of `sam` and `rohan`, check at least:
     - **Overall / Read**.
   This is required so they can see Jenkins and list jobs; job matrices inherit from global via the parent ACL. [plugins.jenkins](https://plugins.jenkins.io/matrix-auth/)
4. Click **Save**.

Do **not** change any other global settings unless the lab is explicitly asking you to.

## 5. Configure job-level security for Packages

Now set job-level project-based matrix authorization for the **Packages** job.

1. From the dashboard, click on the **Packages** job.
2. On the left, click **Configure**.
3. In the **General** section:
   - Locate the **Enable project-based security** option.
   - Check **Enable project-based security**.
4. Under the job’s **Authorization** matrix:
   - Ensure there is a dropdown or section for **Inheritance strategy**.
   - Select:
     - **Inherit permissions from parent ACL**. [plugins.jenkins](https://plugins.jenkins.io/matrix-auth/)
   This means job-level permissions will inherit from global (and possibly folder) plus any explicit entries here.

***

## 6. Grant permissions to sam and rohan on Packages

With project-based security enabled and inheritance set, add the job-specific permissions exactly as requested. [plugins.jenkins](https://plugins.jenkins.io/matrix-auth/)

1. In the matrix for the **Packages** job:

   **For `sam`:**
   - Add user `sam` if not already listed.
   - Check these **Job** permissions:
     - **Job / Build**
     - **Job / Configure**
     - **Job / Read**

   This satisfies:
   - build, configure, read.

   **For `rohan`:**
   - Add user `rohan` if not already listed.
   - Check these permissions:
     - **Job / Build**
     - **Job / Cancel**
     - **Job / Configure**
     - **Job / Read**
     - **Job / Update**
     - **Job / Tag** (on some UIs this may appear as “SCM Tag” or a workspace/tag-related permission). [plugins.jenkins](https://plugins.jenkins.io/matrix-auth/)

2. Confirm that:
   - `admin` still has full permissions on the job.
   - No other user’s permissions have been altered.

3. Scroll down and click **Save**.

This completes the per‑job configuration for the `Packages` job.

## 7. Optional: Use CLI to verify job config (matches your style)

Since you’ve already used CLI with `get-job` and `grep`, you can verify the job configuration via CLI:

On the Jenkins server:

```bash
cd ~
java -jar jenkins-cli.jar \
  -s http://localhost:8080 \

  get-job Packages > packages-config.xml

grep -A10 'AuthorizationMatrixProperty' packages-config.xml
```

You should see a block similar to: [plugins.jenkins](https://plugins.jenkins.io/matrix-auth/)

```xml
<hudson.security.AuthorizationMatrixProperty>
  <inheritanceStrategy class="org.jenkinsci.plugins.matrixauth.inheritance.InheritParentStrategy"/>
  <permission>hudson.model.Item.Read:sam</permission>
  <permission>hudson.model.Item.Build:sam</permission>
  <permission>hudson.model.Item.Configure:sam</permission>
  <permission>hudson.model.Item.Read:rohan</permission>
```

Do not modify the XML directly unless you need to fix something; the lab expects changes through UI, but CLI inspection is safe.
