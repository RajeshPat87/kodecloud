# Terraform AWS Private VPC Infrastructure - Complete Documentation

## Overview

This Terraform configuration provisions a private, isolated AWS networking environment consisting of a VPC, subnet, security group, and EC2 instance. All resources are designed to remain isolated from external networks, with communication restricted to within the VPC boundaries.

***

## Architecture

```
┌─────────────────────────────────────────────────────┐
│  VPC: devops-priv-vpc (10.0.0.0/16)                │
│  ┌───────────────────────────────────────────────┐  │
│  │  Subnet: devops-priv-subnet (10.0.1.0/24)    │  │
│  │  ┌─────────────────────────────────────────┐  │  │
│  │  │  EC2: devops-priv-ec2 (t2.micro)       │  │  │
│  │  │  - Private IP only                     │  │  │
│  │  │  - No public IP auto-assign            │  │  │
│  │  └─────────────────────────────────────────┘  │  │
│  │                                               │  │
│  │  Security Group: devops-priv-sg              │  │
│  │  - Ingress: VPC CIDR only (all TCP ports)    │  │
│  │  - Egress: All traffic allowed               │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

## Terraform Code

### main.tf

```hcl
provider "aws" {
  region = "us-east-1"
}

resource "aws_vpc" "devops-priv-vpc" {
  cidr_block           = var.KKE_VPC_CIDR
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Name = "devops-priv-vpc"
  }
}

resource "aws_subnet" "devops-priv-subnet" {
  vpc_id                  = aws_vpc.devops-priv-vpc.id
  cidr_block              = var.KKE_SUBNET_CIDR
  availability_zone       = "us-east-1a"
  map_public_ip_on_launch = false

  tags = {
    Name = "devops-priv-subnet"
  }
}

resource "aws_security_group" "devops-priv-sg" {
  name        = "devops-priv-sg"
  description = "Security group for private EC2 instance"
  vpc_id      = aws_vpc.devops-priv-vpc.id

  ingress {
    description = "Allow access from within VPC"
    from_port   = 0
    to_port     = 65535
    protocol    = "tcp"
    cidr_blocks = [var.KKE_VPC_CIDR]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "devops-priv-sg"
  }
}

resource "aws_instance" "devops-priv-ec2" {
  ami                    = "ami-0c55b159cbfafe1f0"
  instance_type          = "t2.micro"
  subnet_id              = aws_subnet.devops-priv-subnet.id
  vpc_security_group_ids = [aws_security_group.devops-priv-sg.id]

  tags = {
    Name = "devops-priv-ec2"
  }
}
```

## Resource Details

### 1. VPC (`aws_vpc.devops-priv-vpc`)

| Attribute | Value |
|-----------|-------|
| **Name** | `devops-priv-vpc` |
| **CIDR Block** | `10.0.0.0/16` (via `KKE_VPC_CIDR` variable) |
| **DNS Hostnames** | Enabled |
| **DNS Support** | Enabled |
| **Total IP Addresses** | 65,536 |

**Purpose:** Provides an isolated virtual network environment in AWS where resources can be launched in a logically separated space.

***

### 2. Subnet (`aws_subnet.devops-priv-subnet`)

| Attribute | Value |
|-----------|-------|
| **Name** | `devops-priv-subnet` |
| **CIDR Block** | `10.0.1.0/24` (via `KKE_SUBNET_CIDR` variable) |
| **Availability Zone** | `us-east-1a` |
| **Auto-Assign Public IP** | Disabled (`map_public_ip_on_launch = false`) |
| **Total IP Addresses** | 256 (251 usable) |

**Purpose:** Creates a private subnet within the VPC where EC2 instances do not receive public IP addresses automatically, ensuring network isolation.

***

### 3. Security Group (`aws_security_group.devops-priv-sg`)

| Attribute | Value |
|-----------|-------|
| **Name** | `devops-priv-sg` |
| **VPC** | `devops-priv-vpc` |
| **Ingress Rules** | TCP ports 0-65535 from VPC CIDR (`10.0.0.0/16`) |
| **Egress Rules** | All traffic (`0.0.0.0/0`) |

**Purpose:** Acts as a virtual firewall controlling inbound and outbound traffic. Only allows access from within the VPC, maintaining isolation from external networks.

***

### 4. EC2 Instance (`aws_instance.devops-priv-ec2`)

| Attribute | Value |
|-----------|-------|
| **Name** | `devops-priv-ec2` |
| **Instance Type** | `t2.micro` |
| **AMI** | `ami-0c55b159cbfafe1f0` (Amazon Linux 2, us-east-1) |
| **Subnet** | `devops-priv-subnet` |
| **Security Group** | `devops-priv-sg` |
| **Public IP** | Not assigned (private subnet) |

**Purpose:** Provides a compute instance accessible only from within the VPC, suitable for backend services, databases, or internal applications.

## Security Considerations

### Network Isolation
- ✅ No internet gateway attached
- ✅ No public IP auto-assignment on subnet
- ✅ Security group restricts ingress to VPC CIDR only
- ✅ EC2 instance accessible only from within VPC

### Access Control
- All inbound traffic restricted to `10.0.0.0/16` (VPC range)
- Outbound traffic allowed to all destinations (can be restricted further if needed)
- No SSH access from public internet

### Recommendations for Production
1. **Enable VPC Flow Logs** for network traffic monitoring
2. **Restrict egress rules** to specific required destinations
3. **Use AWS Systems Manager Session Manager** for EC2 access instead of SSH
4. **Implement AWS PrivateLink** for accessing AWS services privately
5. **Add AWS Config rules** for compliance monitoring

## Troubleshooting

### Common Issues

#### 1. AMI Not Found
**Error:** `InvalidAMIID.NotFound`

**Solution:** Update the AMI ID in `main.tf` to a current Amazon Linux 2 AMI for your region:
```bash
aws ec2 describe-images \
  --owners amazon \
  --filters "Name=name,Values=amzn2-ami-hvm-*-x86_64-gp2" \
  --query "sort_by(Images, &CreationDate)[-1].ImageId"
```

#### 2. Insufficient Permissions
**Error:** `UnauthorizedOperation` or `AccessDenied`

**Solution:** Ensure your AWS credentials have the following permissions:
- `ec2:CreateVpc`
- `ec2:CreateSubnet`
- `ec2:CreateSecurityGroup`
- `ec2:RunInstances`
- `ec2:CreateTags`

#### 3. Availability Zone Issues
**Error:** `InvalidParameterValue: The AZ 'us-east-1a' is not valid`

**Solution:** Update the availability zone in `main.tf` to one available in your account:
```bash
aws ec2 describe-availability-zones --region us-east-1
```

## Best Practices

### Code Organization
- ✅ Keep all resources in `main.tf` as per requirements
- ✅ Use `variables.tf` for configurable values
- ✅ Use `outputs.tf` for important resource attributes
- ❌ Avoid creating separate `.tf` files for this task

### Naming Conventions
- Use consistent prefix (`devops-priv-`) for all resources
- Include environment/purpose in resource names
- Use tags for cost allocation and identification

### State Management
- Store Terraform state in remote backend (S3 + DynamoDB)
- Enable state locking to prevent concurrent modifications
- Never commit `.tfstate` files to version control

### Cost Optimization
- Use `t2.micro` (free tier eligible) for development
- Implement resource tagging for cost tracking
- Set up AWS Budgets alerts for unexpected charges
