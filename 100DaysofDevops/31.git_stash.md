Here’s the **OTS, runbook, and mermaid** for restoring `stash@{1}` in `/usr/src/kodekloudrepos/demo`, then committing and pushing it. Since this is a write operation and the repo may have ownership restrictions, I’m including `safe.directory` and `sudo` in the flow as requested. [docs.gitlab](https://docs.gitlab.com/topics/git/stash/)

## OTS
```bash
git config --global --add safe.directory /usr/src/kodekloudrepos/demo
cd /usr/src/kodekloudrepos/demo
sudo git stash list
sudo git stash show -p stash@{1}
sudo git stash apply stash@{1}
sudo git add .
sudo git commit -m "restore stash changes"
sudo git push origin master
```

## Runbook
1. Open the `demo` repository on the storage server.
2. Add the repo to Git’s safe directory list if Git reports trust warnings.
3. List available stashes and inspect `stash@{1}` to confirm it contains the required changes.
4. Apply `stash@{1}` to restore the in-progress changes into the working tree.
5. Stage the restored changes.
6. Commit the changes with a clear message.
7. Push the commit to the origin branch.

## Pre-checks
```bash

cd /usr/src/kodekloudrepos/demo

git remote -v
git stash list

```

## Post-checks
```bash
git status
git log --oneline --decorate -3
git stash list
git ls-remote origin master
```

```mermaid

    B --> C[cd /usr/src/kodekloudrepos/demo]
```

## Note
If `sudo` is not actually needed in your environment, you can remove it from the Git commands; but if the repo is root-owned or Git blocks writes, keep it. The key step is using `git stash apply stash@{1}` rather than the latest stash. [docs.gitlab](https://docs.gitlab.com/topics/git/stash/)
