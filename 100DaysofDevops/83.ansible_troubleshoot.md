That's the host-key prompt I flagged — `sshpass` can't answer the "accept this fingerprint?" question, so with host-key checking on, the password login is blocked. Fix is to disable host-key checking. Cleanest way is an `ansible.cfg` in the playbook dir so it applies automatically at validation time (no extra args needed).

## Fix — add ansible.cfg (on jump host as thor)

```bash
cat > /home/thor/ansible/ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF
```

Then retry from that directory:

```bash
cd /home/thor/ansible
ansible -i inventory stapp03 -m ping
```

The `ansible.cfg` is picked up automatically because you're running from `/home/thor/ansible/` (Ansible reads `./ansible.cfg` in the current dir). This is the right approach for the task — validation runs `ansible-playbook -i inventory playbook.yml` from this dir, so it inherits the setting with no extra flags.

## If you can't/don't want the cfg file

Two alternatives:

**Env var (session only — but validation is a separate session, so the cfg is better):**
```bash
export ANSIBLE_HOST_KEY_CHECKING=False
ansible -i inventory stapp03 -m ping
```

**Or add the fingerprint to known_hosts** (what the error literally suggests):
```bash
ssh-keyscan -H stapp03 >> ~/.ssh/known_hosts
ansible -i inventory stapp03 -m ping
```
This works too and needs no cfg, but the `ansible.cfg` approach is more robust for grading because it survives regardless of which host/session runs the validation.

## Recommended path

Use the **ansible.cfg** — it's the one that guarantees the exact validation command works with no extra arguments, which is the task's Note requirement. After the cfg, ping should return:

```
stapp03 | SUCCESS => {
    "ping": "pong"
}
```

Then run the real validation:
```bash
ansible-playbook -i inventory playbook.yml
```
Expect `changed: [stapp03]` and `PLAY RECAP ... failed=0`. Confirm the file:
```bash
ansible -i inventory stapp03 -m shell -a "ls -l /tmp/file.txt"
```
