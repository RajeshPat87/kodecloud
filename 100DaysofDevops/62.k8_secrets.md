## Purpose

Securely store a license/password from `/opt/beta.txt` inside the Kubernetes cluster using a **generic Secret** (`beta`), and deploy a **Pod** (`secret-devops`) running `ubuntu:latest` that mounts this secret as files under `/opt/apps` so the Nautilus DevOps team can verify access to the secret via `kubectl exec`. [kubernetes](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_create/kubectl_create_secret_generic/)

## OTS (One-Time Setup) Commands

Assuming you’re on the jump host with `kubectl` already pointing to the right cluster and `/opt/beta.txt` exists.

### 1) Create secret from `/opt/beta.txt`

```bash
# From jump host, as root or user that can read /opt/beta.txt
kubectl create secret generic beta \
  --from-file=beta=/opt/beta.txt
```

- This creates an Opaque secret named `beta` with key `beta` and value = contents of `beta.txt`. [kubernetes](https://kubernetes.io/docs/reference/kubectl/generated/kubectl_create/kubectl_create_secret_generic/)

Check it:

```bash
kubectl get secret beta
kubectl describe secret beta
```

### 2) Create Pod manifest (YAML)

Create a file, e.g. `secret-devops-pod.yaml`:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secret-devops
spec:
  containers:
    - name: secret-container-devops
      image: ubuntu:latest
      command: ["sleep", "3600"]
      volumeMounts:
        - name: beta-secret-volume
          mountPath: /opt/apps
          readOnly: true
  volumes:
    - name: beta-secret-volume
      secret:
        secretName: beta
```

Apply it:

```bash
kubectl apply -f secret-devops-pod.yaml
```

### 3) Verify Pod and secret mount

```bash
# Check Pod status
kubectl get pod secret-devops

# Exec into the container once Pod is Running
kubectl exec -it secret-devops -- bash
# Inside container:
ls -l /opt/apps
cat /opt/apps/beta
```

You should see the license/password from `beta.txt` rendered in `/opt/apps/beta`. [itnext](https://itnext.io/how-to-mount-secrets-as-files-or-environment-variables-in-kubernetes-f03d545dcd89)

## Runbook

### Step 1: Pre-checks

- Confirm file exists on jump host:

```bash
ls -l /opt/beta.txt
```

- Optional: view the contents to know what you expect:

```bash
cat /opt/beta.txt
```

### Step 2: Create Kubernetes Secret

- Create generic secret `beta` from file:

```bash
kubectl create secret generic beta \
  --from-file=beta=/opt/beta.txt
```

- Validate:

```bash
kubectl get secret beta
kubectl describe secret beta
```

(Do not worry about the value being base64 encoded in `describe`, that is expected for Secrets.) [kubernetes](https://kubernetes.io/docs/concepts/configuration/secret/)

### Step 3: Deploy Pod that mounts the Secret

- Save YAML as `secret-devops-pod.yaml` (content shown above).
- Apply manifest:

```bash
kubectl apply -f secret-devops-pod.yaml
```

- Confirm Pod is up:

```bash
kubectl get pods
kubectl get pod secret-devops -o wide
```

Ensure `STATUS` is `Running` before proceeding to validation.

### Step 4: Validate secret mount inside container

- Exec into Pod:

```bash
kubectl exec -it secret-devops -- bash
```

- Inside container:

```bash
# Confirm mount path
ls -l /opt/apps

# Read the secret file
cat /opt/apps/beta
```

You should see the license/password that was in `/opt/beta.txt`. If the file is missing, double-check:
- Secret name in `volumes.secret.secretName` matches.
- Key (`beta`) exists in secret.
- Pod was recreated after secret changes.

### Step 5: Troubleshooting

- Secret missing:

```bash
kubectl get secret
kubectl describe secret beta
```

- Pod failing:

```bash
kubectl describe pod secret-devops
kubectl logs secret-devops
```

- If you change the secret, delete and recreate the Pod so it mounts the updated secret:

```bash
kubectl delete pod secret-devops
kubectl apply -f secret-devops-pod.yaml
```
