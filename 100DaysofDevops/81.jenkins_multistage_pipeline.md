# Runbook — `deploy-job`: Pipeline Deploy + Test (CLI setup)

**Job:** `deploy-job` (Pipeline, not Multibranch) · **Stages:** `Deploy` → `Test`
**Target:** App Server 1 (`stapp01`) · **Doc root:** `/var/www/html` · **Setup:** Jenkins CLI
**Status:** Verified / passing (green on repeat run; content live at LB root)

## 1. Purpose

Deploy the `sarah/web` repo to Apache's document root on App Server 1 via a two-stage
Jenkins pipeline, then verify the site is reachable. `Deploy` pulls `master` into
`/var/www/html` (the doc root, which is itself the git clone). `Test` curls both local
Apache and the load balancer and fails the build if either isn't returning HTTP 200 —
so a broken deploy or an unreachable site fails the pipeline. Content must serve at the
LB **root** (`http://stlb01:8091`), no `/web` subpath.

`ssh sarah@stapp01` (confirm prompt `sarah@stapp01`; sudo password `Sarah_pass123`):
```bash

sudo chmod 440 /etc/sudoers.d/sarah

# confirm remote + branch
git -C /var/www/html remote -v      # http://sarah:...@gitea:3000/sarah/web.git
git -C /var/www/html branch -a      # master
```

### 7.3 Pipeline job `deploy-job`
```bash
cat <<'EOF' | java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' \
  create-job deploy-job
<flow-definition plugin="workflow-job">
  <description>Deploy web repo to /var/www/html and test accessibility</description>
  <keepDependencies>false</keepDependencies>
  <properties/>
  <definition class="org.jenkinsci.plugins.workflow.cps.CpsFlowDefinition" plugin="workflow-cps">
    <script>pipeline {
    agent { label 'stapp01' }
    stages {
        stage('Deploy') {
            steps {
                sh '''
                    cd /var/www/html
                    git config --global --add safe.directory /var/www/html
                    git checkout master
                    git pull origin master
                '''
            }
        }
        stage('Test') {
            steps {
                sh '''
                    lcode=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/)
                    echo "local Apache HTTP $lcode"
                    test "$lcode" = "200"

                    bcode=$(curl -s -o /dev/null -w "%{http_code}" http://stlb01:8091/)
                    echo "LB HTTP $bcode"
                    test "$bcode" = "200"
                '''
            }
        }
    }
}</script>
    <sandbox>true</sandbox>
  </definition>
  <triggers/>
  <disabled>false</disabled>
</flow-definition>
EOF
```

**Test-stage design note (why this passes):** the stage gates on **HTTP 200 only**, not on
a content string. An earlier variant used `grep "Welcome…"` on the LB body, which returned
exit 1 (no match) and failed the build even though the deploy was fine. Status-only checks
satisfy the requirement ("curl to see if the website is working") without that fragility.
`Test` runs after `Deploy`, so a failed Deploy aborts before Test — a broken deploy also
fails the build, as required.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Build red at Test, `grep` exit 1 | content-string assertion too strict | gate on HTTP 200 only (section 7.3) |
| Test red, `LB HTTP 000` | agent can't reach `stlb01:8091` | check `getent hosts stlb01`; drop LB line, keep local `localhost:8080` check |
| "Plugin is missing: ..." after restart | installed by `.hpi` URL | reinstall via UI / CLI-by-name |
| Node offline, Java error in log | wrong agent JVM | set JavaPath `/usr/lib/jvm/java-17-openjdk/bin/java` |
| `git pull` prompts for auth | remote lacks creds | `git remote set-url origin http://sarah:Sarah_pass123@gitea:3000/sarah/web.git` |
| `fatal: dubious ownership` | doc root not sarah-owned | `safe.directory` + `chown` (section 5) |
| `create-job`/`create-node` says exists | duplicate | `delete-*` then re-create, or `update-*  < config.xml` |
| Content shows at `/web` | copied into subfolder | pull in place (doc root is the clone) — no copy step |
