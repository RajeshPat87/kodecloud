## 1. Task requirements recap

You must configure a Jenkins controller to use three app servers as **SSH build agents**:

1. Create three slave nodes:
   - `App_server_1`
   - `App_server_2`
   - `App_server_3`
2. Add labels:
   - `App_server_1` → `stapp01`
   - `App_server_2` → `stapp02`
   - `App_server_3` → `stapp03`
3. Remote root directories:
   - `App_server_1` → `/home/tony/jenkins`
   - `App_server_2` → `/home/steve/jenkins`
   - `App_server_3` → `/home/banner/jenkins`
4. All slave nodes must be **online** and working properly (SSH auth OK, Java OK, agent running).

## 2. Prepare SSH keys on the Jenkins controller

### 2.1 Log into Jenkins server as jenkins

From the jump host:

```bash
ssh jenkins@jenkins
```

If `/var/lib/jenkins/.ssh` does not exist, create and generate keys:

```bash
mkdir -p /var/lib/jenkins/.ssh
chmod 700 /var/lib/jenkins/.ssh

ssh-keygen -t rsa -b 4096 -f /var/lib/jenkins/.ssh/id_rsa -N ""
```

Verify:

```bash
ls -l /var/lib/jenkins/.ssh
cat /var/lib/jenkins/.ssh/id_rsa
cat /var/lib/jenkins/.ssh/id_rsa.pub
```

We will use:

- `/var/lib/jenkins/.ssh/id_rsa` → **private key** (pasted into Jenkins credentials).
- `/var/lib/jenkins/.ssh/id_rsa.pub` → **public key** (added to `authorized_keys` on app servers).

## 4. Ensure Java 17 on all app servers

Jenkins agents require Java 17 for the current `remoting.jar`. Install and select Java 17 on each app server.

### 4.1 Install Java 17 (RHEL/Alma/Rocky style)

On each server (`stapp01`, `stapp02`, `stapp03`), as a user with `sudo`:

```bash
sudo dnf install -y java-17-openjdk
```

(or `sudo yum install -y java-17-openjdk` if `dnf` is not available).

### 4.2 Select Java 17 as default

On each server:

```bash
sudo alternatives --config java
```

Choose the entry like:

```text
2           java-17-openjdk.x86_64 (/usr/lib/jvm/java-17-openjdk-17.../bin/java)
```

Confirm:

```bash
java -version
# should show openjdk version "17.x"
```

Do this on **stapp01**, **stapp02**, and **stapp03**.

## 6. Create SSH credentials in Jenkins UI

You need one SSH credential for each app server user, all using `/var/lib/jenkins/.ssh/id_rsa`.

### Common: get private key from Jenkins server

On `jenkins@jenkins`:

```bash
cat /var/lib/jenkins/.ssh/id_rsa
```

Copy the entire private key (`-----BEGIN OPENSSH PRIVATE KEY-----` … `-----END OPENSSH PRIVATE KEY-----`).

### 6.1 Credential for tony@stapp01

In Jenkins UI:

1. **Manage Jenkins → Manage Credentials**.
2. Under **(global)**, click **Add Credentials**.
3. Select **SSH Username with private key**, click **Next**.
4. Fill:
   - **Scope**: Global.
   - **ID**: `ssh-tony-stapp01`.
   - **Description**: `SSH key for tony@stapp01`.
   - **Username**: `tony`.
   - **Private Key**: select **“Enter directly”**, paste the `id_rsa` content into the Key box.
   - **Passphrase**: leave empty.
5. Click **Create**.

### 6.2 Credential for steve@stapp02

Repeat:

- ID: `ssh-steve-stapp02`
- Description: `SSH key for steve@stapp02`
- Username: `steve`
- Private Key: paste `id_rsa`
- Passphrase: empty

### 6.3 Credential for banner@stapp03

- ID: `ssh-banner-stapp03`

2. Click **New Node**.
3. Fill:
   - **Node name**: `App_server_1`.
   - Select **Permanent Agent**.
   - Click **Create**.
4. On the node configuration:
   - **Description**: optional.
   - # of executors: `2` (or as per lab).
   - **Remote root directory**: `/home/tony/jenkins`.
   - **Labels**: `stapp01`.
   - **Usage**: “Use this node as much as possible”.

     - **Credentials**: `ssh-tony-stapp01`.

## 8. Bring nodes online and verify

### 8.1 Reconnect and check logs

For each node (`App_server_1`, `App_server_2`, `App_server_3`):

1. Go to **Manage Jenkins → Nodes**.
2. Click the node name.
3. Click **Reconnect** (if available).
4. Click **Log** and check:

You should see for a successful connection:

- `[SSH] Opening SSH connection to stapp0X:22.`
- `[SSH] Authentication successful.`
- `[SSH] Copying latest remoting.jar...`
- `Starting agent process: cd "/home/USER/jenkins" && java -jar remoting.jar -workDir /home/USER/jenkins -jar-cache /home/USER/jenkins/remoting/jarCache`
- No `Publickey authentication failed`.
- No `UnsupportedClassVersionError`.

Once the agent starts correctly, the node status in **Nodes** page will be **Online** (green icon).

### 8.2 Typical issues and how they were resolved

- **Publickey authentication failed**:
  - Cause: user’s `authorized_keys` missing or wrong public key; Jenkins credential private key wrong.
  - Fix: add PUBLIC_KEY_LINE to `~/.ssh/authorized_keys`; paste correct `id_rsa` into Jenkins credential.

- **UnsupportedClassVersionError (class file version 61.0 vs 55.0)**:
  - Cause: app server using Java 11; Jenkins agent requires Java 17.
  - Fix: install `java-17-openjdk`, select via `alternatives --config java`, confirm `java -version` shows 17.

After you’ve applied both fixes where needed, all three nodes should be online.
