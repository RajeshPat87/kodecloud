You now have a correctly deployed **Iron Gallery** + **Iron DB** stack in `iron-namespace-xfusion`, with proper deployments and services. Below are the OTS commands, purpose, key learnings, a concise runbook, and a Mermaid diagram you can reuse for future labs or interviews.

***

## Purpose

Set up a **multi-tier app** (Iron Gallery frontend + MariaDB backend) in a dedicated namespace `iron-namespace-xfusion`, with:

- Isolated deployments for frontend and DB.
- Correct resource limits and ephemeral storage using `emptyDir` volumes.
- Internal DB exposure via **ClusterIP** service (`iron-db-service-xfusion` on port 3306).
- External frontend exposure via **NodePort** service (`iron-gallery-service-xfusion` on nodePort 32678). [devrajesh.hashnode](https://devrajesh.hashnode.dev/day-63-deploy-iron-gallery-app-on-kubernetes-100-days-of-devops)

***

## OTS (One-Time Setup) Commands

These are the core commands you’d run from a fresh jump host for the xfusion lab.

### 1) Namespace

```bash
kubectl create namespace iron-namespace-xfusion
```

### 2) Iron Gallery deployment

```bash
cat << 'EOF' > iron-gallery-deployment-xfusion.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: iron-gallery-deployment-xfusion
  namespace: iron-namespace-xfusion
  labels:
    run: iron-gallery
spec:
  replicas: 1
  selector:
    matchLabels:
      run: iron-gallery
  template:
    metadata:
      labels:
        run: iron-gallery
    spec:
      containers:
        - name: iron-gallery-container-xfusion
          image: kodekloud/irongallery:2.0
          resources:
            limits:
              memory: "100Mi"
              cpu: "50m"
          volumeMounts:
            - name: config
              mountPath: /usr/share/nginx/html/data
            - name: images
              mountPath: /usr/share/nginx/html/uploads
      volumes:
        - name: config
          emptyDir: {}
        - name: images
          emptyDir: {}
EOF

kubectl apply -f iron-gallery-deployment-xfusion.yaml
```

### 3) Iron DB deployment

```bash
cat << 'EOF' > iron-db-deployment-xfusion.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: iron-db-deployment-xfusion
  namespace: iron-namespace-xfusion
  labels:
    db: mariadb
spec:
  replicas: 1
  selector:
    matchLabels:
      db: mariadb
  template:
    metadata:
      labels:
        db: mariadb
    spec:
      containers:
        - name: iron-db-container-xfusion
          image: kodekloud/irondb:2.0
          env:
            - name: MYSQL_DATABASE
              value: database_host
            - name: MYSQL_ROOT_PASSWORD
              value: "RootP@ssw0rd#IronDB!"
            - name: MYSQL_PASSWORD
              value: "UserP@ssw0rd#IronDB!"
            - name: MYSQL_USER
              value: "ironuser"
          volumeMounts:
            - name: db
              mountPath: /var/lib/mysql
      volumes:
        - name: db
          emptyDir: {}
EOF

kubectl apply -f iron-db-deployment-xfusion.yaml
```

### 4) Iron DB service (ClusterIP)

```bash
cat << 'EOF' > iron-db-service-xfusion.yaml
apiVersion: v1
kind: Service
metadata:
  name: iron-db-service-xfusion
  namespace: iron-namespace-xfusion
spec:
  type: ClusterIP
  selector:
    db: mariadb
  ports:
    - protocol: TCP
      port: 3306
      targetPort: 3306
EOF

kubectl apply -f iron-db-service-xfusion.yaml
```

### 5) Iron Gallery service (NodePort)

```bash
cat << 'EOF' > iron-gallery-service-xfusion.yaml
apiVersion: v1
kind: Service
metadata:
  name: iron-gallery-service-xfusion
  namespace: iron-namespace-xfusion
spec:
  type: NodePort
  selector:
    run: iron-gallery
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
      nodePort: 32678
EOF

kubectl apply -f iron-gallery-service-xfusion.yaml
```

Validation:

```bash
kubectl -n iron-namespace-xfusion get deploy,pods,svc
```

## Learnings

- **Namespace isolation**: Creating `iron-namespace-xfusion` cleanly scopes all Iron Gallery resources, a pattern you’ll reuse for multi-tenant or environment isolation. [kubernetes](https://kubernetes.io/docs/tutorials/cluster-management/namespaces-walkthrough/)
- **Correct labels and selectors**: Matching `run=iron-gallery` and `db=mariadb` across deployments and services is critical for service discovery; mislabels are a common exam/lab pitfall.
- **Ephemeral storage via emptyDir**: Using `emptyDir` for config/images and DB data gives per-pod temporary storage; ideal for labs, not production DBs.
- **Service types semantics**:
  - `ClusterIP` for internal-only DB access.
  - `NodePort` to expose frontend to external clients via `<NodeIP>:nodePort`. [civo](https://www.civo.com/academy/kubernetes-services/introduction-to-kubernetes-services)
- **Pattern reuse**: This pattern (namespace + two deployments + two services) is a solid interview-ready example of a small microservice app on Kubernetes.

## Runbook

### Step 1: Create namespace

```bash
kubectl create namespace iron-namespace-xfusion
kubectl get ns iron-namespace-xfusion
```

### Step 2: Deploy Iron Gallery

```bash
kubectl apply -f iron-gallery-deployment-xfusion.yaml
kubectl -n iron-namespace-xfusion get deploy,pods
kubectl -n iron-namespace-xfusion describe deploy iron-gallery-deployment-xfusion
```

Check:
- `replicas: 1`
- Labels and selectors `run=iron-gallery`
- Container name/image, limits, volumeMounts and `emptyDir` volumes.

### Step 3: Deploy Iron DB

```bash
kubectl apply -f iron-db-deployment-xfusion.yaml
kubectl -n iron-namespace-xfusion get deploy,pods
kubectl -n iron-namespace-xfusion describe deploy iron-db-deployment-xfusion
```

Check:
- `db=mariadb` labels and selectors.
- Env vars: `MYSQL_DATABASE`, `MYSQL_ROOT_PASSWORD`, `MYSQL_PASSWORD`, `MYSQL_USER`.
- VolumeMount `/var/lib/mysql` backed by `emptyDir`.

### Step 4: Create services

```bash
kubectl apply -f iron-db-service-xfusion.yaml
kubectl apply -f iron-gallery-service-xfusion.yaml
kubectl -n iron-namespace-xfusion get svc
kubectl -n iron-namespace-xfusion describe svc iron-db-service-xfusion
kubectl -n iron-namespace-xfusion describe svc iron-gallery-service-xfusion
```

Confirm:

- DB service:
  - Name `iron-db-service-xfusion`
  - Type `ClusterIP`
  - `port: 3306/TCP`, `targetPort: 3306/TCP`
  - Selector `db=mariadb`
- Gallery service:
  - Name `iron-gallery-service-xfusion`
  - Type `NodePort`
  - `port: 80/TCP`, `nodePort: 32678`
  - Selector `run=iron-gallery`.

### Step 5: Functional verification

Get node IPs:

```bash
kubectl get nodes -o wide
```

Then from the jump host:

```bash
curl http://<node-ip>:32678
# or
curl http://localhost:32678    # if jump-host is itself a node
```

Seeing the Iron Gallery UI HTML confirms the frontend is accessible and the lab requirements are met. [devrajesh.hashnode](https://devrajesh.hashnode.dev/day-63-deploy-iron-gallery-app-on-kubernetes-100-days-of-devops)
