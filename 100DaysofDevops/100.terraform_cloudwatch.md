# Terraform EC2 Instance with CloudWatch Alarm - Complete Documentation

## Overview

This Terraform configuration provisions an EC2 instance with automated CPU utilization monitoring using AWS CloudWatch. When CPU usage exceeds 90% for one consecutive 5-minute period, notifications are automatically sent via SNS topic `xfusion-sns-topic`.

## Terraform Configuration

### main.tf

```hcl
provider "aws" {
  region = "us-east-1"
}

# SNS Topic
resource "aws_sns_topic" "xfusion-sns-topic" {
  name = "xfusion-sns-topic"
}

# EC2 Instance
resource "aws_instance" "xfusion-ec2" {
  ami           = "ami-0c02fb55956c7d316"
  instance_type = "t2.micro"

  tags = {
    Name = "xfusion-ec2"
  }
}

# CloudWatch Alarm for CPU Utilization
resource "aws_cloudwatch_metric_alarm" "xfusion-alarm" {
  alarm_name          = "xfusion-alarm"
  comparison_operator = "GreaterThanOrEqualToThreshold"
  evaluation_periods  = 1
  metric_name         = "CPUUtilization"
  namespace           = "AWS/EC2"
  period              = 300
  statistic           = "Average"
  threshold           = 90
  alarm_description   = "This metric monitors ec2 cpu utilization"
  alarm_actions       = [aws_sns_topic.xfusion-sns-topic.arn]

  dimensions = {
    InstanceId = aws_instance.xfusion-ec2.id
  }
}
```

### 2. CloudWatch Alarm (`aws_cloudwatch_metric_alarm.xfusion-alarm`)

| Attribute | Value | Status |
|-----------|-------|--------|
| **Alarm Name** | `xfusion-alarm` | ✅ |
| **Metric Name** | `CPUUtilization` | ✅ |
| **Namespace** | `AWS/EC2` | ✅ |
| **Statistic** | `Average` | ✅ |
| **Threshold** | `90%` | ✅ |
| **Comparison Operator** | `GreaterThanOrEqualToThreshold` | ✅ |
| **Period** | `300 seconds` (5 minutes) | ✅ |
| **Evaluation Periods** | `1` | ✅ |
| **Alarm Actions** | SNS topic ARN | ✅ |
| **Dimensions** | InstanceId (dynamic) | ✅ |
| **Current State** | `INSUFFICIENT_DATA` → `OK` | ⏳ |

**Purpose:** Monitors EC2 CPU utilization and triggers alerts when threshold is breached, enabling proactive capacity management and automated notifications.

**Alarm Logic:**
- **Triggers when:** CPU utilization ≥ 90% for 1 consecutive period (5 minutes)
- **Resolves when:** CPU utilization < 90% for 1 consecutive period (5 minutes)
- **Notification:** Sends alert to SNS topic `xfusion-sns-topic`

**Alarm States:**
1. **OK** - CPU utilization is below 90% (normal operation)
2. **ALARM** - CPU utilization is at or above 90% for 5 minutes
3. **INSUFFICIENT_DATA** - Not enough data points (initial state or metric gaps)

## Alarm State Progression

### Timeline

| Time After Deployment | Alarm State | Description |
|----------------------|-------------|-------------|
| 0-5 minutes | `INSUFFICIENT_DATA` | No metrics collected yet |
| 5-10 minutes | `INSUFFICIENT_DATA` or `OK` | First data point arrives |
| 10-15 minutes | `OK` | Normal operation (CPU < 90%) |
| During high CPU load | `ALARM` | CPU ≥ 90% for 5 minutes |
| After load decreases | `OK` | CPU drops below 90% |

### Monitor Alarm State

```bash
# Check current state
aws cloudwatch describe-alarms \
  --alarm-names "xfusion-alarm" \
  --query "MetricAlarms[0].{StateValue:StateValue,StateReason:StateReason}" \
  --output text

# Watch state changes (run in loop)
while true; do
  echo "$(date): $(aws cloudwatch describe-alarms --alarm-names 'xfusion-alarm' --query 'MetricAlarms[0].StateValue' --output text)"
  sleep 60
done
```

## Troubleshooting

### Common Issues and Solutions

#### 1. Alarm Stays in `INSUFFICIENT_DATA`

**Cause:** Not enough metric data points collected yet

**Solution:**
- Wait 10-15 minutes for CloudWatch to collect sufficient data
- Verify EC2 instance is running
- Check if instance is generating any CPU activity

```bash
# Check metric data points
aws cloudwatch get-metric-statistics \
  --namespace AWS/EC2 \
  --metric-name CPUUtilization \
  --dimensions Name=InstanceId,Value=i-8ba0ec56abe046fd5 \
  --start-time $(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%S) \
  --end-time $(date -u +%Y-%m-%dT%H:%M:%S) \
  --period 300 \
  --statistics Average
```

#### 2. SNS Topic Not Found

**Error:** `InvalidParameter: Invalid parameter: TopicArn`

**Solution:** Verify SNS topic exists:

```bash
aws sns list-topics \
  --query "Topics[?contains(TopicArn, 'xfusion-sns-topic')]"
```

If missing, re-run `terraform apply`.

#### 3. AMI Not Available

**Error:** `InvalidAMIID.NotFound`

**Solution:** Use a different Ubuntu AMI:

```bash
aws ec2 describe-images \
  --owners 099720109477 \
  --filters "Name=name,Values=ubuntu/images/hvm-ssd/ubuntu-focal-20.04-amd64-server-*" \
  --query "sort_by(Images, &CreationDate)[-1].ImageId"
```

Update `main.tf` with the new AMI ID.

#### 4. Insufficient Permissions

**Error:** `UnauthorizedOperation` or `AccessDenied`

**Solution:** Verify IAM permissions include:
- `ec2:RunInstances`
- `ec2:CreateTags`
- `sns:CreateTopic`
- `cloudwatch:PutMetricAlarm`

## Customization Options

### Adjust CPU Threshold

Change from 90% to 80%:

```hcl
resource "aws_cloudwatch_metric_alarm" "xfusion-alarm" {
  # ... other configuration ...
  threshold = 80
}
```

### Change Evaluation Period

Require 2 consecutive periods (10 minutes total):

```hcl
resource "aws_cloudwatch_metric_alarm" "xfusion-alarm" {
  # ... other configuration ...
  evaluation_periods = 2
  period             = 300  # Still 5 minutes per period
}
```

### Use Different Statistic

Use maximum instead of average:

```hcl
resource "aws_cloudwatch_metric_alarm" "xfusion-alarm" {
  # ... other configuration ...
  statistic = "Maximum"
}
```

### Add Multiple Alarm Actions

Notify multiple SNS topics or trigger Lambda:

```hcl
resource "aws_cloudwatch_metric_alarm" "xfusion-alarm" {
  # ... other configuration ...
  alarm_actions = [
    aws_sns_topic.xfusion-sns-topic.arn,
    "arn:aws:sns:us-east-1:123456789012:another-topic",
    "arn:aws:lambda:us-east-1:123456789012:function:my-function"
  ]
}
```

### Enable Detailed Monitoring

Get 1-minute granularity instead of 5-minute:

```hcl
resource "aws_instance" "xfusion-ec2" {
  # ... other configuration ...
  monitoring = true  # Enables detailed monitoring ($0.015/hour)
}
```
