Security group in the **default VPC** with HTTP + SSH inbound. Two things to handle: reference the default VPC (via a data source) and get the `name` right — the SG's `name` attribute must be `xfusion-sg` (not just a tag). Region comes from `provider.tf`.

## main.tf content

Create `/home/bob/terraform/main.tf` (right-click Explorer → New File → `main.tf`, paste, save):

```hcl
data "aws_vpc" "default" {
  default = true
}

resource "aws_security_group" "xfusion_sg" {
  name        = "xfusion-sg"
  description = "Security group for Nautilus App Servers"
  vpc_id      = data.aws_vpc.default.id

  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "xfusion-sg"
  }
}
```

## Why each piece

**`data "aws_vpc" "default"`** — the task says "under the default VPC." A data source looks up the existing default VPC rather than creating one; `data.aws_vpc.default.id` feeds `vpc_id`. This ties the SG to the default VPC (requirement).

**`name = "xfusion-sg"`** — the SG's actual name attribute (requirement 1). Unlike a VPC (where the name is only a tag), a security group *has* a real `name` field. I also add the `Name` tag for good measure, but `name` is the one that matters here.

**`description`** — set to the exact string required (requirement 2). Note: SG description is immutable — if you typo it and re-apply, Terraform must destroy/recreate.

**Two `ingress` blocks** — HTTP (`from_port`/`to_port` = 80) and SSH (= 22), both `protocol = "tcp"`, `cidr_blocks = ["0.0.0.0/0"]`. Terraform's inline `ingress` uses port numbers, not the "type" label — HTTP *is* TCP/80, SSH *is* TCP/22. That satisfies requirements 3 and 4.

**Region** — not set in the resource; `provider.tf` already pins `us-east-1`. Don't duplicate it.

## Apply

In the terminal:

```bash
cd /home/bob/terraform
terraform init
terraform apply -auto-approve
```

Expected:


## Verify

```bash
terraform state show aws_security_group.xfusion_sg
```

Confirm `name = "xfusion-sg"`, `description = "Security group for Nautilus App Servers"`, and two ingress rules (80 and 22, both `0.0.0.0/0`).

If AWS CLI against LocalStack is available:
```bash

```

## Watch-outs

- **`description` must match exactly** — `Security group for Nautilus App Servers`. It's immutable; a typo means recreate. Copy it verbatim.
- **`name` is a real attribute here** — set `name = "xfusion-sg"` (not only a tag). This differs from the VPC task where name was tag-only.
- **`data "aws_vpc" "default"`** — if the default VPC doesn't exist in this LocalStack instance, `terraform apply` errors "no matching VPC found." LocalStack usually provisions a default VPC; if it errors, that's the cause. Fallback: omit `vpc_id` entirely — AWS/LocalStack then places the SG in the default VPC automatically:
  ```hcl
  # drop the data block and the vpc_id line if default VPC lookup fails
  ```
  But try the data-source version first; it's the correct "under the default VPC" approach.
- **`ingress` port model** — Terraform doesn't take "HTTP"/"SSH" as a type; you express them as TCP port 80 and TCP port 22. The `description` fields label them for clarity.
- **One file only** — everything in `main.tf`; leave `provider.tf` as-is.
