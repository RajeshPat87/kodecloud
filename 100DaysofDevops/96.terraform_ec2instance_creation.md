EC2 instance plus a new RSA key pair. The tricky part is requirement 4: "create a new RSA key" — you generate the key with Terraform's `tls_private_key`, register it as an AWS key pair with `aws_key_pair`, and attach it to the instance. Default security group is looked up via a data source. Everything in `main.tf`; region comes from `provider.tf`.

## main.tf content

Create `/home/bob/terraform/main.tf` (Explorer → New File → `main.tf`, paste, save):

```hcl
# Generate a new RSA key
resource "tls_private_key" "datacenter_key" {
  algorithm = "RSA"
  rsa_bits  = 4096
}

# Register it as an AWS key pair named datacenter-kp
resource "aws_key_pair" "datacenter_kp" {
  key_name   = "datacenter-kp"
  public_key = tls_private_key.datacenter_key.public_key_openssh
}

# Look up the default security group
data "aws_vpc" "default" {
  default = true
}

data "aws_security_group" "default" {
  vpc_id = data.aws_vpc.default.id
  name   = "default"
}

# EC2 instance
resource "aws_instance" "datacenter_ec2" {
  ami                    = "ami-0c101f26f147fa7fd"
  instance_type          = "t2.micro"
  key_name               = aws_key_pair.datacenter_kp.key_name
  vpc_security_group_ids = [data.aws_security_group.default.id]

  tags = {
    Name = "datacenter-ec2"
  }
}
```

## Why each piece

**`tls_private_key` + `aws_key_pair`** — requirement 4 says "create a new RSA key." Terraform's `tls_private_key` generates the RSA pair; `aws_key_pair` uploads its public key to AWS under the name `datacenter-kp`. This is the standard Terraform pattern for creating (not just referencing) a key. `key_name = "datacenter-kp"` is the required name.

**`ami = "ami-0c101f26f147fa7fd"`** — the exact AMI ID given (requirement 2). `instance_type = "t2.micro"` (requirement 3).

**`tags = { Name = "datacenter-ec2" }`** — the instance's Name tag (requirement 1), which is what shows as the instance name in AWS.

**`data "aws_security_group" "default"`** — requirement 5 ("attach the default security group"). Looks up the SG named `default` in the default VPC and attaches its ID via `vpc_security_group_ids`.

**`key_name = aws_key_pair.datacenter_kp.key_name`** — links the generated key to the instance.

**Region** — from `provider.tf` (`us-east-1`); not repeated.

## Apply

```bash
cd /home/bob/terraform
terraform init
terraform apply -auto-approve
```

`init` pulls both the `aws` and `tls` providers (tls is needed for the RSA key). Expected:

## Verify

```bash
terraform state show aws_instance.datacenter_ec2
terraform state show aws_key_pair.datacenter_kp
```

Confirm the instance shows `ami = ami-0c101f26f147fa7fd`, `instance_type = t2.micro`, `key_name = datacenter-kp`, the default SG in `vpc_security_group_ids`, and `tags = { Name = "datacenter-ec2" }`.

## Watch-outs

- **`tls` provider auto-installs** — `tls_private_key` comes from the `hashicorp/tls` provider. `terraform init` fetches it automatically; if the lab blocks the registry, init could fail on it — but LocalStack labs normally allow it. If it can't, an alternative is `aws_key_pair` with a `public_key` you paste, but the `tls_private_key` approach satisfies "create a new RSA key" cleanly.
- **Default SG lookup** — if `data.aws_security_group.default` errors "no matching SG," the default VPC/SG isn't present in this LocalStack instance. Fallback: attach by leaving `vpc_security_group_ids` off (AWS uses the default SG automatically) — but the explicit data-source attach is the correct expression of requirement 5.
- **AMI region** — the given AMI ID is valid for this lab's `us-east-1` LocalStack; don't substitute another.
- **Requirement 4 is "create," not "use existing"** — so generating the key with `tls_private_key` is right; just referencing a pre-existing key would miss it.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
