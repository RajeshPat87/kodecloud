## 1. Purpose

Deploy the static `web_app` site from Gitea to Apache's document root on App Server 1
using a Jenkins pipeline. Content must serve at the load-balancer **root** URL
(`https://<LBR-URL>/`) with no `/web_app` subdirectory.

The document root **is** the git clone, so deployment = `git pull` in place. No copy step,
no subdirectory — that is what keeps the content at `/`.

## 5. One-time script (OTS) — run once on `stapp01`

Connect: `ssh sarah@stapp01` (confirm prompt reads `sarah@stapp01`).
Run block-by-block. `sudo` password = `Sarah_pass123`.

```bash
#!/usr/bin/env bash
# stapp01 — Jenkins SSH-agent prerequisites. Run once as sarah (uses sudo).

# --- Java 17 (required by recent Jenkins LTS agents) ---
sudo yum install -y java-17-openjdk java-17-openjdk-devel
JAVA17=$(ls -d /usr/lib/jvm/java-17-openjdk*/bin/java | head -1)
echo "JavaPath -> $JAVA17"      # paste into node config
"$JAVA17" -version

# --- Agent remote root (separate from repo, sarah-owned) ---
sudo install -d -o sarah -g sarah -m 0755 /home/sarah/jenkins_agent

# --- Doc-root ownership + git safe.directory ---
sudo chown -R sarah:sarah /var/www/html
sudo git config --system --add safe.directory /var/www/html

# --- Confirm branch + that remote carries credentials ---
git -C /var/www/html branch -a          # expect: master
git -C /var/www/html remote -v          # expect: http://sarah:...@gitea:3000/sarah/web_app.git
```

**Fallback if `sarah` is not a sudoer:**
```bash
exit
ssh tony@stapp01            # password Ir0nM@n

yum install -y java-17-openjdk java-17-openjdk-devel
```

### 6.3 Job
New Item → `devops-webapp-job` → **Pipeline** (NOT Multibranch) → OK
Pipeline → Definition **Pipeline script**:

```groovy
pipeline {
    agent { label 'stapp01' }
    stages {
        stage('Deploy') {
            steps {
                sh '''
                    cd /var/www/html
                    git config --global --add safe.directory /var/www/html
                    git checkout master
                    git pull origin master
                '''
            }
        }
    }
}
```

- **Use Groovy Sandbox:** leave default — no effect for admin with this script.
- Keep `Deploy` exactly (case-sensitive).
- Save → **Build Now**.

**Rerun-proof variant** (optional — guarantees doc root matches remote every build):
```groovy
sh '''
    cd /var/www/html
    git config --global --add safe.directory /var/www/html
    git fetch origin
    git reset --hard origin/master
'''
```

## 7. Rollback

Deploy is a fast-forward pull, so rollback = check out the prior commit and let the
next scheduled pull re-align, or hard-reset to a known-good SHA:

```bash
# on stapp01, as sarah
git -C /var/www/html log --oneline -5              # find last-good SHA
git -C /var/www/html reset --hard <good_sha>       # revert doc root
```
No service restart needed — Apache serves files directly.

## 9. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Node stays offline, log shows Java version error | Agent JVM wrong | Set JavaPath to `/usr/lib/jvm/java-17-openjdk/bin/java`, relaunch |
| No "Launch agents via SSH" option | `ssh-slaves` plugin missing | Install plugin, restart, refresh, redo node |
| `git pull` prompts for auth | Remote lacks creds | `git remote set-url origin http://sarah:Sarah_pass123@gitea:3000/sarah/web_app.git` |
| `fatal: dubious ownership` | Doc root not sarah-owned | `safe.directory` lines (section 5 + pipeline) |
| `local changes would be overwritten` on rerun | Uncommitted edits in doc root | Use hard-sync variant (section 6.3) |
| `pathspec 'master' did not match` | Branch is `main` | Replace `master` → `main` in pipeline |
| UI hangs after plugin install | Controller restarting | Refresh page after ~30–60s |
