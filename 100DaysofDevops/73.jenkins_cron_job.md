## 2. Parameterized Job: `parameterized-job`

### Objective

Test basic Jenkins parameterized build functionality:

- String parameter: `Stage` (default `Build`)
- Choice parameter: `env` (choices: `Development`, `Staging`, `Production`)
- Job echoes the parameter values and runs successfully at least once with `env=Production`.

### Configuration Steps

1. **Login to Jenkins**

   - Click **Jenkins** in top bar.
   - Log in as `admin / Adm!n321`.

2. **Create job**

   - On the dashboard, click **New Item**.
   - Name: `parameterized-job`.
   - Type: **Freestyle project**.
   - Click **OK**.

3. **Add parameters**

   - In **Configure → General**:
     - Check **This project is parameterized**.
     - **Add Parameter → String Parameter**:
       - Name: `Stage`
       - Default Value: `Build`
       - Description: `Pipeline stage name (default: Build)`.
     - **Add Parameter → Choice Parameter**:
       - Name: `env`
       - Choices (one per line):

         ```text
         Development
         Staging
         Production
         ```

       - Description: `Target environment (Development, Staging, Production)`.

4. **Build step**

   - Scroll to **Build Steps**.
   - Click **Add build step → Execute shell**.
   - Script:

     ```bash
     #!/bin/bash

     echo "Stage parameter value: $Stage"
     echo "env parameter value: $env"
     ```

   - Click **Save**.

### Usage and Verification

1. **Run with env=Production**

   - Open `parameterized-job`.
   - Click **Build with Parameters**.
   - Leave `Stage=Build` or change if desired.
   - Set `env=Production`.
   - Click **Build**.

2. **Check output**

   - Open build `#1` → **Console Output**.
   - Expect:

     ```text
     Stage parameter value: Build
     env parameter value: Production
     Finished: SUCCESS
     ```

3. **Documentation**

   - Screenshots:
     - General configuration showing parameters.
     - Build step with shell echoing `$Stage` and `$env`.
     - Console output showing values and SUCCESS.

- Jenkins jobs run non‑interactively; they cannot type passwords.
- To let Jenkins do `ssh`/`scp` automatically, we need **key-based SSH** from `jenkins@jenkins` to:
  - `tony@stapp01`
  - `natasha@ststor01`

### Steps

From the **jump host**:

```bash

# password: j@rv!s
```

On Jenkins server, accept host keys and verify password logins:

```bash

ssh natasha@ststor01
```

## 5. Jenkins Job: `copy-logs`

### Creation and Configuration

1. **Create job**

   - In Jenkins UI:
     - Click **New Item**.
     - Name: `copy-logs`.
     - Type: **Freestyle project**.
     - Click **OK**.

2. **Build trigger: every 2 minutes**

   - In **Configure → Build Triggers**:
     - Enable **Build periodically**.
     - Cron schedule:

       ```text
       H/2 * * * *   # Jenkins best practice for ~every 2 minutes
       ```

3. **Build step: Execute shell**

   - In **Build Steps → Add build step → Execute shell**.
   - Script:

     ```bash
     #!/bin/bash
     set -e

     APP_SERVER="stapp01"
     APP_USER="tony"

     STORAGE_SERVER="ststor01"
     STORAGE_USER="natasha"

     APP_LOG_DIR="/var/log/httpd"
     DEST_DIR="/usr/src/itadmin"

     echo "Copying Apache logs from ${APP_USER}@${APP_SERVER} to ${STORAGE_USER}@${STORAGE_SERVER}..."

     # Copy logs from app server to Jenkins server (using key-based SSH)
     ssh ${APP_USER}@${APP_SERVER} "sudo cat ${APP_LOG_DIR}/access_log" > /tmp/access_log
     ssh ${APP_USER}@${APP_SERVER} "sudo cat ${APP_LOG_DIR}/error_log"  > /tmp/error_log

     # Ensure destination exists on storage server
     ssh ${STORAGE_USER}@${STORAGE_SERVER} "mkdir -p ${DEST_DIR}"

     # Copy logs from Jenkins to storage server
     scp /tmp/access_log ${STORAGE_USER}@${STORAGE_SERVER}:${DEST_DIR}/access_log
     scp /tmp/error_log  ${STORAGE_USER}@${STORAGE_SERVER}:${DEST_DIR}/error_log

     echo "Apache logs copied to ${STORAGE_SERVER}:${DEST_DIR}"
     ```

   - Click **Save**.

### Execution and Verification

1. **Manual build (required at least once)**

   - Open `copy-logs`.
   - Click **Build Now**.
   - Check **Console Output**:

     ```text
     Copying Apache logs from tony@stapp01 to natasha@ststor01...
     Apache logs copied to ststor01:/usr/src/itadmin
     Finished: SUCCESS
     ```

2. **Verify on storage server**

   - From jump host or Jenkins server:

     ```bash
     ssh natasha@ststor01
     ls -l /usr/src/itadmin
     ```

   - Expect `access_log` and `error_log` present.

3. **Periodic runs**

   - With `H/2 * * * *`, Jenkins will run the job roughly every 2 minutes.
   - Subsequent runs refresh the logs, and should continue to show **SUCCESS**.

### Notes/Examples from the task

- Example cron in note (`*/10 * * * *`) is just to demonstrate cron syntax; your required schedule is every 2 minutes (`H/2 * * * *` or `*/2 * * * *`).
- If plugins are needed:
  - Use **Manage Jenkins → Manage Plugins**, then select **Restart Jenkins when installation is complete and no jobs are running**.
  - Refresh UI after restart if needed.

## 6. Why manual worked but automation initially failed

- Manual SSH:

  - Host key prompt → you answered `yes`.
  - Password prompt → you typed `Ir0nM@n` or `Bl@kW`.
  - Result: success.

- Jenkins job SSH:

  - No interactive TTY → cannot type password.
  - Tries `publickey` → failed until we added Jenkins public key to `authorized_keys`.
  - Falls back to password → fails, as Jenkins cannot provide password.

Once we:

- Exported `/var/lib/jenkins/.ssh/id_rsa.pub`.
- Appended it correctly to `~tony/.ssh/authorized_keys` and `~natasha/.ssh/authorized_keys`.
- Set permissions (`~/.ssh` 700, `authorized_keys` 600).
- Verified `ssh -o BatchMode=yes user@host 'echo OK'`,

then Jenkins job SSH succeeded and automation worked.

## 7. Key takeaways for future tasks

1. **Always separate manual vs automated SSH**
   - Manual works with passwords and prompts.
   - Jenkins jobs must be non‑interactive; use keys.

2. **SSH automation checklist**
   - From Jenkins server:
     - Accept host keys (first `ssh` with `yes`).
     - Generate `id_rsa` / `id_rsa.pub` for Jenkins user.
     - Install public key into `authorized_keys` for target users.
     - Verify with `ssh -o BatchMode=yes user@host 'echo OK'`.

3. **Only after key-based SSH works, configure Jenkins jobs**
   - Use `ssh` and `scp` in job’s shell.
   - Configure cron (`H/2 * * * *`, `*/2 * * * *`, etc.).
   - Run once, check console output, verify target files.
