Good — `provider.tf` is already in `/home/bob/terraform/`, the same directory where `main.tf` goes. That's exactly right; Terraform loads all `.tf` files in the working directory together, so your `main.tf` resource will use the provider config from `provider.tf` automatically. Nothing to move or change.

## Create main.tf in the same dir

```bash
cd /home/bob/terraform

cat > main.tf <<'EOF'
resource "aws_vpc" "nautilus_vpc" {
  cidr_block = "10.0.0.0/16"

  tags = {
    Name = "nautilus-vpc"
  }
}
EOF

ls -l          # confirm main.tf and provider.tf sit together
cat main.tf
```

You should see both files:
```
provider.tf
main.tf
README.md
```

## Apply

```bash
terraform init
terraform apply -auto-approve
```

`init` picks up the provider from `provider.tf`; `apply` creates the VPC against LocalStack (`http://aws:4566`).

Expected:
```
aws_vpc.nautilus_vpc: Creation complete after 1s [id=vpc-...]
Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

## Verify

```bash
terraform state show aws_vpc.nautilus_vpc
```

Confirm it shows `cidr_block = "10.0.0.0/16"` and `tags = { "Name" = "nautilus-vpc" }`.

That's the whole task: `main.tf` alongside the existing `provider.tf`, one `aws_vpc` resource with the `Name = "nautilus-vpc"` tag and any valid CIDR. Region comes from the provider, so it's not repeated in the resource. Run `init` → `apply` → `state show` and you're done.
