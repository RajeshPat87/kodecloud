# Runbook — Conditional Branch Deploy of `web_app` via Jenkins Pipeline

**Job:** `datacenter-webapp-job`  ·  **Target:** App Server 1 (`stapp01`)  ·  **Doc root:** `/var/www/html`
**Key feature:** `BRANCH` string parameter → conditional deploy of `master` or `feature`
**Owner:** DevOps team

---

## 1. Purpose

Deploy the static `web_app` site from Gitea to Apache's document root on App Server 1
using a **parameterized** Jenkins pipeline. A `BRANCH` string parameter decides which
branch is deployed: `master` → master branch, `feature` → feature branch. Content must
serve at the load-balancer **root** URL (`https://<LBR-URL>/`) with no `/web_app` subpath.

The document root **is** the git clone, so deployment = `git checkout <branch>` +
`git pull` in place. No copy step, no subdirectory — that is what keeps content at `/`.

## 4. Plugin bootstrap (bare controller)

A freshly provisioned controller may ship with only ~4 base plugins. The task plugins
must be installed **with their dependency tree**, or they fail to load.

### 4.1 Check current state (Jenkins host)
```bash
JENKINS_URL=http://localhost:8080
curl -sO "$JENKINS_URL/jnlpJars/jenkins-cli.jar"
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' list-plugins | wc -l
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' list-plugins \
  | grep -iE 'ssh-slaves|workflow|git|credential'
```
A count near 4 with no matches = bare controller; install below.

### 4.2 Install WITH dependencies — two valid methods

**Method A — UI (most reliable, auto-resolves the whole tree):**
Manage Jenkins → **Plugins** → **Available plugins** → search and tick
**SSH Build Agents**, **Git**, **Pipeline**, **Credentials Binding** → **Install** →
tick **Restart Jenkins when installation is complete and no jobs are running** →
refresh UI after ~60s.

**Method B — CLI by NAME (resolves dependencies from the catalog):**
```bash
# prime the update-center catalog first (bare controllers haven't fetched it)
curl -s -u admin:'Adm!n321' -X POST "$JENKINS_URL/pluginManager/checkUpdatesServer"
sleep 25
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' \
  install-plugin ssh-slaves git workflow-aggregator credentials-binding -restart
```

> **Do NOT install by `.hpi` URL** (`install-plugin https://.../git.hpi`). That method
> installs only the named file and skips all dependencies, producing
> "Plugin is missing: structs / credentials / workflow-cps / ..." load errors.
> Name-based install (Method B) and the UI (Method A) both resolve the dependency graph;
> URL-based install does not.

### 4.3 Verify clean load
```bash
sleep 90
curl -s -o /dev/null -w "%{http_code}\n" -u admin:'Adm!n321' "$JENKINS_URL/login"   # expect 200
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' list-plugins | wc -l  # expect 70+
```
Confirm no red load-error banner under Manage Jenkins, and that
**Launch agents via SSH** now appears in the node launch dropdown.

## 6. One-time script (OTS) — run once on `stapp01`

Connect: `ssh sarah@stapp01` (confirm prompt reads `sarah@stapp01`).
Run block-by-block; `sudo` password = `Sarah_pass123`.

```bash
#!/usr/bin/env bash
# stapp01 — Jenkins SSH-agent prerequisites for conditional branch deploy.

# --- Java 17 (required by recent Jenkins LTS agents) ---
sudo yum install -y java-17-openjdk java-17-openjdk-devel
JAVA17=$(ls -d /usr/lib/jvm/java-17-openjdk*/bin/java | head -1)
echo "JavaPath -> $JAVA17"      # paste into node config
"$JAVA17" -version

# --- Agent remote root (separate from repo, sarah-owned) ---
sudo install -d -o sarah -g sarah -m 0755 /home/sarah/jenkins_agent

# --- Doc-root ownership + git safe.directory ---
sudo chown -R sarah:sarah /var/www/html
sudo git config --system --add safe.directory /var/www/html

# --- CRITICAL: both branches must exist on origin ---
git -C /var/www/html fetch origin
git -C /var/www/html branch -a          # expect origin/master AND origin/feature
git -C /var/www/html remote -v          # expect http://sarah:...@gitea:3000/sarah/web_app.git
```

**If `feature` is missing on origin:** create it in the Gitea UI
(login `sarah` → repo `web_app` → branch dropdown → New Branch from `master`),
then re-run `git -C /var/www/html fetch origin`.

**Fallback if `sarah` is not a sudoer:** `ssh tony@stapp01` (pass `Ir0nM@n`) → `sudo -i`
→ run the install/chown/config lines as root, then
`su - sarah -c 'git -C /var/www/html fetch origin && git -C /var/www/html branch -a'`.

### 7.3 Job
New Item → `datacenter-webapp-job` → **Pipeline** (NOT Multibranch) → OK
Pipeline → Definition **Pipeline script**:

```groovy
pipeline {
    agent { label 'stapp01' }
    parameters {
        string(name: 'BRANCH', defaultValue: 'master', description: 'Branch to deploy: master or feature')
    }
    stages {
        stage('Deploy') {
            steps {
                script {
                    if (params.BRANCH == 'master') {
                        sh '''
                            cd /var/www/html
                            git config --global --add safe.directory /var/www/html
                            git checkout master
                            git pull origin master
                        '''
                    } else if (params.BRANCH == 'feature') {
                        sh '''
                            cd /var/www/html
                            git config --global --add safe.directory /var/www/html
                            git checkout feature
                            git pull origin feature
                        '''
                    } else {
                        error "Unknown BRANCH value: ${params.BRANCH} (expected 'master' or 'feature')"
                    }
                }
            }
        }
    }
}
```

- Single stage `Deploy` (case-sensitive); `if/else` provides the required conditional.
- The `parameters {}` block registers `BRANCH` on first run — no need to tick
  "This project is parameterized" manually.
- Save.

**Rerun-proof variant** (idempotent — guarantees doc root matches remote every run):
```groovy
sh '''
    cd /var/www/html
    git config --global --add safe.directory /var/www/html
    git fetch origin
    git checkout master           # or feature
    git reset --hard origin/master   # or origin/feature
'''
```

Always use **Build with Parameters** to exercise the conditional — the plain build only
uses the default.

## 10. Rollback

Deploy is a branch checkout + pull, so rollback = reset the doc root to a known-good SHA:
```bash
git -C /var/www/html log --oneline -5
git -C /var/www/html reset --hard <good_sha>
```
No service restart needed — Apache serves files directly.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Plugins show "Plugin is missing: ..." after restart | Installed by `.hpi` URL (no deps) | Reinstall via UI Available plugins or CLI by-name (section 4.2) |
| `install-plugin <name>` → "no update center data" | Catalog not fetched on bare controller | `POST /pluginManager/checkUpdatesServer`, then retry by-name |
| Node stays offline, log shows Java version error | Agent JVM wrong | Set JavaPath to `/usr/lib/jvm/java-17-openjdk/bin/java`, relaunch |
| No "Launch agents via SSH" option | `ssh-slaves` not loaded | Complete plugin bootstrap (section 4) |
| `pathspec 'feature' did not match` | `feature` branch absent on origin | Create it in Gitea, `git fetch origin`, rebuild |
| Grader passes `feature` but sees master content | Ran plain build, not with parameters | Use **Build with Parameters** |
| `git pull` prompts for auth | Remote lacks creds | `git remote set-url origin http://sarah:Sarah_pass123@gitea:3000/sarah/web_app.git` |
| `local changes would be overwritten` on rerun | Uncommitted edits in doc root | Use rerun-proof variant (section 7.3) |
| `fatal: dubious ownership` | Doc root not sarah-owned | `safe.directory` lines (sections 6 + pipeline) |
| UI hangs after plugin install | Controller restarting | Refresh page after ~60s |
