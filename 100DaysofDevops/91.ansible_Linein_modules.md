## OTS — run on jump host as thor

```bash
#!/usr/bin/env bash
# jump host — httpd + sample index.html (copy + lineinfile at top) on all app servers
set -e

cd /home/thor/ansible

[ -f ansible.cfg ] || cat > ansible.cfg <<'EOF'
[defaults]
host_key_checking = False
inventory = inventory
EOF

cat > playbook.yml <<'EOF'
---
- name: Install httpd and deploy sample page on all app servers
  hosts: all
  become: true
  tasks:
    - name: Install httpd
      ansible.builtin.yum:
        name: httpd
        state: present

    - name: Start and enable httpd
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true

    - name: Create index.html with base content
      ansible.builtin.copy:
        dest: /var/www/html/index.html
        content: "This is a Nautilus sample file, created using Ansible!\n"

    - name: Add welcome line at the top using lineinfile
      ansible.builtin.lineinfile:
        path: /var/www/html/index.html
        line: "Welcome to Nautilus Group!"
        insertbefore: BOF

    - name: Set owner, group and permissions on index.html
      ansible.builtin.file:
        path: /var/www/html/index.html
        owner: apache
        group: apache
        mode: '0744'
EOF

echo "== playbook.yml =="; cat playbook.yml
```

## Why each piece

**Task 1 `yum` + Task 2 `service`** — install httpd, `state: started` + `enabled: true` = "up and running" (requirement 1).

**Task 3 `copy` with `content:`** — writes the base line (requirement 2). Using `copy` with inline `content` creates the file with exactly that text. The `\n` gives it a clean trailing newline so the prepended line sits on its own line.

**Task 4 `lineinfile` with `insertbefore: BOF`** — this is the key requirement-3 detail: `insertbefore: BOF` ("beginning of file") puts `Welcome to Nautilus Group!` at the **top**. Without it, lineinfile appends to the end. Result order:
```
Welcome to Nautilus Group!
This is a Nautilus sample file, created using Ansible!
```

**Task order is deliberate** — copy must run **before** lineinfile, or there's no file to prepend into. copy first (base content), then lineinfile (top line), then file (perms last so nothing overrides them).

**Task 5 `file`** — `owner: apache`, `group: apache` (requirement 4) and `mode: '0744'` (requirement 5). Quoted mode. Kept last so the final ownership/perms are authoritative.

## Watch-outs

- **`insertbefore: BOF`** is what satisfies "added at the top." Don't use `insertafter` or omit it — lineinfile defaults to appending at the end, which fails requirement 3.
- **copy before lineinfile** — reversed order means lineinfile creates the file with only the welcome line and copy then *overwrites* it, losing the top-line placement. Keep the order as written.
- **`mode: '0744'` quoted** — `-rwxr--r--` = owner rwx, group r, other r. Enter exactly.
- **Idempotency** — on reruns, `copy` may re-assert base content and `lineinfile` won't duplicate the top line (it matches the existing line). But note: if `copy` rewrites the file on every run it would strip the lineinfile line, then lineinfile re-adds it — net result identical each run, so validation passes on repeat. The order guarantees the final state is always correct.
- **`become: true`** required for all tasks.
- **owner `apache` exists** — created by installing httpd (Task 1 before Task 5), so keep order.
- **Existing inventory** — don't recreate; add `ansible.cfg` only if pings fail on host keys.
- File exact: playbook `/home/thor/ansible/playbook.yml`.
