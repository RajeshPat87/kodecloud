# Runbook — Auto-Deploy `web` on Push via Jenkins (Poll SCM)

**Job:** `nautilus-app-deployment` · **Type:** Freestyle · **Target:** App Server 1 (`stapp01`)
**Trigger:** Poll SCM (auto-build on push to `master`) · **Deploy dir:** `/var/www/html`
**Status:** Verified / passing

## 1. Purpose

Auto-deploy the `web` repo to Apache's document root on App Server 1 whenever a developer
pushes to `master`. Repo lives in sarah's home (`/home/sarah/web`); the job clones it on
the agent and copies the **entire repo content** into `/var/www/html`, so the site serves
at the load-balancer **root** (no `/web` subpath). All deploy steps run via `sudo`.

## 4. Plugin bootstrap (bare controller)

Check state on the Jenkins host:
```bash
JENKINS_URL=http://localhost:8080
curl -sO "$JENKINS_URL/jnlpJars/jenkins-cli.jar"
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' list-plugins | wc -l
```

If near 4, install with dependencies. **UI method (reliable, resolves the tree):**
Manage Jenkins → Plugins → Available plugins → tick **SSH Build Agents**, **Git**,
**Pipeline**, **Credentials Binding**, **Gitea** → Install → tick *Restart Jenkins when
installation is complete and no jobs are running* → refresh after ~60s.

**CLI-by-name method (also resolves deps; prime catalog first):**
```bash
curl -s -u admin:'Adm!n321' -X POST "$JENKINS_URL/pluginManager/checkUpdatesServer"
sleep 25
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' \
  install-plugin ssh-slaves git workflow-aggregator credentials-binding gitea -restart
sleep 90
java -jar jenkins-cli.jar -s "$JENKINS_URL" -auth admin:'Adm!n321' list-plugins | wc -l   # 70+
```

> Never install by `.hpi` URL — it skips dependencies and causes "Plugin is missing" load

### 6.3 Job
New Item → `nautilus-app-deployment` → **Freestyle project** → OK

- **Restrict where this project can be run** → Label: `stapp01`
- **Source Code Management → Git**
  - Repository URL: `http://gitea:3000/sarah/web.git`
  - Credentials: `sarah-cred`
  - Branch Specifier: `*/master`
  - Repository browser: (Auto)
- **Build Triggers** → tick **Poll SCM** → schedule:
  ```
  * * * * *
  ```
- **Build Steps → Execute shell:**
  ```bash
  sudo cp -r "$WORKSPACE"/. /var/www/html/
  sudo rm -rf /var/www/html/.git
  sudo chown -R sarah:sarah /var/www/html
  sudo systemctl restart httpd
  ```
- Save.

> `"$WORKSPACE"/.` (trailing `/.`) copies repo **contents** into the doc root — whole repo,
> no `/web` subfolder, served at `/`. The block is idempotent (Note 2): `cp` overwrites,
> `rm -rf .git` is safe if absent, `chown`/`restart` re-run cleanly.

> **Poll SCM vs Gitea webhook:** Poll SCM satisfies the "auto-deploy on push" requirement
> with no webhook and is the reliable path in-lab. If the **Gitea** push-trigger checkbox is
> preferred (instant), it only appears once a Gitea Git SCM is saved and the page is hard-
> refreshed; then add a Gitea webhook → `http://jenkins:8080/gitea-webhook/post`. Optional.

## 9. Rollback

```bash
git -C /home/sarah/web log --oneline -5
git -C /home/sarah/web reset --hard <good_sha>
git -C /home/sarah/web push -f origin master   # re-triggers deploy of the good state
```
Or reset the doc root directly: `sudo git`-independent — re-run the job after fixing the repo.

## 10. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| "Plugin is missing: ..." after restart | installed by `.hpi` URL | reinstall via UI/CLI-by-name (section 4) |
| Node offline, Java error in log | wrong agent JVM | set JavaPath to `/usr/lib/jvm/java-17-openjdk/bin/java` |
| No "Build when a change is pushed to Gitea" checkbox | SCM not saved as Gitea / page stale | save Git SCM, hard-refresh; or use Poll SCM |
| `sudo: a password is required` in build | NOPASSWD sudoers missing | recreate `/etc/sudoers.d/sarah` (section 5) |
| `/web` subdirectory appears | copied folder not contents | keep `/.` in `cp -r "$WORKSPACE"/.` |
| index.html owned by root | chown didn't run/recurse | ensure `sudo chown -R sarah:sarah /var/www/html` after cp |
| Git SCM "Failed to connect" | wrong host | use internal `gitea:3000` (confirm via `remote -v`) |
| Build didn't auto-trigger | Poll SCM schedule wrong | set `* * * * *`; wait up to 60s after push |
| Second build fails | non-idempotent step | steps here are idempotent by design |
