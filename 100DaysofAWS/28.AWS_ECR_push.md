## Concept

**Amazon ECR** is a managed private Docker registry (AWS's equivalent of Docker Hub, but private to your account). The workflow to push an image:

1. **Create** the ECR repo (`datacenter-ecr`).
2. **Authenticate** Docker to ECR — you can't `docker push` to ECR without logging in first, using a temporary token from `aws ecr get-login-password`.
3. **Build** the image from the Dockerfile.
4. **Tag** the image with the **full ECR URI** (`<account>.dkr.ecr.<region>.amazonaws.com/datacenter-ecr:latest`) — Docker pushes based on the tag's registry prefix, so the tag *is* the destination.
5. **Push** it.

Key facts:
- The ECR repo URI format is **`<account-id>.dkr.ecr.<region>.amazonaws.com/<repo-name>`**.
- The auth token from `get-login-password` is **valid 12 hours** and is piped into `docker login`.
- The image must be tagged with the registry URI **before** push — a plain `myimage:latest` won't go to ECR.

## Prerequisites

- `showcreds` first — CLI + Docker needed; requires working `AKIA`/secret.
- Region **us-east-1**.
- Docker installed/running on aws-client (`docker ps` works).
- Dockerfile at `/root/pyapp/Dockerfile`.

## OTS (CLI, on aws-client)

```bash
REGION=us-east-1
REPO=datacenter-ecr

# 0. Account ID (for the registry URI)
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
ECR_URI="${ACCOUNT_ID}.dkr.ecr.${REGION}.amazonaws.com/${REPO}"
echo "ECR URI: $ECR_URI"

# 1. Create the private ECR repository
aws ecr create-repository --repository-name $REPO --region $REGION

# 2. Authenticate Docker to ECR (token valid 12h)
aws ecr get-login-password --region $REGION \
  | docker login --username AWS --password-stdin "${ACCOUNT_ID}.dkr.ecr.${REGION}.amazonaws.com"

# 3. Build the image from the Dockerfile, tagged with the ECR URI directly
docker build -t ${ECR_URI}:latest /root/pyapp

# 4. Push to ECR
docker push ${ECR_URI}:latest
```

**Verify:**
```bash
# Image now listed in the repo with tag 'latest'
aws ecr describe-images --repository-name $REPO --region us-east-1 \
  --query 'imageDetails[].imageTags' --output text

# And the repo exists
aws ecr describe-repositories --repository-names $REPO --region us-east-1 \
  --query 'repositories[0].repositoryUri' --output text
```
Expect `latest` in the image tags and the repo URI printed.

## Runbook (step-by-step)

1. `showcreds` → confirm CLI works (`aws sts get-caller-identity`).
2. `aws ecr create-repository --repository-name datacenter-ecr --region us-east-1`.
3. Log Docker into ECR with the `get-login-password | docker login` pipe.
4. `cd /root/pyapp` (or pass the path) → `docker build -t <ECR_URI>:latest .`.
5. `docker push <ECR_URI>:latest`.
6. Verify with `aws ecr describe-images`.

---

### Gotchas
- **Must `docker login` to ECR first** — skipping it gives `no basic auth credentials` on push. The `get-login-password | docker login --password-stdin` one-liner handles it securely (no token on disk).
- **Tag with the full ECR URI** — `docker push` routes by the tag's registry prefix. Tagging as just `datacenter-ecr:latest` (no account/region) pushes nowhere useful. Build directly with `-t ${ECR_URI}:latest` or `docker tag` afterward.
- **Login endpoint vs image URI** — you log in to `<account>.dkr.ecr.<region>.amazonaws.com` (registry), but tag/push to `<account>.dkr.ecr.<region>.amazonaws.com/<repo>` (registry + repo). Note the difference.
- **Repo must exist before push** — ECR won't auto-create it (unlike some registries).
- **Build context** — `docker build ... /root/pyapp` uses that dir as context; ensure the Dockerfile and its referenced files are there.
- **Private by default** — `create-repository` makes a private repo; no extra step needed (task wants private).
- Region **us-east-1**; repo name `datacenter-ecr`; tag `latest`.
