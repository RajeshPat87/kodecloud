# Runbook: Create an EC2 Key Pair (RSA) — AWS

**Task family:** Nautilus / KodeKloud AWS migration labs
**Example deliverable:** key pair named `nautilus-kp`, type `rsa`, region `us-east-1`
**Author context:** aws-client lab host, time-boxed session credentials

---

## 1. Concept

An **EC2 key pair** is an asymmetric credential (public + private key) used to
authenticate SSH access to Linux EC2 instances.

- AWS stores the **public key**; you receive the **private key exactly once** at
  creation time. It is never retrievable again — capture it immediately.
- **Key types:** `rsa` (2048-bit, broad compatibility) or `ed25519` (newer,
  smaller, faster). This task requires `rsa`.
- **Private key formats:** `pem` (OpenSSH — Linux/macOS/`ssh`) or `ppk` (PuTTY —
  Windows). Format is independent of type. `pem` is the default and correct here.
- A key pair is **regional** — one created in `us-east-1` does not appear in any
  other region. Grader checks the exact region, so pin it.

---

## 2. Prerequisites

- SSH/terminal access to the **aws-client** host (AWS CLI v2 pre-installed).
- Lab credentials, retrieved with `showcreds`.
- Target region: **us-east-1** (from the console URL `...?region=us-east-1`).
- Awareness that session credentials are **time-boxed** (~1 hour) — finish inside
  the window and run the checker before expiry.

---

## 3. Decide the path FIRST (critical)

Run `showcreds` and read the output before touching `aws configure`:

```bash
showcreds
```

| showcreds output contains...              | Path to use            |
|-------------------------------------------|------------------------|
| `aws_access_key_id = AKIA...` + a secret  | **CLI** (Section 4)    |
| Only Console URL / Username / Password    | **Console** (Section 5)|

> **Key insight:** If `showcreds` returns only a console URL + username +
> password (no `AKIA` key), it is a **console-only lab**. The AWS CLI cannot
> authenticate with a username/password or a console URL — it signs requests with
> an access key ID + secret (SigV4). Attempting `aws configure` with the console
> username/password produces `InvalidClientTokenId`. Do not loop on it.
>
> Minting your own key via `IAM → Create access key` only works if the user has
> `iam:CreateAccessKey`. These labs frequently deny that action
> (`AccessDenied ... not authorized to perform: iam:CreateAccessKey`), which
> closes the CLI route entirely. When that happens, go to the console.

## 4. CLI path

Only if `showcreds` provided a real `AKIA...` key + secret.

### 4.1 Configure the CLI
```bash
aws configure
# AWS Access Key ID     : AKIA................   (from showcreds, NOT the console username)
# AWS Secret Access Key : ................        (from showcreds, ~40 chars, NOT the console password)
# Default region name   : us-east-1
# Default output format  : json
```

### 4.2 Verify authentication (equivalent of `az account show`)
```bash
aws sts get-caller-identity
```
Expect an ARN with the lab account ID. If you get `InvalidClientTokenId` or
`SignatureDoesNotMatch`, the credentials are wrong — re-check ID vs secret (they
are two different strings; the secret never starts with `AKIA`).

### 4.3 Create the key pair
```bash
aws ec2 create-key-pair \
  --key-name nautilus-kp \
  --key-type rsa \
  --key-format pem \
  --region us-east-1 \
  --query 'KeyMaterial' --output text > nautilus-kp.pem

chmod 400 nautilus-kp.pem
```
`--query 'KeyMaterial' --output text` strips the JSON wrapper so the `.pem`
contains a clean, usable private key (`-----BEGIN RSA PRIVATE KEY-----`).

### 4.4 Verify
```bash
aws ec2 describe-key-pairs \
  --key-names nautilus-kp \
  --region us-east-1 \
  --query 'KeyPairs[0].{Name:KeyName,Type:KeyType,ID:KeyPairId}' \
  --output table
```

## 5. Console path (guaranteed for console-only labs)

1. Open the console URL, e.g.
   `https://<account>.signin.aws.amazon.com/console?region=us-east-1`
2. Sign in with the lab **Username / Password**.
3. Top-right region selector → confirm **US East (N. Virginia) — us-east-1**.
4. Search **EC2** → left menu → **Network & Security → Key Pairs**.
5. **Create key pair** (top-right).
6. Set:
   - **Name:** `nautilus-kp`
   - **Key pair type:** **RSA**
   - **Private key file format:** **.pem**
7. **Create key pair** — the `.pem` downloads automatically.
8. Confirm it appears in the list with **Type = rsa**.

---

## 6. Verification checklist (both paths)

- [ ] Key pair name is exactly `nautilus-kp` (no typos, no trailing spaces).
- [ ] Type column shows `rsa`.
- [ ] Region is `us-east-1` (URL shows `region=us-east-1`).
- [ ] Created **early** in the session; waited ~10 s before running the checker.

---

## 7. Cleanup / idempotency

```bash
# Delete (to recreate cleanly or on teardown)
aws ec2 delete-key-pair --key-name nautilus-kp --region us-east-1
```
`create-key-pair` on an existing name returns `InvalidKeyPair.Duplicate`. Delete
first if you need a clean recreate.

## 8. Troubleshooting reference

| Symptom | Cause | Fix |
|---|---|---|
| `InvalidClientTokenId` on `get-caller-identity` | Entered console username/password into `aws configure` | Use `AKIA...` ID + secret from `showcreds`; if none, use console |
| `SignatureDoesNotMatch` | Correct access key ID but wrong/duplicated secret | Re-enter the real ~40-char secret (not the ID) |
| `AccessDenied ... iam:CreateAccessKey` | Lab denies programmatic key creation | CLI route closed — use the console |
| Key visible in console but checker fails | Grader ran before creation / stale creds / timing at session tail | Recreate early, wait, re-check; else request review with screenshot |
| Key not found by grader | Created in wrong region | Recreate with `--region us-east-1` / correct region in console |
