# EC2 + Private RDS + PHP Connectivity — Complete Documentation

## 1. What this task builds (plain English)

A **two-tier web application**: a public web server (`nautilus-ec2`) running PHP that connects to a **private database** (`nautilus-rds`, MySQL). A browser hits the web server on port 80; the PHP page connects to the database on port 3306 and prints **"Connected successfully."**

```
Browser ──:80──> nautilus-ec2 (Apache + PHP) ──:3306──> nautilus-rds (MySQL, private)
                                                              │
                        index.php prints "Connected successfully"
```

The database is **private** (no public internet endpoint) — only the EC2 instance can reach it, which is the secure, real-world pattern.

---

## 2. The five stages (and why each matters)

| Stage | What | Why |
|-------|------|-----|
| 1 | Create private RDS MySQL | The database backend |
| 2 | Security-group rules | Let EC2 reach RDS on 3306; let public reach EC2 on 80 |
| 3 | SSH key onto EC2's root | Password-less access to configure the instance |
| 4 | Copy + edit `index.php` | The PHP page that connects to RDS |
| 5 | Verify in browser | Confirm the whole chain works |

## 3. Stage 1 — Create the private RDS instance

```bash
REGION=us-east-1

# Confirm the exact version string exists
aws rds describe-db-engine-versions --engine mysql \
  --query "DBEngineVersions[?EngineVersion=='8.4.5'].EngineVersion" --output text --region $REGION

aws rds create-db-instance \
  --db-instance-identifier nautilus-rds \
  --db-instance-class db.t3.micro \
  --engine mysql \
  --engine-version 8.4.5 \
  --storage-type gp2 \
  --allocated-storage 5 \
  --master-username nautilus_admin \
  --master-user-password 'NautilusRds#2024' \
  --db-name nautilus_db \
  --no-publicly-accessible \
  --backup-retention-period 0 \
  --region $REGION

# RDS takes ~10 minutes — wait for available
aws rds wait db-instance-available --db-instance-identifier nautilus-rds --region $REGION
```

- `--db-name nautilus_db` creates the database inside the instance.
- `--no-publicly-accessible` makes it private (no public endpoint).
- Avoid `@ / " space` in the password — they break connection strings.

## 4. Stage 2 — Security groups

```bash
# EC2 details
EC2_IID=$(aws ec2 describe-instances --filters "Name=tag:Name,Values=nautilus-ec2" \
  --query 'Reservations[0].Instances[0].InstanceId' --output text --region $REGION)
EC2_SG=$(aws ec2 describe-instances --instance-ids $EC2_IID \
  --query 'Reservations[0].Instances[0].SecurityGroups[0].GroupId' --output text --region $REGION)
EC2_IP=$(aws ec2 describe-instances --instance-ids $EC2_IID \
  --query 'Reservations[0].Instances[0].PublicIpAddress' --output text --region $REGION)

# RDS security group
RDS_SG=$(aws rds describe-db-instances --db-instance-identifier nautilus-rds \
  --query 'DBInstances[0].VpcSecurityGroups[0].VpcSecurityGroupId' --output text --region $REGION)

# a) RDS accepts 3306 ONLY from the EC2's security group (least privilege)
aws ec2 authorize-security-group-ingress --group-id $RDS_SG \
  --protocol tcp --port 3306 --source-group $EC2_SG --region $REGION

# b) EC2 open on 80 (web) and 22 (SSH)
aws ec2 authorize-security-group-ingress --group-id $EC2_SG \
  --protocol tcp --port 80 --cidr 0.0.0.0/0 --region $REGION
aws ec2 authorize-security-group-ingress --group-id $EC2_SG \
  --protocol tcp --port 22 --cidr 0.0.0.0/0 --region $REGION
```

> Note: in this lab the EC2 and RDS happened to share one security group. That still
> works — the EC2 is a member of the group referenced as the 3306 source.

## 5. Stage 3 — Password-less SSH to the EC2's root

```bash
# Key on aws-client (create if missing)
[ -f /root/.ssh/id_rsa ] || ssh-keygen -t rsa -b 2048 -f /root/.ssh/id_rsa -N ""
PUBKEY=$(cat /root/.ssh/id_rsa.pub)

AZ=$(aws ec2 describe-instances --instance-ids $EC2_IID \
  --query 'Reservations[0].Instances[0].Placement.AvailabilityZone' --output text --region $REGION)
ssh-keygen -t rsa -b 2048 -f /tmp/eic -N "" 2>/dev/null
```

**Determine the correct SSH user first** — it depends on the OS:
```bash
AMI=$(aws ec2 describe-instances --instance-ids $EC2_IID \
  --query 'Reservations[0].Instances[0].ImageId' --output text --region $REGION)
aws ec2 describe-images --image-ids $AMI --query 'Images[0].Name' --output text --region $REGION
```
- Name contains `ubuntu` → login user is **`ubuntu`**
- Name contains `amzn`/`al2` → login user is **`ec2-user`**

**Push your key to root via EC2 Instance Connect** (chain within the 60s window; replace `<user>` with the one you found):
```bash
aws ec2-instance-connect send-ssh-public-key --instance-id $EC2_IID \
  --availability-zone $AZ --instance-os-user <user> \
  --ssh-public-key file:///tmp/eic.pub --region $REGION \
&& ssh -o ConnectTimeout=10 -o StrictHostKeyChecking=no -i /tmp/eic <user>@$EC2_IP \
   "sudo mkdir -p /root/.ssh && echo '$PUBKEY' | sudo tee -a /root/.ssh/authorized_keys && sudo chmod 600 /root/.ssh/authorized_keys && echo KEY_ADDED"
```
Now `ssh -i /root/.ssh/id_rsa root@$EC2_IP` works password-less.

## 6. Stage 4 — Web stack + index.php

**Identify the OS package set** — this instance was **Ubuntu**:

| Amazon Linux | Ubuntu (what this task needed) |
|---|---|
| `yum`/`dnf` | `apt-get` |
| `httpd` | `apache2` |
| `php-mysqlnd` | `php-mysql` |
| `systemctl start httpd` | `systemctl start apache2` |

**Install the stack (Ubuntu):**
```bash
ssh -i /root/.ssh/id_rsa root@$EC2_IP bash -s <<'EOF'
export DEBIAN_FRONTEND=noninteractive
apt-get update -y
apt-get install -y apache2 php php-mysql libapache2-mod-php
systemctl enable apache2
systemctl start apache2
EOF
```
> `libapache2-mod-php` is what makes Apache actually *execute* PHP.
> `php-mysql` provides `mysqli` — without it, `mysqli_connect` is undefined → HTTP 500.

**Copy index.php up:**
```bash
scp -o StrictHostKeyChecking=no -i /root/.ssh/id_rsa /root/index.php root@$EC2_IP:/var/www/html/index.php
```

**Inspect the file to see its placeholders — ALWAYS do this before editing:**
```bash
ssh -i /root/.ssh/id_rsa root@$EC2_IP "cat /var/www/html/index.php"
```
This file used angle-bracket placeholders:
```php
$dbname = '<dbname>';
$dbuser = '<dbuser>';
$dbpass = '<dbpass>';
$dbhost = '<dbhost>';
```

**Get the RDS endpoint (the DNS name, not the identifier):**
```bash
RDS_ENDPOINT=$(aws rds describe-db-instances --db-instance-identifier nautilus-rds \
  --query 'DBInstances[0].Endpoint.Address' --output text --region us-east-1)
echo "$RDS_ENDPOINT"   # confirm it's not blank BEFORE editing
```

**Replace the placeholders (run on the instance; `|` delimiter, endpoint expanded locally):**
```bash
ssh -i /root/.ssh/id_rsa root@$EC2_IP "sed -i \"s|<dbname>|nautilus_db|g; s|<dbuser>|nautilus_admin|g; s|<dbpass>|NautilusRds#2024|g; s|<dbhost>|${RDS_ENDPOINT}|g\" /var/www/html/index.php"
```

**Verify the edit actually landed (critical step):**
```bash
ssh -i /root/.ssh/id_rsa root@$EC2_IP "head -6 /var/www/html/index.php"
```
Must show real values, no `<...>` brackets.

**Fallback if sed won't replace** (angle brackets fight shell quoting) — rewrite the whole file:
```bash
ssh -i /root/.ssh/id_rsa root@$EC2_IP "cat > /var/www/html/index.php" <<EOF
<?php
\$dbname = 'nautilus_db';
\$dbuser = 'nautilus_admin';
\$dbpass = 'NautilusRds#2024';
\$dbhost = '${RDS_ENDPOINT}';
\$link = mysqli_connect(\$dbhost, \$dbuser, \$dbpass) or die("Unable to Connect to '\$dbhost'");
mysqli_select_db(\$link, \$dbname) or die("Could not open the db '\$dbname'");
\$test_query = "SHOW TABLES FROM \$dbname";
\$result = mysqli_query(\$link, \$test_query);
\$tblCnt = 0;
while(\$tbl = mysqli_fetch_array(\$result)) { \$tblCnt++; }
echo "Connected successfully<br />\n";
?>
EOF
```

## 8. Troubleshooting table (the actual errors hit, in order)

| Symptom | Real meaning | Fix |
|---|---|---|
| `Permission denied (publickey)` on SSH | Connected but key rejected — wrong SSH user | Ubuntu uses `ubuntu`, not `ec2-user`; check the AMI name |
| `dnf: command not found` / `httpd.service not found` | This is Ubuntu, not Amazon Linux | Use `apt-get` / `apache2` / `php-mysql` |
| `curl` returns empty | Apache serving but PHP not executing | Install `libapache2-mod-php`, restart apache2 |
| HTTP **500** | PHP runs but crashes | Read `/var/log/apache2/error.log` for the exact fatal error |
| `getaddrinfo for <dbhost> failed` | The literal placeholder was never replaced | Re-run sed; **verify with `head -6`** that brackets are gone |
| `Access denied for user` | Wrong DB username/password in index.php | Match `$dbuser`/`$dbpass` to the RDS master creds |
| `Can't connect to MySQL server` | Network path blocked or RDS not ready | Confirm RDS `available` + SG allows 3306 from EC2 SG |

**Where to look when a PHP page 500s:** `/var/log/apache2/error.log` (Ubuntu) or
`/var/log/httpd/error_log` (Amazon Linux). It names the exact line and reason.

## 9. Key lessons

1. **Match commands to the OS.** Detect it from the AMI name first. Ubuntu = `apt`/`apache2`/`php-mysql`; Amazon Linux = `yum`/`httpd`/`php-mysqlnd`.
2. **`Permission denied` = auth problem; timeout = network problem.** Different SSH user vs blocked port 22 are diagnosed differently.
3. **HTTP 500 means PHP executed and crashed** — the Apache error log pinpoints why. An empty page usually means PHP isn't being executed at all (missing mod-php).
4. **Always verify an edit landed on the live file** (`head -6`) before testing downstream. The persistent 500 here was purely an unreplaced placeholder — a 10-second check would have caught it.
5. **RDS needs the endpoint DNS name**, not the instance identifier, and it must be `available` before PHP can connect.
6. **Private RDS security model:** the DB allows 3306 only from the web server's security group — never the public internet.
