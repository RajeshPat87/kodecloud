# Runbook — Copy Local File to S3 Bucket (`aws_s3_object`)

**Task:** Upload `/tmp/devops.txt` to S3 bucket `devops-cp-12859`
**Resource:** `aws_s3_object` · **Working directory:** `/home/bob/terraform`

---

## 1. Concept / purpose

**`aws_s3_object`** is the Terraform-native resource for managing files (objects) inside an S3 bucket. It uploads a local file to S3 and tracks it in Terraform state — meaning Terraform detects content changes, can update the object, and manages its lifecycle.

**How it works:**
```
Local file /tmp/devops.txt
    → Terraform reads file + computes MD5 (etag)
    → Calls s3:PutObject API
    → Object lands at s3://devops-cp-12859/devops.txt
    → Tracked in terraform.tfstate
```

**`aws_s3_object` vs `null_resource + aws s3 cp`:**

| Approach | Change detection | State tracked | Idempotent | Best for |
|---|---|---|---|---|
| `aws_s3_object` | ✓ via `etag` | ✓ | ✓ | Terraform-native, declarative |
| `null_resource + local-exec` | ✗ runs once | ✗ | ✗ | One-time procedural commands |

Always use `aws_s3_object` for file uploads — it's the correct declarative approach.

**`etag = filemd5(path)`** — computes the MD5 hash of the local file. Terraform compares this against S3's stored ETag on every plan. If the file content changes → Terraform detects the diff → re-uploads on next apply. Without `etag`, Terraform has no way to detect content changes and won't re-upload.

**`key`** — the object's name/path inside the bucket. `"devops.txt"` = root of the bucket. `"uploads/2026/devops.txt"` = nested path (S3 "folders" are just key prefixes).

**Bucket must already exist** — `aws_s3_object` uploads into an existing bucket. It does not create the bucket. Use `aws_s3_bucket` first (or reference an existing one).

## 2. Syntax reference

```hcl
resource "aws_s3_object" "<local_name>" {
  bucket = "<bucket-name>"              # REQUIRED — target bucket name or reference
  key    = "<object-key>"              # REQUIRED — path/name in bucket e.g. "file.txt"
  source = "<local-file-path>"         # upload from local file

  # change detection — re-upload when file content changes
  etag   = filemd5("<local-file-path>") # MD5 of local file

  # OR use inline content instead of source file
  content      = "hello world"          # string content directly
  content_type = "text/plain"           # MIME type

  # optional settings
  acl                    = "private"    # private | public-read
  storage_class          = "STANDARD"   # STANDARD | STANDARD_IA | GLACIER
  server_side_encryption = "AES256"     # encrypt at rest
  content_disposition    = "attachment" # browser download behavior
  cache_control          = "max-age=3600"

  tags = { Name = "<object-key>" }
}
```

**Reference pattern — bucket already in state:**
```hcl
resource "aws_s3_object" "example" {
  bucket = aws_s3_bucket.<bucket_resource_name>.id   # reference not hardcode
  key    = "devops.txt"
  source = "/tmp/devops.txt"
  etag   = filemd5("/tmp/devops.txt")
}
```

**Reference pattern — bucket pre-existing (not in state):**
```hcl
resource "aws_s3_object" "example" {
  bucket = "devops-cp-12859"           # hardcoded — bucket managed externally
  key    = "devops.txt"
  source = "/tmp/devops.txt"
  etag   = filemd5("/tmp/devops.txt")
}
```

## 5. main.tf content

Existing `main.tf` had the bucket resource — append only the object block:

```hcl
resource "aws_s3_bucket" "my_bucket" {
  bucket = "devops-cp-12859"
  acl    = "private"

  tags = {
    Name = "devops-cp-12859"
  }
}

resource "aws_s3_object" "devops_file" {
  bucket = aws_s3_bucket.my_bucket.id
  key    = "devops.txt"
  source = "/tmp/devops.txt"
  etag   = filemd5("/tmp/devops.txt")
}
```

`bucket = aws_s3_bucket.my_bucket.id` — references the existing bucket resource in state. `.id` on an S3 bucket returns the bucket name (which is also its ID). This is preferred over hardcoding the string `"devops-cp-12859"` because it creates an implicit dependency — Terraform ensures the bucket exists before creating the object.

## 9. Common errors and fixes

| Error | Cause | Fix |
|---|---|---|
| `NoSuchBucket` | Bucket doesn't exist | Verify bucket name; create bucket first |
| `source` file not found | `/tmp/devops.txt` missing on Terraform client | `ls -l /tmp/devops.txt` — create if missing |
| `etag` causes re-upload every plan | File content changed or path wrong | Ensure path in `filemd5()` matches `source` exactly |
| `acl` error on newer provider | `acl` deprecated in AWS provider 4.x+ | Remove `acl` line; manage via `aws_s3_bucket_acl` |
| Object uploads but content wrong | Wrong source path | `cat /tmp/devops.txt` before apply |
| `plan` shows 0 changes but object missing | State has stale entry | `terraform state rm aws_s3_object.devops_file` then re-apply |

## 10. Key lessons

### `etag` is essential for change detection

```hcl
# WITHOUT etag — Terraform can't detect file content changes
resource "aws_s3_object" "example" {
  bucket = "my-bucket"
  key    = "file.txt"
  source = "/tmp/file.txt"
  # if you update /tmp/file.txt → terraform plan shows No changes → stale content in S3
}

# WITH etag — Terraform detects any content change
resource "aws_s3_object" "example" {
  bucket = "my-bucket"
  key    = "file.txt"
  source = "/tmp/file.txt"
  etag   = filemd5("/tmp/file.txt")   # file changes → etag changes → plan shows update
}
```

### `bucket` reference vs hardcoded string

```hcl
# hardcoded — works but no implicit dependency
bucket = "devops-cp-12859"

# reference — preferred when bucket is in same state
bucket = aws_s3_bucket.my_bucket.id
# implicit dependency: Terraform creates/verifies bucket before uploading
```

### `key` controls the S3 object path

```hcl
key = "devops.txt"                    # s3://bucket/devops.txt
key = "uploads/devops.txt"            # s3://bucket/uploads/devops.txt
key = "2026/08/devops.txt"            # s3://bucket/2026/08/devops.txt
key = "path/to/nested/devops.txt"     # s3://bucket/path/to/nested/devops.txt
```

S3 doesn't have real folders — the `/` in the key is just a naming convention that the console displays as a folder hierarchy.
