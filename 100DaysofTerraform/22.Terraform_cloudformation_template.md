# Terraform — CloudFormation Stack (`xfusion-stack`) with S3 + Versioning

## Concept / purpose

**AWS CloudFormation** is AWS's native Infrastructure-as-Code service. It provisions and manages AWS resources via **stacks** — a collection of resources defined in a CloudFormation template (JSON or YAML).

**Why use Terraform to create a CloudFormation stack?**
- You might be migrating from CloudFormation to Terraform incrementally
- Some teams use Terraform as the outer orchestrator but have existing CloudFormation templates
- This task tests your ability to use `aws_cloudformation_stack` resource — Terraform manages the stack lifecycle (create/update/delete), and CloudFormation manages the resources inside it

**Relationship:**
```
Terraform (aws_cloudformation_stack)
    └── CloudFormation Stack: xfusion-stack
            └── S3 Bucket: xfusion-bucket-28815
                    └── Versioning: Enabled
```

**Key concept — two IaC layers:**
- Terraform creates/manages the **CloudFormation stack**
- CloudFormation creates/manages the **S3 bucket** inside the stack
- The S3 bucket is NOT in Terraform state directly — it's inside the stack

**CloudFormation template structure:**
```yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: <text>
Resources:
  <LogicalID>:
    Type: AWS::<Service>::<Resource>
    Properties:
      <key>: <value>
```

**S3 versioning in CloudFormation:**
```yaml
VersioningConfiguration:
  Status: Enabled    # Enabled | Suspended
```

## Syntax reference

```hcl
resource "aws_cloudformation_stack" "<local_name>" {
  name          = "<stack-name>"        # REQUIRED — stack name
  template_body = <<TEMPLATE
    <CloudFormation JSON or YAML>
  TEMPLATE

  # OR reference an S3-hosted template
  template_url  = "https://s3.amazonaws.com/<bucket>/<template>"

  parameters = {                        # optional — pass to template params
    ParamKey = "ParamValue"
  }

  capabilities = ["CAPABILITY_IAM"]     # required if stack creates IAM resources
                                        # CAPABILITY_IAM | CAPABILITY_NAMED_IAM
                                        # CAPABILITY_AUTO_EXPAND

  on_failure   = "ROLLBACK"            # ROLLBACK | DO_NOTHING | DELETE
  timeout_in_minutes = 30              # optional

  tags = { Name = "<stack-name>" }
}
```

## main.tf content

```hcl
resource "aws_cloudformation_stack" "xfusion_stack" {
  name = "xfusion-stack"

  template_body = jsonencode({
    AWSTemplateFormatVersion = "2010-09-09"
    Description = "CloudFormation stack to create S3 bucket with versioning"
    Resources = {
      XfusionBucket = {
        Type = "AWS::S3::Bucket"
        Properties = {
          BucketName = "xfusion-bucket-28815"
          VersioningConfiguration = {
            Status = "Enabled"
          }
        }
      }
    }
  })

  tags = {
    Name = "xfusion-stack"
  }
}
```

**Why `jsonencode`** — Terraform's `jsonencode` function converts HCL maps to valid JSON, which CloudFormation accepts as a template body. This avoids heredoc JSON formatting issues and gets validated at `terraform plan` time.

## Watch-outs

- **S3 bucket is NOT in Terraform state** — it's inside the CloudFormation stack. `terraform state list` shows only `aws_cloudformation_stack.xfusion_stack`, not the bucket. Verify the bucket via the CloudFormation or S3 API.
- **Terraform waits for `CREATE_COMPLETE`** — `aws_cloudformation_stack` blocks until the stack finishes (success or failure). If the template has an error, `terraform apply` will fail with the CloudFormation error message.
- **`jsonencode` vs YAML heredoc** — both work. `jsonencode` is preferred (HCL-native, validated at plan time). YAML heredoc is also valid:
  ```hcl
  template_body = <<YAML
  AWSTemplateFormatVersion: "2010-09-09"
  Resources:
    XfusionBucket:
      Type: AWS::S3::Bucket
      Properties:
        BucketName: xfusion-bucket-28815
        VersioningConfiguration:
          Status: Enabled
  YAML
  ```
- **`capabilities`** — not needed here since the stack only creates an S3 bucket (no IAM resources). Add `capabilities = ["CAPABILITY_IAM"]` only when the template creates IAM roles/policies.
- **Stack update vs replace** — if you change the `template_body`, Terraform sends an `UpdateStack` call. CloudFormation then updates or replaces resources as needed.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
