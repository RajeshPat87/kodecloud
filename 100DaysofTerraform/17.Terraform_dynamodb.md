# Terraform — DynamoDB Table (`xfusion-users`)

## Concept / purpose

**DynamoDB** is AWS's fully managed NoSQL key-value and document database. Unlike relational databases, DynamoDB is schemaless — you only define the **primary key** at table creation; all other attributes are defined per-item at write time.

**Primary key types:**
- **Simple primary key** — just a **partition key** (hash key). Each item is uniquely identified by this key alone. This task uses this type (`xfusion_id`).
- **Composite primary key** — a **partition key + sort key** (hash + range). Multiple items can share the same partition key as long as sort keys differ.

**Billing modes:**
- `PROVISIONED` — you specify read/write capacity units (RCUs/WCUs) upfront. Cheaper for predictable, steady workloads. Requires `read_capacity` and `write_capacity` attributes.
- `PAY_PER_REQUEST` (on-demand) — AWS scales automatically; you pay per request. No capacity planning needed. Best for unpredictable or spiky workloads, dev/test environments. **This task uses this mode.**

**Attribute types:**
- `S` — String
- `N` — Number
- `B` — Binary

Only attributes used in the primary key (or secondary indexes) need to be declared in `attribute` blocks. Other item attributes are schema-free.

## Syntax reference

```hcl
resource "aws_dynamodb_table" "<local_name>" {
  name         = "<table-name>"         # REQUIRED
  billing_mode = "PAY_PER_REQUEST"      # PAY_PER_REQUEST | PROVISIONED
  # if PROVISIONED:
  # read_capacity  = <number>
  # write_capacity = <number>

  hash_key  = "<partition-key-name>"   # REQUIRED — partition key attribute name
  range_key = "<sort-key-name>"        # optional — sort key attribute name

  # declare ONLY attributes used in hash_key, range_key, or indexes
  attribute {
    name = "<key-name>"                 # must match hash_key or range_key
    type = "S"                          # S=String | N=Number | B=Binary
  }

  # optional — Global Secondary Index
  global_secondary_index {
    name            = "<gsi-name>"
    hash_key        = "<attr-name>"
    range_key       = "<attr-name>"
    projection_type = "ALL"             # ALL | KEYS_ONLY | INCLUDE
  }

  # optional — Local Secondary Index
  local_secondary_index {
    name            = "<lsi-name>"
    range_key       = "<attr-name>"
    projection_type = "ALL"
  }

  # optional — TTL
  ttl {
    attribute_name = "<ttl-attr>"
    enabled        = true
  }

  # optional — point-in-time recovery
  point_in_time_recovery {
    enabled = true
  }

  tags = { Name = "<table-name>" }
}
```

## Watch-outs

- **`attribute` block only for key attributes** — only declare `attribute` blocks for attributes used as `hash_key`, `range_key`, or index keys. Declaring non-key attributes causes an error: `All attributes must be indexed`.
- **`hash_key` name must exactly match the `attribute` block `name`** — `xfusion_id` in both places. Mismatch = plan error.
- **`PAY_PER_REQUEST` = no capacity attributes** — do NOT add `read_capacity` or `write_capacity` when using `PAY_PER_REQUEST`; they are only for `PROVISIONED` mode and will cause a conflict error.
- **`type = "S"` for String** — `S` (uppercase), not `string` or `str`. DynamoDB type codes are single uppercase letters.
- **Table status** — DynamoDB tables go through `CREATING` → `ACTIVE`. Terraform waits for `ACTIVE` before completing. After apply, `table_status = "ACTIVE"` confirms it's ready.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
