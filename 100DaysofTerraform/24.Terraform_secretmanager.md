# Terraform — AWS Secrets Manager (`datacenter-secret`)

## Concept / purpose

**AWS Secrets Manager** is a fully managed service for storing, rotating, and retrieving sensitive data — database credentials, API keys, OAuth tokens, SSH keys, and any other secrets your applications need.

**Key concepts:**
- **Secret** — the container. Has a name, description, and metadata. Think of it as a "slot" that holds the actual secret value.
- **Secret version** — the actual sensitive value. A secret can have multiple versions (current, previous, pending rotation). Terraform manages this via `aws_secretsmanager_secret_version`.
- **Secret value** — stored as a string. For structured data (credentials, config), store as JSON string. Secrets Manager has first-class support for JSON key-value pairs.
- **Two resources always needed:**
  - `aws_secretsmanager_secret` — creates the secret container (name, description, KMS key, rotation config)
  - `aws_secretsmanager_secret_version` — stores the actual secret value inside the container

**Why two resources?** AWS separates the secret metadata (name, rotation policy, KMS key) from the secret value (the sensitive data). This allows:
- Updating the value without changing metadata
- Rotating values (new version) while keeping the secret name
- Granting separate IAM permissions for `secretsmanager:GetSecretValue` vs `secretsmanager:DescribeSecret`

**Secret value formats:**
```json
// Key-value pairs (most common for credentials)
{"username": "admin", "password": "MyPassword123"}

// Plain string (for simple tokens/keys)
"myApiToken123"

// Connection string
"postgresql://user:pass@host:5432/dbname"
```

**Rotation** — Secrets Manager can automatically rotate secrets on a schedule using Lambda functions. Not required here but a key production feature.

**Cost note** — in real AWS, Secrets Manager charges per secret per month ($0.40) plus per 10,000 API calls. Use Parameter Store SecureString for cost-sensitive use cases with less rotation complexity.

## Syntax reference

```hcl
# secret container (metadata)
resource "aws_secretsmanager_secret" "<local_name>" {
  name                    = "<secret-name>"     # REQUIRED — unique name
  description             = "<text>"            # optional
  kms_key_id              = "<key-arn>"         # optional — custom KMS key
  recovery_window_in_days = 7                   # 0 = no recovery window (instant delete)
                                                # 7-30 = soft delete window

  tags = { Name = "<secret-name>" }
}

# secret value (the actual sensitive data)
resource "aws_secretsmanager_secret_version" "<local_name>" {
  secret_id     = aws_secretsmanager_secret.<local_name>.id  # REQUIRED
  secret_string = jsonencode({                               # REQUIRED (or secret_binary)
    key = "value"
  })
  # OR for plain string:
  # secret_string = "plain-text-value"
  # OR for binary:
  # secret_binary = filebase64("path/to/file")
}

# read an existing secret (data source)
data "aws_secretsmanager_secret" "<local_name>" {
  name = "<secret-name>"
}
data "aws_secretsmanager_secret_version" "<local_name>" {
  secret_id = data.aws_secretsmanager_secret.<local_name>.id
}
# access value: data.aws_secretsmanager_secret_version.<name>.secret_string
# parse JSON: jsondecode(data.aws_secretsmanager_secret_version.<name>.secret_string)
```

## main.tf content

```hcl
resource "aws_secretsmanager_secret" "datacenter_secret" {
  name                    = "datacenter-secret"
  description             = "Secret containing admin credentials for datacenter"
  recovery_window_in_days = 0           # instant delete on terraform destroy (lab friendly)

  tags = {
    Name = "datacenter-secret"
  }
}

resource "aws_secretsmanager_secret_version" "datacenter_secret_version" {
  secret_id = aws_secretsmanager_secret.datacenter_secret.id

  secret_string = jsonencode({
    username = "admin"
    password = "Namin123"
  })
}
```

**Why `recovery_window_in_days = 0`** — in a lab environment, if you `terraform destroy` and re-apply, a secret with a recovery window (default 7 days) can't be recreated with the same name until the window expires. Setting it to `0` allows instant deletion and recreation — critical for lab/test environments.

## Watch-outs

- **Two resources required** — `aws_secretsmanager_secret` (container) + `aws_secretsmanager_secret_version` (value). Creating only the secret container leaves it empty — no value stored.
- **`recovery_window_in_days = 0`** — critical for labs. Without it, destroying and recreating the same secret name within 7–30 days fails with "already scheduled for deletion." Set to `0` to bypass the recovery window.
- **`secret_string` is sensitive in state** — Terraform marks it as sensitive and won't show the value in `terraform plan` output, but it IS stored in `terraform.tfstate` in plaintext. Never commit state files to Git.
- **`jsonencode` produces valid JSON** — the key-value pair `{"username":"admin","password":"Namin123"}` is what Secrets Manager stores. AWS SDKs can then parse it with `JSON.parse()` or equivalent.
- **Secret name suffix** — AWS appends a random 6-character suffix to the ARN (`datacenter-secret-xxxxxx`) but the `name` remains `datacenter-secret`. Use the name (not ARN) for `--secret-id` in CLI commands.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
