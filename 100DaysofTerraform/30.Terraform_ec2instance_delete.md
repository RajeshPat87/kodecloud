Exactly right. Since the instance is already in state and you want to **keep the provisioning code** (requirement: "keep the code, might need it again"), a targeted destroy is the correct and minimal approach.

## Command

```bash
cd /home/bob/terraform
terraform destroy -target=aws_instance.ec2 -auto-approve
```

`-target=aws_instance.ec2` — destroys only that specific resource, leaves everything else in state and `main.tf` untouched.

## Why this is the right approach

| Approach | Keeps code | Deletes instance | Safe |
|---|---|---|---|
| `terraform destroy -target=aws_instance.ec2` | ✓ | ✓ | ✓ |
| `terraform destroy` (no target) | ✓ | ✓ | ✗ destroys everything |
| Delete resource block from main.tf + apply | ✗ loses the code | ✓ | ✗ |
| Comment out resource + apply | ✓ | ✓ | ok but messy |

The `-target` flag is exactly for this scenario — temporary deletion of one resource while keeping the configuration intact for future re-provisioning.

## Post-check

```bash
# confirm instance terminated
aws --endpoint-url=http://aws:4566 ec2 describe-instances \
  --region us-east-1 \
  --filters "Name=tag:Name,Values=datacenter-ec2" \
  --query "Reservations[].Instances[].{ID:InstanceId,State:State.Name}"

# confirm removed from state
terraform state list
# expect: empty (or no aws_instance.ec2)

# confirm main.tf still has the code
cat main.tf
```

Expected:
```json
[{ "ID": "i-...", "State": "terminated" }]

# state list: empty

# main.tf: still shows the full aws_instance.ec2 block untouched
```

## To re-provision later

When needed again, just run:
```bash
terraform apply -auto-approve
```
The code is still in `main.tf` — Terraform will create a fresh instance from it.
