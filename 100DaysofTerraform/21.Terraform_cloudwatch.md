# Terraform — CloudWatch Log Group + Log Stream

## Concept / purpose

**CloudWatch Logs** is AWS's centralized log management service. It collects, monitors, and stores log data from AWS services, EC2 instances, Lambda functions, containers, and custom applications.

**Hierarchy:**
```
Log Group
  └── Log Stream 1
  └── Log Stream 2
        └── Log Events (individual log lines)
```

**Log Group** — the top-level container. Defines retention policy and access controls. All log streams within a group share the same retention period. Example: one log group per application (`/myapp/prod`).

**Log Stream** — a sequence of log events from a single source within a group. Example: one stream per EC2 instance, per container, or per Lambda invocation. Streams are automatically created by AWS services but can also be pre-created manually (as this task requires).

**Log Event** — a single log record with a timestamp and message. The actual log line.

**Retention periods** — how long logs are kept before automatic deletion:
```
1, 3, 5, 7, 14, 30, 60, 90, 120, 150, 180, 365, 400, 545, 731, 1096, 1827, 2192, 2557, 2922, 3288, 3653
```
`null` (default) = never expire (logs kept forever — costs money in production).

**Two separate resources** are needed:
- `aws_cloudwatch_log_group` — creates the log group
- `aws_cloudwatch_log_stream` — creates the stream inside the group (references the group)

## Syntax reference

```hcl
resource "aws_cloudwatch_log_group" "<local_name>" {
  name              = "<log-group-name>"    # REQUIRED — e.g. "/myapp/prod"
  retention_in_days = <number>              # optional — null = never expire
  kms_key_id        = "<key-arn>"          # optional — encrypt logs with KMS

  tags = { Name = "<log-group-name>" }
}

resource "aws_cloudwatch_log_stream" "<local_name>" {
  name           = "<stream-name>"          # REQUIRED
  log_group_name = aws_cloudwatch_log_group.<local_name>.name   # REQUIRED

  # no tags support on log streams
}

# optional — metric filter (alert on log patterns)
resource "aws_cloudwatch_log_metric_filter" "<local_name>" {
  name           = "<filter-name>"
  pattern        = "<filter-pattern>"       # e.g. "ERROR"
  log_group_name = aws_cloudwatch_log_group.<local_name>.name

  metric_transformation {
    name      = "<metric-name>"
    namespace = "<namespace>"
    value     = "1"
  }
}

# optional — subscription filter (stream logs to Lambda/Kinesis)
resource "aws_cloudwatch_log_subscription_filter" "<local_name>" {
  name            = "<filter-name>"
  log_group_name  = aws_cloudwatch_log_group.<local_name>.name
  filter_pattern  = ""
  destination_arn = "<lambda-or-kinesis-arn>"
}
```

## Watch-outs

- **Two resources required** — `aws_cloudwatch_log_group` alone is not enough; `aws_cloudwatch_log_stream` is a separate resource that must be created explicitly.
- **`log_group_name` references the group** — `aws_cloudwatch_log_stream` must know which group it belongs to via `log_group_name`. Use the resource reference (`aws_cloudwatch_log_group.<name>.name`) not a hardcoded string — this creates the implicit dependency ensuring correct creation order.
- **Log streams don't support tags** — `aws_cloudwatch_log_stream` has no `tags` argument. Only the log group supports tags.
- **`retention_in_days = 0`** in state means never expire (null/unset) — this is the default and is correct for this task.
- **Stream ARN format** — note the log stream ARN includes both the group and stream name: `arn:aws:logs:...:log-group:<group>:log-stream:<stream>`.
- **Tags may drift on log group** — same LocalStack pattern; remove tags block if plan shows changes after apply.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
