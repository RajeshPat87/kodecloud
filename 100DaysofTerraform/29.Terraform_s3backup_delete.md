**Task:** Copy `datacenter-bck-9895` contents to `/opt/s3-backup/` then delete the bucket

**Working directory:** `/home/bob/terraform`

## 1. Concept / purpose

### Why `null_resource` + `local-exec`?

Terraform manages AWS resources declaratively — it creates, updates, and destroys real infrastructure objects. But some tasks are **procedural** — run a command, copy files, call a script. Terraform handles these via **provisioners**.

**`null_resource`** — a resource that manages no real infrastructure. It exists purely to run provisioners. Its lifecycle (create/destroy) is the hook for running commands.

**`local-exec` provisioner** — runs a shell command on the machine executing `terraform apply` (the Terraform client host, not a remote server). AWS CLI must be available on that host.

```
terraform apply runs on terraform-client
    → local-exec fires on terraform-client
    → AWS CLI calls run from terraform-client
    → S3 API called via LocalStack endpoint
    → Files land on terraform-client at /opt/s3-backup/
```

### Why two `null_resource` blocks?

`depends_on` between them enforces the order:
```
null_resource.copy_s3_contents  →  null_resource.delete_s3_bucket
(sync first)                        (delete after copy confirms)
```
Without this, Terraform might delete the bucket before the sync completes — data loss.

### `aws s3 sync` vs `aws s3 cp --recursive`

| Command | Behavior |
|---|---|
| `aws s3 sync s3://bucket /local/` | Only copies changed/new files. Preserves directory structure. Idempotent. |
| `aws s3 cp s3://bucket /local/ --recursive` | Copies everything every time. |

`sync` is preferred — idempotent (safe to re-run), only copies what's needed.

### `force_destroy = true` on `aws_s3_bucket`

S3 buckets cannot be deleted if they contain objects. `force_destroy = true` tells Terraform to empty the bucket (all objects + versions) before deleting. Without it: `BucketNotEmpty` error on destroy.

In this task we use the pure CLI approach (`aws s3 rm --recursive` + `aws s3api delete-bucket`) via the second `null_resource` — no `aws_s3_bucket` resource needed when doing everything via CLI.

## 2. Syntax reference

```hcl
# null_resource — runs commands, manages no real AWS resource
resource "null_resource" "<local_name>" {

  # local-exec — runs on the Terraform client machine
  provisioner "local-exec" {
    command     = "<shell command or heredoc>"
    interpreter = ["/bin/sh", "-c"]    # optional — default
    environment = { KEY = "value" }    # optional — env vars
    working_dir = "/path"              # optional — working directory
    when        = destroy              # optional — run on destroy instead of create
  }

  # re-run the resource when these values change
  triggers = {
    always_run = timestamp()           # forces re-run every apply
    bucket     = "my-bucket"          # re-run if bucket name changes
  }

  # enforce execution order
  depends_on = [null_resource.other]
}
```

**AWS CLI S3 commands:**
```bash
# list bucket contents
aws s3 ls s3://<bucket> --recursive

# sync bucket to local directory (recommended)
aws s3 sync s3://<bucket> /local/path/

# copy all objects recursively
aws s3 cp s3://<bucket> /local/path/ --recursive

# delete all objects in bucket
aws s3 rm s3://<bucket> --recursive

# delete the empty bucket
aws s3api delete-bucket --bucket <bucket> --region <region>

# one-liner: empty + delete
aws s3 rb s3://<bucket> --force      # rb = remove bucket, --force empties first
```

## 5. main.tf content

**Always write with `cat >` — never paste directly — avoids line-ending corruption:**

```bash
cat > /home/bob/terraform/main.tf << 'EOF'
resource "null_resource" "copy_s3_contents" {
  provisioner "local-exec" {
    command = <<-EOT
      mkdir -p /opt/s3-backup
      aws --endpoint-url=http://aws:4566 s3 sync s3://datacenter-bck-9895 /opt/s3-backup/ --region us-east-1
      echo "Contents copied:"
      ls -la /opt/s3-backup/
    EOT
  }
}

resource "null_resource" "delete_s3_bucket" {
  provisioner "local-exec" {
    command = <<-EOT
      aws --endpoint-url=http://aws:4566 s3 rm s3://datacenter-bck-9895 --recursive --region us-east-1
      aws --endpoint-url=http://aws:4566 s3api delete-bucket --bucket datacenter-bck-9895 --region us-east-1
      echo "Bucket datacenter-bck-9895 deleted"
    EOT
  }

  depends_on = [null_resource.copy_s3_contents]
}
EOF
```

## 8. Common errors and fixes

| Error | Cause | Fix |
|---|---|---|
| `Missing newline after block definition` | Paste corruption — extra text on closing `}` line | Use `cat > main.tf << 'EOF'` to write file, never paste |
| `Inconsistent dependency lock file` — null provider missing | `null_resource` added but `terraform init` not re-run | Run `terraform init -upgrade` |
| `BucketNotEmpty` on delete | Objects not emptied before bucket delete | Use `aws s3 rm s3://bucket --recursive` before `delete-bucket` |
| `NoSuchBucket` on sync | Wrong bucket name or wrong endpoint | Verify bucket name + `--endpoint-url=http://aws:4566` |
| `Permission denied` on `/opt/s3-backup/` | Directory not writable | `sudo chmod 777 /opt/s3-backup/` in pre-checks |
| `aws: command not found` in local-exec | AWS CLI not in PATH | Use full path `/usr/local/bin/aws` or install AWS CLI |
| `null_resource` re-runs on every apply | No triggers defined | Add `triggers = { run_once = "true" }` to run only once |
| Commands run out of order | Missing `depends_on` | Always add `depends_on = [null_resource.copy_s3_contents]` on the delete block |

## 9. Key lessons

### Paste vs heredoc for file creation

```bash
# WRONG — paste into VS Code/terminal can corrupt line endings
# Causes: "Missing newline after block definition"

# CORRECT — use cat heredoc
cat > /home/bob/terraform/main.tf << 'EOF'
<content>
EOF
```

### `terraform init -upgrade` vs `terraform init`

```bash
terraform init           # uses existing lock file versions
terraform init -upgrade  # updates lock file + pulls new providers
                         # required when adding a new provider (null, local, tls)
```

### Execution order with `depends_on`

```
Without depends_on:
  Terraform may parallelize null_resources → delete fires before copy completes

With depends_on = [null_resource.copy_s3_contents]:
  copy completes → delete starts → safe sequential execution
```

### `aws s3 rb --force` — the one-liner alternative

```bash
# combines empty + delete in one command
aws --endpoint-url=http://aws:4566 s3 rb s3://datacenter-bck-9895 --force
```
Equivalent to `s3 rm --recursive` + `s3api delete-bucket` but more concise.
