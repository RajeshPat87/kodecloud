# Terraform — VPC with Variables (`variables.tf` + `main.tf`)

## Concept / purpose

**Terraform Variables** separate configuration values from infrastructure code. Instead of hardcoding values directly in `main.tf`, you define them in `variables.tf` and reference them via `var.<name>`. This makes the code reusable — change the variable value without touching the infrastructure logic.

**File structure this task introduces:**
```
/home/bob/terraform/
├── provider.tf       # provider config (already exists)
├── variables.tf      # variable declarations + default values (NEW)
└── main.tf           # infrastructure code referencing variables (NEW)
```

**Three-part variable system:**

```
variables.tf          → declares the variable + sets default value
main.tf               → references with var.<name>
terraform.tfvars      → optional override file (not needed here)
```

**Variable declaration syntax:**
```hcl
variable "<name>" {
  type        = string           # string | number | bool | list | map | object
  default     = "<value>"        # used if no value passed at runtime
  description = "<text>"         # documents what the variable is for
}
```

**Reference syntax in main.tf:**
```hcl
var.<variable_name>
```

**Why this matters for production:**
- Same `main.tf` can create a `dev-vpc`, `staging-vpc`, or `prod-vpc` by changing one variable
- Variables can be overridden at runtime: `terraform apply -var="KKE_vpc=prod-vpc"`
- Or stored in `terraform.tfvars` per environment

## Syntax reference — variables.tf

```hcl
# simple string variable
variable "<name>" {
  type        = string
  default     = "<value>"
  description = "<text>"
}

# number variable
variable "<name>" {
  type    = number
  default = 10
}

# boolean variable
variable "<name>" {
  type    = bool
  default = true
}

# list variable
variable "<name>" {
  type    = list(string)
  default = ["a", "b", "c"]
}

# map variable
variable "<name>" {
  type = map(string)
  default = {
    key1 = "value1"
    key2 = "value2"
  }
}

# object variable (structured)
variable "<name>" {
  type = object({
    name = string
    cidr = string
  })
  default = {
    name = "my-vpc"
    cidr = "10.0.0.0/16"
  }
}
```

## Variable override examples (not needed for this task — for reference)

```bash
# override at runtime via -var flag
terraform apply -var="KKE_vpc=prod-vpc" -auto-approve

# override via environment variable
export TF_VAR_KKE_vpc="staging-vpc"
terraform apply -auto-approve

# override via terraform.tfvars file
echo 'KKE_vpc = "dev-vpc"' > terraform.tfvars
terraform apply -auto-approve
```

**Override priority (highest to lowest):**
```
1. -var flag at command line
2. TF_VAR_* environment variable
3. terraform.tfvars file
4. *.auto.tfvars files
5. default value in variables.tf   ← this task uses this
```

## Watch-outs

- **Variable name `KKE_vpc` is case-sensitive** — must match exactly in `variables.tf` declaration and `var.KKE_vpc` reference in `main.tf`.
- **`variables.tf` is auto-loaded** — Terraform automatically reads all `.tf` files in the working directory. No `import` or `include` needed — just having `variables.tf` in the same directory is enough.
- **`default` value used when no override provided** — since this task doesn't use `-var` flags or `.tfvars`, the `default = "xfusion-vpc"` in `variables.tf` is what gets used.
- **VPC name is a tag not a field** — `aws_vpc` has no native `name` attribute; the name is set via `tags = { Name = var.KKE_vpc }`.
- **Two files, not one** — the task explicitly requires separate `variables.tf` and `main.tf` files. Don't put the variable declaration in `main.tf`.
- **`provider.tf` stays untouched** — leave as-is.
