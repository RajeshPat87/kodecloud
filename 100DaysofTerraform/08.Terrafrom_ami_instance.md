# Terraform — Create AMI from existing EC2 instance (`datacenter-ec2-ami`)

## Concept / purpose

An **Amazon Machine Image (AMI)** is a snapshot of an EC2 instance at a point in time — it captures the OS, installed software, configuration, and data volumes. Once created, you can launch new instances from it, making AMIs the standard mechanism for:
- **Golden images** — a pre-configured baseline that all new instances start from
- **Migration** — capture the current state of an on-prem-style instance and replicate it
- **Backup/recovery** — restore an instance to a known-good state

`aws_ami_from_instance` is the correct Terraform resource for this — it wraps the AWS `CreateImage` API call, which takes a running (or stopped) instance and creates an AMI + backing EBS snapshots. The AMI moves through states: `pending` → `available`. Terraform waits for `available` before marking the resource creation complete, so after `apply` the AMI is ready to use.

The existing instance `datacenter-ec2` is looked up via a **data source** (`aws_instance`) — this reads the instance's ID without managing it, so Terraform won't touch or destroy the source instance.

```hcl
# Look up the existing datacenter-ec2 instance (do not manage/destroy it)
data "aws_instance" "datacenter_ec2" {
  filter {
    name   = "tag:Name"
    values = ["datacenter-ec2"]
  }
}

# Create AMI from the existing instance
resource "aws_ami_from_instance" "datacenter_ec2_ami" {
  name               = "datacenter-ec2-ami"
  source_instance_id = data.aws_instance.datacenter_ec2.id

  tags = {
    Name = "datacenter-ec2-ami"
  }
}
```

## Watch-outs

- **Data source vs resource** — `data "aws_instance"` reads the existing instance without managing it. If you used `resource "aws_instance"` instead, Terraform would try to create a new instance, not reference the existing one.
- **AMI creation takes time** — in real AWS, `aws_ami_from_instance` can take minutes because it snapshots EBS volumes. Terraform waits automatically. In LocalStack it's near-instant.
- **`main.tf` says update, not create** — check `cat main.tf` first. If the EC2 instance is already there as a resource, the instance's ID is available as `aws_instance.datacenter_ec2.id` directly (no data source needed). Use whichever is cleaner based on what's already in the file.
- **AMI name must match exactly** — `datacenter-ec2-ami` in the `name` attribute (not just a tag). The `name` field is what AWS registers as the AMI name; the tag is optional but adds the Name in the console.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
