# Terraform Resource Lifecycle — Behind the Scenes

## The four operation types

Every `terraform apply` falls into one of four categories. Knowing which one fires — and why — prevents surprises in production.

| Operation | Terraform Symbol | AWS API Call | Instance Downtime | ID Changes |
|---|---|---|---|---|
| **Create** | `+` | `RunInstances` | N/A (new) | New ID assigned |
| **In-place update** | `~` | `ModifyInstanceAttribute` | Brief stop for some attrs | Same ID |
| **Destroy + Recreate** | `-/+` | `TerminateInstances` + `RunInstances` | Full replacement | New ID |
| **Destroy** | `-` | `TerminateInstances` | Full termination | ID gone |

---

## EC2 as the example resource

```hcl
# Provision EC2 instance
resource "aws_instance" "ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = "t2.nano"
  subnet_id     = ""
  vpc_security_group_ids = [
    "sg-8ec5ab57adb0dd080"
  ]

  tags = {
    Name = "devops-ec2"
  }
}

resource "aws_instance" "devops_ec2" {
  ami             = "ami-0c101f26f147fa7fd"
  instance_type   = "t2.micro"
  key_name        = "devops-kp"
  security_groups = ["default"]

  root_block_device {
    volume_size = 20
    volume_type = "gp3"
  }

  tags = {
    Name = "devops-ec2"
  }
}
```

## Operation 1 — First-time creation (`+`)

**Triggered when:** resource doesn't exist in state.

**What Terraform does:**
```
terraform plan  → Plan: 1 to add, 0 to change, 0 to destroy
terraform apply → aws_instance.devops_ec2: Creating...
                  aws_instance.devops_ec2: Creation complete [id=i-abc123]
```

**Behind the scenes:**
```
Terraform → AWS EC2 API: RunInstances(ami, instance_type, key_name, ...)
AWS       → Provisions hardware, boots AMI, runs user_data
AWS       → Status: pending → running
Terraform → Polls DescribeInstances until state = "running"
Terraform → Writes i-abc123 + all attributes to terraform.tfstate
```

**Availability during:** N/A — resource didn't exist before.

**Plan output:**
```hcl
+ resource "aws_instance" "devops_ec2" {
    + ami           = "ami-0c101f26f147fa7fd"
    + instance_type = "t2.micro"
    + id            = (known after apply)
  }
```

## Operation 2 — In-place update (`~`)

**Triggered when:** a mutable attribute changes. Terraform modifies the existing resource without destroying it. The instance ID stays the same.

### EC2 attributes that trigger in-place update

| Attribute | AWS API Used | Downtime? |
|---|---|---|
| `instance_type` | `StopInstances` + `ModifyInstanceAttribute` + `StartInstances` | Yes — brief stop/start |
| `tags` | `CreateTags` / `DeleteTags` | None |
| `ebs_optimized` | `ModifyInstanceAttribute` | Brief stop/start |
| `user_data` (with `user_data_replace_on_change = false`) | `ModifyInstanceAttribute` | None (takes effect on next boot) |
| `security_groups` (non-VPC) | `ModifyInstanceAttribute` | None |
| `vpc_security_group_ids` | `ModifyNetworkInterfaceAttribute` | None |

**Example — change instance type (what we just did):**

```hcl
# Before
instance_type = "t2.micro"

# After
instance_type = "t2.nano"
```

**Plan output:**
```hcl
~ resource "aws_instance" "devops_ec2" {
    id            = "i-abc123"           # same ID — in-place
  ~ instance_type = "t2.micro" -> "t2.nano"
  }
Plan: 0 to add, 1 to change, 0 to destroy.
```

**Behind the scenes:**
```
Terraform → StopInstances(i-abc123)
Terraform → Polls until state = "stopped"
Terraform → ModifyInstanceAttribute(i-abc123, instanceType=t2.nano)
Terraform → StartInstances(i-abc123)
Terraform → Polls until state = "running"
Terraform → Updates terraform.tfstate (same id, new instance_type)
```

**Availability:** instance is briefly unavailable during stop → modify → start (~30–60s).

**Example — tag update (zero downtime):**
```hcl
# Before
tags = { Name = "devops-ec2" }

# After
tags = { Name = "devops-ec2", Env = "prod" }
```

**Behind the scenes:**
```
Terraform → CreateTags(i-abc123, {Env: prod})
# instance never stops — tag API is live
```

## Operation 3 — Destroy + Recreate (`-/+`)

**Triggered when:** an **immutable** (ForceNew) attribute changes. Terraform must destroy the old resource and create a new one. A new instance ID is assigned.

### EC2 attributes that trigger destroy + recreate

| Attribute | Why Immutable |
|---|---|
| `ami` | Can't swap the OS image on a running instance |
| `availability_zone` | Physical location can't change |
| `subnet_id` | Network placement is fixed at launch |
| `key_name` | Key pair baked in at launch |
| `user_data` (with `user_data_replace_on_change = true`) | Re-runs bootstrap = new instance needed |
| `placement_group` | Set at launch, can't move |
| `tenancy` | Hardware dedication set at launch |

**Example — change AMI:**

```hcl
# Before
ami = "ami-0c101f26f147fa7fd"

# After
ami = "ami-0abcdef1234567890"
```

**Plan output:**
```hcl
-/+ resource "aws_instance" "devops_ec2" {
      ~ id  = "i-abc123" -> (known after apply)   # NEW ID
      ~ ami = "ami-0c101f26f147fa7fd" -> "ami-0abcdef1234567890" # forces replacement
    }
Plan: 1 to add, 0 to change, 1 to destroy.
```

**Behind the scenes:**
```
Terraform → TerminateInstances(i-abc123)          # old instance GONE
Terraform → Polls until state = "terminated"
Terraform → RunInstances(ami-new, instance_type, ...)  # brand new instance
Terraform → Polls until state = "running"
Terraform → Writes i-xyz789 to terraform.tfstate  # new ID
```

**Availability:** full outage — old instance is terminated before new one is ready (unless `create_before_destroy = true` in lifecycle block).

## Operation 4 — `create_before_destroy` lifecycle (zero-downtime replacement)

**The problem with default `-/+`:** old instance dies first → gap before new one is ready → downtime.

**The fix:** `lifecycle { create_before_destroy = true }` reverses the order.

```hcl
resource "aws_instance" "devops_ec2" {
  ami           = "ami-0abcdef1234567890"    # changed AMI
  instance_type = "t2.nano"

  lifecycle {
    create_before_destroy = true             # new instance UP before old one DOWN
  }

  tags = { Name = "devops-ec2" }
}
```

**Behind the scenes with `create_before_destroy = true`:**
```
WITHOUT (default):
  Stop old → [GAP = DOWNTIME] → Start new

WITH create_before_destroy:
  Start new → [BOTH RUNNING] → Stop old → No gap = zero downtime
```

**Plan output (same `-/+` symbol but different execution order):**
```hcl
-/+ resource "aws_instance" "devops_ec2" {
      + ami = "ami-0abcdef1234567890"    # created first
      - ami = "ami-0c101f26f147fa7fd"   # destroyed after
    }
```

**Important caveat:** both instances run simultaneously briefly. This means:
- Double cost during the transition
- Name tag conflict if the old instance holds it
- Works best with load balancers (detach old, attach new)

## Operation 5 — `ignore_changes` (drift protection)

**Use case:** something outside Terraform (Auto Scaling, manual console change, another tool) modifies an attribute. Without `ignore_changes`, Terraform would revert it every apply.

```hcl
resource "aws_instance" "devops_ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = "t2.nano"

  lifecycle {
    ignore_changes = [
      tags["LastDeployedBy"],    # ignore this specific tag
      user_data,                 # ignore if user_data changes externally
    ]
  }
}
```

**Behind the scenes:**
```
External change: someone added tag LastDeployedBy=jenkins via console
terraform plan  → No changes (because LastDeployedBy is in ignore_changes)
                  Without ignore_changes → plan would show ~ tags = {- LastDeployedBy}
```

## Operation 6 — `prevent_destroy` (accidental deletion guard)

```hcl
resource "aws_instance" "devops_ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = "t2.nano"

  lifecycle {
    prevent_destroy = true       # terraform destroy or -/+ will ERROR
  }
}
```

**Behind the scenes:**
```
terraform destroy → Error: Instance cannot be destroyed
                    (lifecycle.prevent_destroy is true)
```
Terraform refuses to proceed. You must remove `prevent_destroy = true` before destroying.

## Complete decision tree — which operation fires?

```
Attribute changed in main.tf?
         │
         ├── No change → No changes (terraform plan shows nothing)
         │
         ├── New resource (not in state) → CREATE (+)
         │
         ├── Attribute marked ForceNew?
         │      ├── Yes → DESTROY + RECREATE (-/+)
         │      │          └── with create_before_destroy? → new first, then old
         │      │
         │      └── No → IN-PLACE UPDATE (~)
         │                 └── requires stop/start? → brief downtime
         │
         └── Resource removed from main.tf → DESTROY (-)
```

## Side-by-side summary table

| Scenario | Operation | Symbol | ID Changes | Downtime | Key flag |
|---|---|---|---|---|---|
| First apply | Create | `+` | New | No | — |
| Change tags | In-place | `~` | Same | None | mutable |
| Change `instance_type` | In-place | `~` | Same | Brief stop/start | mutable |
| Change `vpc_security_group_ids` | In-place | `~` | Same | None | mutable |
| Change `ami` | Destroy+Recreate | `-/+` | New | Full | ForceNew |
| Change `subnet_id` | Destroy+Recreate | `-/+` | New | Full | ForceNew |
| Change `ami` + `create_before_destroy` | Destroy+Recreate | `-/+` | New | Zero | ForceNew+lifecycle |
| `terraform destroy` | Destroy | `-` | Gone | Full | — |
| Attribute in `ignore_changes` | No-op | none | Same | None | lifecycle |
| Any change + `prevent_destroy` | Error | — | — | — | lifecycle |

## The `replace_triggered_by` meta-argument (Terraform 1.2+)

Force replacement of one resource when another changes — even if the first resource's own attributes didn't change.

```hcl
resource "aws_instance" "devops_ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = "t2.nano"

  lifecycle {
    replace_triggered_by = [
      aws_key_pair.devops_kp.id    # if the key pair changes → recreate instance too
    ]
  }
}
```

**Behind the scenes:**
```
aws_key_pair.devops_kp changes (new key uploaded)
→ Terraform flags aws_instance.devops_ec2 for replacement too
→ even though instance attributes didn't change
→ -/+ recreate with new key pair
```

## Quick reference — EC2 attribute mutability

```
MUTABLE (in-place ~):           IMMUTABLE (destroy+recreate -/+):
─────────────────────────────   ──────────────────────────────────
tags                            ami
instance_type          *        availability_zone
ebs_optimized          *        subnet_id
vpc_security_group_ids          key_name
monitoring                      placement_group
credit_specification            tenancy
hibernation                     host_id

* requires stop/start — brief downtime
```
