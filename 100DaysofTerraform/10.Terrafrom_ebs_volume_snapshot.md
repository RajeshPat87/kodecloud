# Terraform — EBS Snapshot (`devops-vol-ss`) from existing volume

## Concept / purpose

An **EBS Snapshot** is a point-in-time backup of an EBS volume stored in S3 (managed by AWS, not your S3 bucket). Snapshots are:
- **Incremental** — only changed blocks since the last snapshot are stored, saving cost
- **Region-scoped** — snapshots live in the same region as the source volume
- **Used for** — backups, creating new volumes from a known state, copying volumes across regions/accounts, creating AMIs

The workflow here: look up the existing `devops-vol` volume via a **data source** (read-only, no management), then create a snapshot from its ID using `aws_ebs_snapshot`. Terraform waits for the snapshot to reach `completed` state before finishing — so after `apply` it's immediately usable.

---

## Syntax reference — `aws_ebs_snapshot`

```hcl
resource "aws_ebs_snapshot" "<local_name>" {
  volume_id   = "<vol-id>"            # REQUIRED — source volume ID
  description = "<text>"              # optional but graded here
  
  tags = {
    Name = "<display-name>"           # snapshot name in console
  }
}

# companion data source to look up existing volume by name tag
data "aws_ebs_volume" "<local_name>" {
  filter {
    name   = "tag:Name"               # filter by Name tag
    values = ["<volume-name>"]
  }
  filter {
    name   = "status"
    values = ["available"]            # only look at available volumes
  }
}
```

**Minimum required:**
```hcl
resource "aws_ebs_snapshot" "example" {
  volume_id   = data.aws_ebs_volume.source.id
  description = "My snapshot"
  tags = {
    Name = "my-snapshot"
  }
}
```

## Watch-outs

- **`description` must match exactly** — `Devops Snapshot` (capital D, capital S). Copy verbatim; description is immutable after creation.
- **Data source vs resource** — `data "aws_ebs_volume"` reads the existing volume without managing it. Using `resource "aws_ebs_volume"` instead would try to create a new volume.
- **Snapshot name is a tag** — `aws_ebs_snapshot` has no native `name` field; use `tags = { Name = ... }` like VPCs and EBS volumes.
- **Terraform waits for `completed`** — unlike some resources that return immediately, `aws_ebs_snapshot` polls until the snapshot finishes. No manual wait or `time_sleep` needed.
- **If volume is already in state** (from a previous task), reference it directly as `aws_ebs_volume.<name>.id` instead of using a data source — no need for both.
- **One file only** — append to `main.tf`; leave `provider.tf` untouched.
