# Terraform — IAM Policy (`iampolicy_jim`) — EC2 Read-Only

## Concept / purpose

**IAM Policy** is a JSON document that defines permissions — what actions are allowed or denied on which AWS resources. Policies are attached to users, groups, or roles to grant permissions.

**Policy types:**
- **Managed policies** (`aws_iam_policy`) — standalone reusable policies with their own ARN; can be attached to multiple identities
- **Inline policies** — embedded directly in a user/group/role; not reusable
- **AWS managed policies** — pre-built by AWS (e.g. `AmazonEC2ReadOnlyAccess`) — you reference, not create them

**Policy document structure:**
```
Version → Statement[] → Effect + Action + Resource
```
- `Effect: Allow` — permit the actions
- `Action` — what API calls are permitted. `ec2:Describe*` covers all read/view actions in the EC2 console — `DescribeInstances`, `DescribeImages` (AMIs), `DescribeSnapshots`, etc.
- `Resource: "*"` — Describe actions don't support resource-level restrictions; `*` is required

**`jsonencode({})`** vs **heredoc** — `jsonencode` is preferred: Terraform validates the structure at plan time, handles escaping automatically, and is more readable than a raw JSON string.

## Syntax reference

```hcl
resource "aws_iam_policy" "<local_name>" {
  name        = "<policy-name>"        # REQUIRED — unique policy name
  path        = "/"                    # optional — default "/"
  description = "<text>"              # optional but recommended

  policy = jsonencode({               # REQUIRED — JSON policy document
    Version = "2012-10-17"            # always this fixed date string
    Statement = [
      {
        Sid      = "<optional-id>"
        Effect   = "Allow"            # Allow | Deny
        Action   = [                  # list of API actions or wildcards
          "service:Action",
          "service:Action*"
        ]
        Resource = "*"                # ARN or * for all
      }
    ]
  })

  tags = { Name = "<policy-name>" }
}

# optional — attach to user
resource "aws_iam_user_policy_attachment" "<local_name>" {
  user       = aws_iam_user.<name>.name
  policy_arn = aws_iam_policy.<local_name>.arn
}

# optional — attach to group
resource "aws_iam_group_policy_attachment" "<local_name>" {
  group      = aws_iam_group.<name>.name
  policy_arn = aws_iam_policy.<local_name>.arn
}

# optional — attach to role
resource "aws_iam_role_policy_attachment" "<local_name>" {
  role       = aws_iam_role.<name>.name
  policy_arn = aws_iam_policy.<local_name>.arn
}
```

## Watch-outs

- **`ec2:Describe*` covers all three requirements** — `DescribeInstances` (view instances), `DescribeImages` (AMIs), `DescribeSnapshots` (snapshots). One wildcard satisfies all three view requirements plus every other read action in the EC2 console.
- **`Version = "2012-10-17"` is a fixed string** — not today's date. It's the IAM policy language version and never changes.
- **`Resource = "*"` is required for Describe actions** — EC2 Describe actions don't support resource-level restrictions (you can't limit `DescribeInstances` to specific instance ARNs). `*` is the only valid value here.
- **`jsonencode` validates at plan time** — if the policy document is malformed, `terraform plan` catches it before apply. Use `jsonencode` over heredoc for this safety net.
- **Policy name vs description** — `name` is the IAM policy name (graded); `description` is optional but good practice for documentation.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
