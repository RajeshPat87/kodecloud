# Terraform Environments — Simple Examples

## Concept / purpose

**Terraform environments** = managing multiple versions of the same infrastructure (dev, staging, prod) without duplicating code. The same `main.tf` logic runs with different variable values per environment.

**Three common patterns — simplest to most structured:**

```
Pattern 1: terraform.tfvars files      → simplest, one dir, multiple var files
Pattern 2: workspaces                  → built-in Terraform feature
Pattern 3: separate directories        → most isolated, recommended for prod
```

---

## Pattern 1 — `.tfvars` files (simplest)

One directory, one `main.tf`, separate variable files per environment.

**File structure:**
```
/home/bob/terraform/
├── provider.tf
├── variables.tf
├── main.tf
├── dev.tfvars        ← dev values
├── staging.tfvars    ← staging values
└── prod.tfvars       ← prod values
```

**variables.tf:**
```hcl
variable "env_name" {
  type    = string
  default = "dev"
}

variable "instance_type" {
  type    = string
  default = "t2.nano"
}

variable "vpc_cidr" {
  type    = string
  default = "10.0.0.0/16"
}
```

**main.tf:**
```hcl
resource "aws_vpc" "env_vpc" {
  cidr_block = var.vpc_cidr
  tags = { Name = "${var.env_name}-vpc" }
}

resource "aws_instance" "env_ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = var.instance_type
  tags = { Name = "${var.env_name}-ec2" }
}
```

**dev.tfvars:**
```hcl
env_name      = "dev"
instance_type = "t2.nano"
vpc_cidr      = "10.0.0.0/16"
```

**staging.tfvars:**
```hcl
env_name      = "staging"
instance_type = "t2.micro"
vpc_cidr      = "10.1.0.0/16"
```

**prod.tfvars:**
```hcl
env_name      = "prod"
instance_type = "t2.small"
vpc_cidr      = "10.2.0.0/16"
```

**Apply per environment:**
```bash
# deploy dev
terraform apply -var-file="dev.tfvars" -auto-approve

# deploy staging
terraform apply -var-file="staging.tfvars" -auto-approve

# deploy prod
terraform apply -var-file="prod.tfvars" -auto-approve
```

**Problem:** single state file — all environments share one `terraform.tfstate`. Not suitable for truly isolated environments.

## Pattern 2 — Workspaces (built-in Terraform)

One directory, one `main.tf`, **separate state per workspace**. Each workspace has its own `terraform.tfstate`.

**Workspace commands:**
```bash
# list workspaces
terraform workspace list
# * default

# create new workspaces
terraform workspace new dev
terraform workspace new staging
terraform workspace new prod

# switch between workspaces
terraform workspace select dev
terraform workspace select prod

# show current workspace
terraform workspace show
```

**main.tf — use `terraform.workspace` to differ per environment:**
```hcl
locals {
  env = terraform.workspace          # "dev", "staging", "prod"

  instance_types = {
    dev     = "t2.nano"
    staging = "t2.micro"
    prod    = "t2.small"
  }

  vpc_cidrs = {
    dev     = "10.0.0.0/16"
    staging = "10.1.0.0/16"
    prod    = "10.2.0.0/16"
  }
}

resource "aws_vpc" "env_vpc" {
  cidr_block = local.vpc_cidrs[local.env]
  tags = { Name = "${local.env}-vpc" }
}

resource "aws_instance" "env_ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = local.instance_types[local.env]
  tags          = { Name = "${local.env}-ec2" }
}
```

**Apply per workspace:**
```bash
# deploy dev
terraform workspace select dev
terraform apply -auto-approve

# deploy staging
terraform workspace select staging
terraform apply -auto-approve

# deploy prod
terraform workspace select prod
terraform apply -auto-approve
```

**State is isolated per workspace:**
```
terraform.tfstate.d/
├── dev/terraform.tfstate
├── staging/terraform.tfstate
└── prod/terraform.tfstate
```

**See resources per workspace:**
```bash
terraform workspace select dev
terraform state list
# aws_vpc.env_vpc
# aws_instance.env_ec2   (t2.nano, 10.0.0.0/16)

terraform workspace select prod
terraform state list
# aws_vpc.env_vpc
# aws_instance.env_ec2   (t2.small, 10.2.0.0/16)
```

## Pattern 3 — Separate directories (most isolated)

Each environment is a completely independent directory with its own state, variables, and optionally its own provider config.

**File structure:**
```
/home/bob/terraform/
├── modules/
│   └── vpc/
│       ├── main.tf       ← reusable module
│       ├── variables.tf
│       └── outputs.tf
├── dev/
│   ├── main.tf           ← calls the module
│   ├── variables.tf
│   └── terraform.tfvars
├── staging/
│   ├── main.tf
│   ├── variables.tf
│   └── terraform.tfvars
└── prod/
    ├── main.tf
    ├── variables.tf
    └── terraform.tfvars
```

**modules/vpc/variables.tf:**
```hcl
variable "env_name"      { type = string }
variable "vpc_cidr"      { type = string }
variable "instance_type" { type = string }
```

**modules/vpc/main.tf:**
```hcl
resource "aws_vpc" "vpc" {
  cidr_block = var.vpc_cidr
  tags = { Name = "${var.env_name}-vpc" }
}

resource "aws_instance" "ec2" {
  ami           = "ami-0c101f26f147fa7fd"
  instance_type = var.instance_type
  tags          = { Name = "${var.env_name}-ec2" }
}
```

**modules/vpc/outputs.tf:**
```hcl
output "vpc_id" {
  value = aws_vpc.vpc.id
}

output "instance_id" {
  value = aws_instance.ec2.id
}
```

**dev/main.tf:**
```hcl
module "vpc" {
  source        = "../modules/vpc"
  env_name      = "dev"
  vpc_cidr      = "10.0.0.0/16"
  instance_type = "t2.nano"
}
```

**prod/main.tf:**
```hcl
module "vpc" {
  source        = "../modules/vpc"
  env_name      = "prod"
  vpc_cidr      = "10.2.0.0/16"
  instance_type = "t2.small"
}
```

**Apply per environment:**
```bash
# deploy dev
cd /home/bob/terraform/dev
terraform init
terraform apply -auto-approve

# deploy prod
cd /home/bob/terraform/prod
terraform init
terraform apply -auto-approve
```

**State is fully isolated:**
```
dev/terraform.tfstate    ← only dev resources
prod/terraform.tfstate   ← only prod resources
```

---

## Pattern comparison

| | `.tfvars` files | Workspaces | Separate dirs |
|---|---|---|---|
| State isolation | ✗ shared | ✓ per workspace | ✓ per dir |
| Code duplication | None | None | Low (modules) |
| Setup complexity | Simple | Simple | More setup |
| Best for | Learning/labs | Dev/staging | Production |
| Risk of cross-env blast | High | Low | Zero |
| Recommended for prod | ✗ | ✗ | ✓ |

## Quick start for this lab (Pattern 1 — simplest)

```bash
cd /home/bob/terraform

# create var files
cat > dev.tfvars << 'EOF'
env_name      = "dev"
instance_type = "t2.nano"
vpc_cidr      = "10.0.0.0/16"
EOF

cat > prod.tfvars << 'EOF'
env_name      = "prod"
instance_type = "t2.small"
vpc_cidr      = "10.2.0.0/16"
EOF

# deploy dev
terraform apply -var-file="dev.tfvars" -auto-approve
terraform state list

# destroy dev
terraform destroy -var-file="dev.tfvars" -auto-approve

# deploy prod
terraform apply -var-file="prod.tfvars" -auto-approve
terraform state list
```

## Key takeaway

```
Learning/labs    → Pattern 1 (.tfvars)    simple, fast
Team projects    → Pattern 2 (workspaces) isolated state, same codebase
Production       → Pattern 3 (dirs)       fully isolated, zero blast radius
```

The pattern you need for KodeKloud tasks is Pattern 1 — `.tfvars` with `variables.tf` — which is exactly what the `KKE_vpc`, `KKE_sg`, `KKE_eip`, `KKE_user` tasks have been practising.
