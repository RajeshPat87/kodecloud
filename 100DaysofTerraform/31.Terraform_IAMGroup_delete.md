## Pre-check

```bash
cd /home/bob/terraform
cat main.tf                            # confirm iamgroup_kirsty resource exists
terraform state list                   # confirm aws_iam_group.* is in state
```

Identify the exact resource name in state:
```bash
terraform state list | grep iam_group
```

---

## Command

```bash
terraform destroy -target=aws_iam_group.<resource_name> -auto-approve
```

Replace `<resource_name>` with whatever `terraform state list` showed. Most likely:

```bash
terraform destroy -target=aws_iam_group.iamgroup_kirsty -auto-approve
```

---

## Post-checks

```bash
# confirm removed from state
terraform state list | grep iam_group
# expect: no output

# confirm main.tf still has the code
cat main.tf                            # aws_iam_group block must still be there

# confirm gone from AWS
aws --endpoint-url=http://aws:4566 iam get-group \
  --group-name iamgroup_kirsty 2>&1
# expect: error — NoSuchEntityException (group does not exist)

# no changes check (state is empty, main.tf has code — plan will show 1 to add)
terraform plan
# expect: Plan: 1 to add (ready to re-provision when needed)
```

## Pattern summary — temporary deletion keeping code

```bash
# delete one specific resource, keep everything else
terraform destroy -target=<resource_type>.<resource_name> -auto-approve

# verify gone from state
terraform state list

# verify code still in main.tf
cat main.tf

# re-provision when needed
terraform apply -auto-approve
```

This is the standard Terraform pattern for temporary resource deletion. The code in `main.tf` is the source of truth — state is just the record of what currently exists. Removing from state (via targeted destroy) without touching `main.tf` = clean temporary deletion with full re-provision capability.
