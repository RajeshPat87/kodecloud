## main.tf content

```hcl
resource "aws_iam_role" "iamrole_ravi" {
  name = var.KKE_iamrole

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect    = "Allow"
        Principal = { Service = "ec2.amazonaws.com" }
        Action    = "sts:AssumeRole"
      }
    ]
  })

  tags = {
    Name = var.KKE_iamrole
  }
}
```

**Why `assume_role_policy` is required** — unlike IAM users or groups, an IAM role **must** have a trust policy (`assume_role_policy`) that defines who can assume it. Without it, `terraform plan` errors: `assume_role_policy is required`. The trust policy here allows EC2 instances to assume the role (`ec2.amazonaws.com`) — the most common pattern. Change the `Principal.Service` to `lambda.amazonaws.com`, `ecs-tasks.amazonaws.com`, etc. depending on the use case.

## IAM role syntax reference (complete)

```hcl
resource "aws_iam_role" "<local_name>" {
  name        = "<role-name>"           # REQUIRED — role name
  description = "<text>"               # optional
  path        = "/"                    # optional — hierarchy path

  # REQUIRED — trust policy (who can assume this role)
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = {
        Service = "ec2.amazonaws.com"   # EC2 can assume
        # Service = "lambda.amazonaws.com"
        # Service = "ecs-tasks.amazonaws.com"
        # AWS = "arn:aws:iam::ACCOUNT:root"  # another account
      }
      Action    = "sts:AssumeRole"
    }]
  })

  # optional — session duration (seconds)
  max_session_duration = 3600          # 1 hour default, max 43200 (12h)

  # optional — permissions boundary
  permissions_boundary = "<policy-arn>"

  tags = { Name = "<role-name>" }
}

# optional — attach managed policy to role
resource "aws_iam_role_policy_attachment" "<name>" {
  role       = aws_iam_role.<local_name>.name
  policy_arn = "arn:aws:iam::aws:policy/ReadOnlyAccess"
}

# optional — inline policy on role
resource "aws_iam_role_policy" "<name>" {
  name   = "<policy-name>"
  role   = aws_iam_role.<local_name>.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:GetObject"]
      Resource = "*"
    }]
  })
}

# optional — instance profile (attach role to EC2)
resource "aws_iam_instance_profile" "<name>" {
  name = "<profile-name>"
  role = aws_iam_role.<local_name>.name
}
```

## Trust policy — common principals

```hcl
# EC2 instances
Principal = { Service = "ec2.amazonaws.com" }

# Lambda functions
Principal = { Service = "lambda.amazonaws.com" }

# ECS tasks
Principal = { Service = "ecs-tasks.amazonaws.com" }

# Another AWS account (cross-account)
Principal = { AWS = "arn:aws:iam::ACCOUNT_ID:root" }

# Specific IAM user
Principal = { AWS = "arn:aws:iam::ACCOUNT_ID:user/username" }

# Any AWS service (broad — use carefully)
Principal = { Service = "*" }
```

## Watch-outs

- **`assume_role_policy` is mandatory** — IAM roles cannot exist without a trust policy. This differentiates roles from users and groups (which don't need one).
- **Role name must match exactly** — `iamrole_ravi` (underscore, all lowercase). IAM role names are case-sensitive.
- **`name` is a real field** — unlike VPCs (tag only) and EIPs (tag only), IAM roles have a real `name` field used as the primary identifier.
- **If `variables.tf` already exists** from a previous task, append — don't overwrite:
  ```hcl
  # append to existing variables.tf
  variable "KKE_iamrole" {
    type        = string
    default     = "iamrole_ravi"
    description = "Name of the IAM role to be created"
  }
  ```
- **Two files required** — `variables.tf` for the variable declaration, `main.tf` for the resource.
- **`provider.tf` stays untouched.**
