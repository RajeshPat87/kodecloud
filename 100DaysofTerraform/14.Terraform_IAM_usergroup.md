# Terraform — IAM Group (`iamgroup_javed`)

## Concept / purpose

**IAM Group** is a collection of IAM users. Instead of attaching policies to individual users (which becomes unmanageable at scale), you attach policies to a group and add users to it — all users inherit the group's permissions automatically.

Key points:
- Groups are **not identities** — you cannot log in as a group or assume a group
- Groups **cannot be nested** — a group cannot contain another group
- A user can belong to **multiple groups** (up to 10 by default)
- Groups are **global** like all IAM resources — no region restriction
- Groups alone do nothing — you attach policies to give them permissions

**Typical IAM hierarchy:**
```
IAM Policy → attached to → IAM Group → contains → IAM Users
```

This task is just the group creation step — the foundation before adding users or policies.

## Syntax reference

```hcl
resource "aws_iam_group" "<local_name>" {
  name = "<group-name>"               # REQUIRED — group name
  path = "/"                          # optional — hierarchy path, default "/"
}

# optional — add users to group
resource "aws_iam_group_membership" "<local_name>" {
  name  = "<membership-name>"
  group = aws_iam_group.<local_name>.name
  users = [
    aws_iam_user.<user1>.name,
    aws_iam_user.<user2>.name,
  ]
}

# optional — attach managed policy to group
resource "aws_iam_group_policy_attachment" "<local_name>" {
  group      = aws_iam_group.<local_name>.name
  policy_arn = "<policy-arn>"
}

# optional — attach inline policy to group
resource "aws_iam_group_policy" "<local_name>" {
  name  = "<policy-name>"
  group = aws_iam_group.<local_name>.name
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["s3:*"]
      Resource = "*"
    }]
  })
}
```

## Watch-outs

- **`aws_iam_group` has no `tags` argument** — unlike users, EC2, and most other AWS resources, IAM groups do not support tagging. Don't add a `tags` block; it will error.
- **Group name must match exactly** — `iamgroup_javed` (underscore). IAM group names are case-sensitive.
- **Group alone has no effect** — no permissions until policies are attached and users are added. This task only creates the group itself.
- **`path` defaults to `"/"`** — no need to specify unless you're using IAM path hierarchies (e.g. `/engineering/devops/`).
- **IAM is global** — group is available across all regions; provider routes the API call through `us-east-1` as configured.
- **One file only** — all in `main.tf`; leave `provider.tf` untouched.
